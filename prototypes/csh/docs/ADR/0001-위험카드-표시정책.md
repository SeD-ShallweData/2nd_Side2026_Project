# ADR-0001 · 위험카드에 점수를 표시하지 않는다

- 상태: **채택**
- 날짜: 2026-08-01
- 결정자: csh
- 관련: [30-디자인-반영.md](../30-디자인-반영.md), [20-가드레일.md](../20-가드레일.md)

## 맥락

Figma 시안(`4:2` 노드 `13:304`)의 위험카드는 실명 기업과 위험 점수를 함께 표시합니다.

```
삼성전자 반도체 기흥사업장   [위험 낮음]   체불 위험 5 · 산재 위험 12 · 고용 안정성 88
현대건설 인천 2공구         [위험 높음]   체불 위험 68 · 산재 위험 71 · 고용 안정성 42
```

그런데 `knowledge/_source`의 두 학습자료는 이를 제1원칙으로 금지합니다.

- 임금체불 예시집: "예측값은 실명과 함께 노출하지 않는다", "`risk_probability` 필드는 구직자용 응답 스키마에 아예 존재하지 않는다 — 값이 null인 게 아니라 필드 자체가 없다"
- 산재 예시집: "시도×업종 위험도를 개별 사업장에 부여하지 않는다. 역방향 매핑은 생태학적 오류다"

두 문서를 무시하면 다음 두 문제가 생깁니다.

1. **명예훼손 리스크** — 아직 체불하지 않은 사업장을 공개적으로 "위험"이라 표시하면 사실이라도 형법 제307조 소지
2. **통계적 오류** — 산재 모델의 예측 단위는 시도×업종×주차. 개별 사업장에 점수를 부여하는 것은 생태학적 오류

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 가드레일 우선 — 점수를 관측 사실 + 확인 체크리스트로 대체 | 정책 준수. 시안의 시각 언어는 유지. "법적 리스크를 설계로 해결" 서사 확보 | 시안의 막대그래프 임팩트 상실 |
| B. 2-트랙 토글 — 감독관 뷰(점수 노출) / 구직자 뷰(체크리스트) | 학습자료의 원래 설계와 정확히 일치. 발표 임팩트 최대 | 화면·프롬프트·가드레일을 두 벌 만들어야 함 (작업량 약 2배) |
| C. 시안 그대로 + 가상 데이터 배너 | 시안 재현도 최대 | 정책 문서가 정면으로 금지한 형태. 심사에서 지적 여지 |

## 결정

**A. 가드레일 우선.**

- 사업장명은 전부 가명(`샘플A건설` 등), 모든 레코드에 `is_dummy=true`
- 체불 점수 → **관측 사실**(명단 등재 여부, 가입자 추이, 결측) + **확인 체크리스트**(예측 신호를 질문으로 변환)
- 산재 점수 → 카드 안이 아니라 **별도 "지역·업종 맥락" 레이어**로 분리하고 면책 문구 고정
- API 응답 스키마에 `risk_probability` 필드를 만들지 않음
- 세 레이어를 배경색·라벨 막대 색으로 시각적으로 분리

시안의 카드 형태·색·타이포·배치는 그대로 유지합니다. 바뀐 것은 **무엇을 담느냐**뿐입니다.

## 결과

- `app/demo.py`가 3레이어 스키마로 더미 데이터를 제공. `risk_probability` 필드 부재를 API 응답에서 검증
- `app/guardrails.py`에 `risk_score`, `risk_grade`, `named_risk`, `risk_verdict` 규칙 추가 — 챗봇이 점수를 말해도 차단
- 랜딩 카피를 "위험을 숫자로" → "위험을 점수 대신 확인할 것으로" 변경

## 되돌리려면

B(2-트랙)로 확장하는 것은 언제든 가능합니다. 지금 구조가 구직자 트랙이므로,
감독관 트랙을 별도 라우트(`/inspector`)와 별도 페르소나로 추가하면 됩니다.
그때는 **내부 전용 배너**와 접근 제어가 함께 필요합니다.

C로 되돌리는 것은 권하지 않습니다. 되돌린다면 이 문서의 두 리스크를 팀이 명시적으로 수용해야 합니다.
