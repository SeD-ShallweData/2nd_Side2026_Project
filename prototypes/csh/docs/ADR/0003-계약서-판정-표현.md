# ADR-0003 · 계약서 판정은 코드가 내리고, 3단계로만 말한다

- 상태: **채택**
- 날짜: 2026-08-08
- 결정자: csh
- 관련: [80-근로계약서-진단.md](../80-근로계약서-진단.md), [ADR-0001](0001-위험카드-표시정책.md), [20-가드레일.md](../20-가드레일.md)

## 맥락

근로계약서를 올리면 부당한 계약서인지 알려주는 기능을 붙입니다.
사업장 위험도와 달리 **사용자가 자기 문서를 올린 것**이고, 조항이 법정 기준에 맞는지는
상당 부분 객관적으로 계산됩니다. 그래서 ADR-0001의 "점수·등급 금지"를 그대로 적용할지,
계약서에는 다르게 갈지 먼저 정해야 했습니다.

두 갈래가 얽혀 있습니다.

1. **누가 판정하는가** — LLM인가, 코드인가
2. **어느 수위로 말하는가** — "위법입니다"인가, 3단계인가

### 왜 하나로 묶어 결정했는가

두 질문의 답이 서로를 강제하기 때문입니다.
LLM이 판정하면 근거가 매번 달라져 "위법입니다"라고 단정할 자격이 없고,
코드가 판정하면 근거가 고정되어 조문을 걸고 설명할 수 있습니다.

## 갈래 ① 누가 판정하는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 순수 LLM — 법 기준을 knowledge로 주입하고 한 번에 판단 | 구현이 빠름. 조항 유형에 제한 없음 | **금액 계산이 틀려도 알 수 없음.** 같은 계약서에 매번 다른 판정. 가드레일이 대조할 근거가 없음 |
| B. LLM 추출 → **코드 규칙 엔진** 판정 → LLM 해설 | 판정이 결정적. 계산이 검증됨. 가드레일이 대조할 사실을 가짐 | 규칙에 없는 조항 유형은 `other`로만 잡힘. 규칙을 손으로 늘려야 함 |

### 결정: **B**

프로토타입 단계에서 A를 프롬프트로 시도했을 때 두 모델 모두 같은 실패를 냈습니다.

> 월급 2,400,000원 (고정연장수당 400,000원 포함), 주 40시간
> 🤖 "월급 240만원은 2026년 최저임금 월 환산액 215만원을 넘으므로 최저임금 이상입니다."

두 군데가 틀렸습니다.

1. 가산수당 40만원은 최저임금에 **산입되지 않습니다** → 산입임금은 200만원
2. 월 환산액과 직접 비교하면 주 40시간이 아닌 계약에서 전부 틀립니다 → 시급으로 환산해야 합니다

바르게 계산하면 `2,000,000 ÷ 208.6 = 9,588원 < 10,320원`으로 **미달**입니다.
포괄임금이 최저임금 미달을 가리는 가장 흔한 형태인데, 모델은 정반대로 답했습니다.

나눗셈을 모델에 맡기지 않습니다. `app/demo.py`에서 지역·업종 필터를 프롬프트가 아니라
코드로 건 것과 같은 판단입니다.

> 재식별 방지 3종 세트는 프롬프트가 아니라 DB 쿼리 계층에 코드로 구현합니다. — [50-더미데이터.md](../50-더미데이터.md) 4절

## 갈래 ② 어느 수위로 말하는가

| 선택지 | 예시 | 문제 |
|---|---|---|
| A. 위법 단정 | "근로기준법 제20조 위반입니다. 500만원 이하 벌금 대상입니다" | 오탐 시 잘못된 법적 확신을 줌. `guardrails.py`의 `legal_verdict` 규칙을 예외 처리해야 함 |
| B. **3단계 + 조문 인용** | "근로기준법 제20조는 위약금을 미리 정하는 계약을 금지합니다. 이 계약서 제8조가 여기에 해당합니다" | 단정보다 한 박자 약함 |
| C. 점수·등급 요약 | "이 계약서 위험도 D등급 (37점)" | ADR-0001이 금지한 형태. `risk_grade`·`risk_score` 규칙에 정면으로 걸림 |

### 결정: **B**

- C는 형태가 ADR-0001이 금지한 것과 같습니다. 대상이 사업장에서 문서로 바뀌었을 뿐
  "복잡한 판단을 한 숫자로 뭉개는" 문제는 동일합니다. `guard.py`의 `contract_score` 규칙이 막습니다.
- A는 오탐 비용이 비대칭입니다. 미탐(놓침)은 사용자가 다른 경로로 확인하면 되지만,
  오탐(멀쩡한 조항을 위법이라 함)은 사용자가 회사와 다투게 만듭니다.
- B는 기존 `20-가드레일.md` 6번("법적 판단을 단정하지 않는다")과 충돌하지 않습니다.
  계약서 기능만 예외를 파지 않아도 됩니다.

레벨은 4단계입니다 — 🔴 법정 기준 미달 / 🟡 확인 필요 / 🟢 기준 충족 / ⚪ 적용 제외.
🟢을 넣은 이유는 문제만 나열하면 사용자가 계약서 전체를 불신하기 때문입니다.
⚪는 상시 5인 미만 사업장에서 해당 조문이 적용되지 않는 경우입니다.

## 결과

- `app/contract/rules.py` — 규칙 12개. LLM을 부르지 않고 같은 입력이면 항상 같은 판정
- `app/contract/standards.py` — 최저임금·조문 21개의 **단일 출처.** 규칙이 표에 없는 조문을 요구하면 `KeyError`로 즉시 터집니다
- `app/contract/guard.py` — 계약서 전용 가드레일. `legal_certainty`(위법 단정), `contract_score`(점수화), `fabricated_article`(조문 창작), `decision_directive`(서명 여부 지시)
  - 기존 `guardrails.py`를 그대로 쓰지 않는 이유 — `legal_verdict`가 조문을 인용한 **정상 해설**을 차단하고, `fabricated_workplace`가 계약서에 적힌 회사명을 전부 오탐합니다
- 해설이 가드레일에 걸려도 **조항별 판정은 화면에 그대로 남습니다.** 판정은 규칙 엔진이 낸 것이고 가드레일은 해설 문장만 봅니다
- `tests/test_contract_rules.py` 47건 · `tests/test_contract_guard.py` 27건 — 오탐 케이스를 함께 넣었습니다

## 되돌리려면

갈래 ①을 A(순수 LLM)로 되돌리는 것은 권하지 않습니다.
되돌린다면 최저임금 환산이 틀릴 수 있다는 점을 화면에 명시해야 합니다.

갈래 ②를 A(위법 단정)로 올리는 것은 **규칙별로** 가능합니다.
조문이 명확하고 계산이 결정적인 것(위약 예정, 퇴직금 포기)만 골라
`Finding`에 `certainty` 필드를 추가하고 해설 프롬프트의 표현 표를 바꾸면 됩니다.
그때도 C(점수·등급)로는 가지 않습니다 — ADR-0001과 정면으로 어긋납니다.
