## 1. 왜 TSX를 그대로 쓰지 않았나

추출물은 React + Tailwind 골격입니다. 그런데 이 서버에는 **node/npm이 설치되어 있지 않습니다.**

```
$ which node npm
(없음)
```

빌드 도구 없이 돌아가야 하고, 팀이 revert 전에 쓰던 스택도 Flask + 정적 파일이었습니다.
그래서 TSX를 **디자인 명세로만 읽고** 순수 HTML/CSS/JS로 다시 구현했습니다.

추출물에서 실제로 가져온 것:

| 가져온 것 | 어디로 |
|---|---|
| 색 토큰 13개 | [web/css/tokens.css](../web/css/tokens.css) |
| 폰트 (Noto Sans KR 400/700/900) | [scripts/fetch_fonts.sh](../scripts/fetch_fonts.sh)로 로컬 서빙 |
| 레이아웃 수치 (max-width 1152, nav 64, 섹션 96 등) | tokens.css + 각 CSS |
| 문구·구조 | HTML 그대로 |
| SVG 21개 | `web/assets/figma/` (참고용 보관) |

추출물의 절대 위치(`absolute`, 고정 폭 1152px)는 쓰지 않았습니다. flex/grid로 다시 짰습니다.

## 3. ⚠️ 시안과 다르게 만든 것 — 위험카드

### 무엇이 문제였나

시안의 위험카드는 이렇습니다.

```
삼성전자 반도체 기흥사업장            [위험 낮음]
경기 용인 · 반도체 제조
  체불 위험  ▬                    5
  산재 위험  ▬▬▬                 12
  고용 안정성 ▬▬▬▬▬▬▬▬▬▬▬▬     88
  데이터 신뢰도 94%          상세 보기 >

현대건설 인천 2공구                  [위험 높음]
  체불 위험  ▬▬▬▬▬▬▬▬▬▬▬▬     68
  산재 위험  ▬▬▬▬▬▬▬▬▬▬▬▬▬    71
```

**실명 대기업 + 위험 점수 + 위험 등급**입니다. 이건 `knowledge/`의 두 학습자료가
제1원칙으로 금지한 바로 그 형태입니다.

> 🔑 예측값은 실명과 함께 노출하지 않는다. (임금체불 예시집)
> 🔑 시도×업종 위험도를 개별 사업장에 부여하지 않는다 — 생태학적 오류. (산재 예시집)
> 🔒 `risk_probability` 필드는 구직자용 응답 스키마에 아예 존재하지 않는다.

두 가지를 동시에 위반합니다.

1. **명예훼손 리스크** — 아직 체불하지 않은 사업장을 공개적으로 "위험"이라 표시하면
   사실이라도 형법 제307조(사실적시 명예훼손) 소지가 있습니다.
2. **생태학적 오류** — 산재 모델의 예측 단위는 시도×업종×주차입니다.
   개별 사업장에 "산재 위험 71"을 붙이는 것은 통계적으로 틀린 추론입니다.

### 어떻게 했나

사용자 결정: **가드레일 우선** (2026-08-01). [ADR/0001-위험카드-표시정책.md](ADR/0001-위험카드-표시정책.md)

시안의 **카드 형태·색·타이포·배치는 그대로 살리고 내용만 바꿨습니다.**

| 시안 | 구현 |
|---|---|
| 실명 대기업 (삼성전자, 현대건설) | 가명 (샘플A건설, 데모B제조 …) + 전 레코드 `is_dummy=true` |
| 체불 위험 68 (막대 + 숫자) | 관측 사실 — 명단 등재 여부, 가입자 51→38명, 결측 1개월 |
| — | **확인 체크리스트** — "4대보험 가입 여부를 확인하세요" 등 2~4건 |
| 산재 위험 71 (카드 안) | **별도 레이어**로 분리 — "인천광역시 건설업 주의 · 개별 사업장의 사고 위험이 아닙니다" |
| 위험 낮음 / 높음 배지 | 명단 등재 이력 / 미등재 배지 |
| 데이터 신뢰도 94% | 그대로 유지 (매칭 신뢰도) |

세 레이어를 **배경색·라벨 막대 색으로 확실히 분리**했습니다.
학습자료가 "세 레이어를 시각적으로 확실히 분리하는 것이 이 서비스의 핵심 차별점"이라고 적은 부분입니다.

```
┌ 관측 사실 · 공개 데이터 ────────┐  흰 배경, 검정 라벨 막대
├ 확인 체크리스트 · 예측을 질문으로 ┤  옅은 노랑 배경, 브랜드 라벨 막대
├ 지역·업종 맥락 · 집계 ─────────┤  회색 배경, 보라 라벨 막대
└ 면책 문구 + 기준 시점 ─────────┘
```

왼쪽 카피도 바꿨습니다.

- 시안: "사업장 위험을 **숫자로** 보세요"
- 구현: "위험을 점수 대신 **확인할 것으로**"

발표에서는 이게 오히려 강점입니다. *"법적 리스크를 설계로 해결했다"* 는 서사가 화면에 그대로 보입니다.

## 5. 폰트

시안은 Noto Sans KR Regular/Bold/Black을 씁니다.
발표장에서 외부망이 막히면 폰트가 깨지므로 **woff2 서브셋 124개(3.7MB)를 로컬에 두고 직접 서빙**합니다.

```bash
./scripts/fetch_fonts.sh     # web/assets/fonts/notosanskr/ + web/css/fonts.css 생성
```

받은 파일은 git에 올리지 않습니다(.gitignore). 실행하지 않아도 사이트는 동작하며 시스템 한글 폰트로 대체됩니다.

## 6. 시안을 갱신할 때

1. Figma Dev Mode에서 다시 추출해 `design/source/figma-extract-<날짜>/`에 넣습니다 (기존 폴더를 덮어쓰지 않습니다)
2. `design-tokens.css`의 값이 바뀌었으면 [web/css/tokens.css](../web/css/tokens.css)만 갱신합니다
3. 레이아웃이 바뀌었으면 해당 섹션의 CSS를 고칩니다
4. **위험 표시 정책과 충돌하는 변경이 있으면 반영 전에 이 문서와 ADR을 먼저 확인합니다**
