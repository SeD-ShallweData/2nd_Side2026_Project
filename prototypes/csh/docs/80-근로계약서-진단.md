# 근로계약서 진단

작성 2026-08-08 · 구현 [app/contract/](../app/contract/) · 화면 [web/contract.html](../web/contract.html)

노동자가 자기 근로계약서를 올리면 조항을 법정 기준과 대조해 돌려주는 기능입니다.
AI 상담(`/chat`)과 **완전히 분리된 화면**(`/contract`)이고, 대화 이력을 공유하지 않습니다.

---

## 0. 먼저 바로잡은 전제

> "solar-pro가 PDF를 인식할 수 있으니 계약서를 그대로 넣으면 된다"

**아닙니다.** solar-pro3의 `/v1/chat/completions`는 `messages` 배열의 텍스트만 처리합니다.
PDF·이미지·파일 파트를 받지 않습니다.

Upstage에서 문서를 읽는 것은 **별도 엔드포인트**입니다.

| API | 엔드포인트 | 하는 일 |
|---|---|---|
| Document Parse | `POST /v1/document-digitization` | PDF·사진·HWP·DOCX → 마크다운/HTML + 요소 배열 |
| Information Extraction | `POST /v1/information-extraction` | JSON 스키마를 주고 필드 추출 |
| Chat Completions | `POST /v1/chat/completions` | **텍스트만** |

그래서 구조가 **2단**이 됩니다. Document Parse로 글자를 뽑고, 그 텍스트를 solar-pro3에 넘깁니다.

---

## 1. 파이프라인

```
 업로드 (PDF·사진·HWP, 최대 20MB)
   │
   ├─① Document Parse ────────────  parse.py    OCR 포함. 사진으로 찍은 계약서도 읽습니다
   │      → 마크다운 + 요소 배열              파일 해시로 캐시 (호출당 과금)
   │
   ├─② 조항 구조화 추출 (LLM) ──────  extract     solar-pro3 · temperature 0
   │      → 조항 JSON                        **사실만 뽑습니다. 판정하지 않습니다**
   │
   ├─③ 규칙 엔진 (코드) ───────────  rules.py    ★ 판정은 여기서만 납니다
   │      → 조항별 4단계 판정                  LLM 없음. 같은 입력 → 항상 같은 출력
   │
   ├─④ 해설 (LLM) ────────────────  explain     판정 결과를 사람 말로 옮깁니다
   │      → 설명 텍스트                       두 모델 비교 가능
   │
   └─⑤ 계약서 전용 가드레일 ────────  guard.py    위법 단정·점수화·조문 창작 차단
```

**③이 이 설계의 요점입니다.**

최저임금 미달 여부는 나눗셈입니다. 나눗셈을 모델에 맡기면 같은 계약서에서 다른 답이 나옵니다.
실제로 프롬프트만으로 시켰을 때 두 모델 모두 209시간 환산을 건너뛰고
월급을 최저임금 **월 환산액**과 직접 비교했습니다. 주 30시간 계약이면 이 비교는 틀립니다.

`app/demo.py`에서 지역·업종 필터를 프롬프트가 아니라 코드로 건 것과 같은 원칙입니다.

> 판정은 코드가, 읽기와 쓰기는 모델이.

## 2. 판정 4단계

점수·등급을 매기지 않습니다. [ADR-0001](ADR/0001-위험카드-표시정책.md)이 사업장에 대해
금지한 것과 같은 이유이고, 계약서에도 같은 원칙을 적용합니다 →
[ADR-0003](ADR/0003-계약서-판정-표현.md)

| | 레벨 | 뜻 | 예 |
|---|---|---|---|
| 🔴 | `violation` | 법정 기준 미달 — 조문이 명확하고 계약서 문면으로 확인됨 | 위약금 300만원 예정 (근기법 제20조) |
| 🟡 | `check` | 확인 필요 — 그 자체로는 위법이 아니거나 실태를 봐야 함 | 포괄임금, 경업금지 |
| 🟢 | `ok` | 기준 충족 | 환산 시급이 최저임금 이상 |
| ⚪ | `excluded` | 적용 제외 — 상시 5인 미만이라 해당 조문이 적용되지 않음 | 4명 사업장의 연차 조항 |

**"위법입니다"라고 단정하지 않습니다.** 조문이 무엇을 정하는지 말하고, 계약서의 어느 문구가
거기에 닿는지 보여줍니다. 최종 판단은 근로감독관·노무사·법원의 몫입니다.
기존 `guardrails.py`의 `legal_verdict` 규칙과 충돌하지 않는 것도 이 때문입니다.

## 3. 오탐을 막는 세 장치

이 기능에서 가장 무서운 것은 미탐이 아니라 **오탐**입니다.
멀쩡한 계약서를 "부당하다"고 말하면 서비스를 못 씁니다.

### ① `null`(모름)과 `false`(없다고 적힘)를 절대 섞지 않는다

| 계약서 상태 | 값 | 판정 |
|---|---|---|
| "연차휴가는 부여하지 않는다" | `false` | 🔴 제60조 위반 |
| 연차에 관한 말이 아예 없음 | `null` | 🟡 제17조 명시 누락 확인 필요 |
| 연차 조항이 있음 | `true` | 🟢 |

`schema.normalize()`가 이 구분을 강제하고, 프롬프트(`extract.md` ②항)가 모델에 같은 것을 지시합니다.
`tests/test_contract_rules.py`의 "항목을 모른다고 해서 누락은 아니다"가 이걸 고정합니다.

### ② 상시 근로자 5인 미만 처리

5인 미만 사업장에는 **연장·야간·휴일 가산수당(제56조), 연차(제60조), 근로시간 제한(제50조·제53조),
부당해고 구제(제23조), 공휴일 유급(제55조②)이 적용되지 않습니다.**

- 계약서에 인원이 **적혀 있고 5인 미만** → ⚪ 적용 제외로 낮춤
- 계약서에 인원이 **없음** → 🟡 확인 필요로 낮춤. **5인 이상이라고 가정하지 않습니다**
- 5인 이상 → 그대로 🔴

이 처리는 규칙마다 흩어놓지 않고 `rules._scale()` 한 곳에 모았습니다.

### ③ 모델이 붙인 조항 코드를 코드로 검증

**가장 크게 물린 지점입니다** (2026-08-08 실호출). 모델이 두 가지로 실패했습니다.

- 조항 코드 표를 **체크리스트로 훑어** 해당 없는 코드까지 나열하고,
  `quote`에 계약서 원문 대신 프롬프트의 표 설명문을 복사했습니다
- **원문에 있는 문장에 엉뚱한 코드**를 붙였습니다.
  "이 계약에 정함이 없는 사항은 근로기준법령에 따른다"에 `at_will_dismissal`·
  `marriage_retirement`·`no_annual_leave`를 동시에,
  "퇴직급여제도를 설정한다"(정상 조항)에 `severance_waived`를 붙였습니다

인용문이 진짜라 원문 대조만으로는 통과하고, 그대로 🔴 위반이 됩니다.
그래서 `schema.verify_quotes()`가 네 단계로 거릅니다.

| 단계 | 무엇을 |
|---|---|
| ① | `note`가 "해당 없음" 류면 버림 — 표를 훑고 있다는 신호 |
| ② | 인용문이 계약서 본문에 실제로 있는지 대조 (공백·기호 무시) |
| ③ | **인용 내용이 그 코드의 요건을 만족하는지** (`CLAUSE_SIGNATURES`) |
| ④ | `other`가 표준 조항 문구면 버림 |

③이 핵심입니다. `penalty_predetermined`는 인용문 안에 *배상·위약* + **금액**이,
`severance_waived`는 *퇴직금* + *안 준다는 말*이 함께 있어야 합니다.

프롬프트에도 같은 것을 지시하지만 **프롬프트는 지켜지지 않을 때가 있고 코드는 항상 지켜집니다.**
놓치는 것보다 멀쩡한 조항을 위반이라고 말하는 쪽이 훨씬 나쁩니다.

## 4. 무엇을 판정하는가

`app/contract/rules.py`에 규칙 12개, `standards.py`에 조문 21개가 있습니다.

| 규칙 | 무엇을 계산하는가 |
|---|---|
| `rule_min_wage` | 월급·연봉 → 산입임금 → 월 소정근로시간으로 나눠 **환산 시급** → 최저임금 대조 |
| `rule_probation` | 수습 기간(3개월)·감액률(90%)·계약기간(1년)·단순노무업무 4가지를 각각 |
| `rule_work_hours` | 1일 8시간 · 1주 40시간 · 연장 12시간 · 총 52시간 |
| `rule_break` | 4시간 30분 / 8시간 60분 |
| `rule_holiday` | 주휴일(5인 미만도 적용) · 연차 · 공휴일 |
| `rule_severance` | 퇴직금 미지급·분할약정 · 주 15시간 요건 |
| `rule_required_items` | 제17조 서면 명시 7항목 + 교부 |
| `rule_term` | 기간제 2년 초과 |
| `rule_inclusive_wage` | 포괄임금 — 고정연장수당의 **시간 수**가 적혀 있는가 |
| `rule_insurance` | 4대보험, 특히 산재보험 |
| `rule_headcount` | 상시 근로자 수 미기재 |
| `rule_clauses` | 모델이 원문 인용과 함께 뽑은 독소조항 14종 |

### 최저임금 계산이 왜 까다로운가

```
월급 2,400,000원 (고정연장수당 400,000원 포함), 주 40시간

산입 임금 = 2,400,000 − 400,000 = 2,000,000원
            └ 가산수당은 최저임금에 산입되지 않습니다
              (매월 지급되는 상여금·복리후생비는 2024년부터 전액 산입)

월 소정근로시간 = (40 + 8) × 4.345 = 208.6시간
                        └ 유급 주휴 8시간

환산 시급 = 2,000,000 ÷ 208.6 = 9,588원  <  10,320원  → 🔴 미달
```

월급만 보면 240만원이라 최저임금 월 환산액(215만원)을 넘습니다.
**포괄임금이 최저임금 미달을 가리는 전형적인 형태**이고, 모델이 가장 자주 놓치는 지점입니다.

## 5. 더미 근로계약서 3종

```bash
.venv/bin/python scripts/make_contract_samples.py            # → data/contracts/samples/
.venv/bin/python scripts/make_contract_samples.py --scan     # 스캔본(OCR 경로)까지
```

reportlab + Noto Sans KR로 표준근로계약서 서식을 본떠 만듭니다.
이름 규칙은 [50-더미데이터.md](50-더미데이터.md) 3절을 그대로 따릅니다.

| | 문서 | 상시 인원 | 실호출 판정 (2026-08-08) |
|---|---|---|---|
| ① | 정상 — 샘플A건설 | 42명 | 🔴 0건 · 🟢 9건 |
| ② | 부당 — 예시C물류 | 28명 | 🔴 16건 · 🟡 3건 · 🟢 1건 |
| ③ | 경계 — 데모B제조 | **4명** | 🔴 0건 · 🟡 5건 · ⚪ 1건 |

**③이 왜 필요한가** — 정상·부당 둘만 두면 🟡 경로가 한 번도 실행되지 않습니다.
"전부 빨강 아니면 전부 초록"으로 몰아가는 실패를 발견하지 못한 채 넘어갑니다.
`demo.py`에 "판단 불가" 케이스 4건을 반드시 넣은 것과 같은 이유입니다.

③은 상시 4명이라 공휴일 무급 조항이 ⚪ 적용 제외로 떨어집니다.
5인 미만 처리가 실제로 동작하는지 이 한 건으로 확인됩니다.

②의 부당 조항은 실제 상담 사례에 나오는 것들로 채웠습니다 —
포괄임금으로 가린 최저임금 미달, 수습 6개월 70%, 주 60시간, 휴게 30분,
연차 미부여, 주휴 무급, 퇴직금 월급 포함, 위약금 300만원, 급여 공제,
예고 없는 해지, 계약서 1부만 작성.

## 6. 확인 방법

```bash
# LLM·네트워크 없이 — 규칙 엔진과 가드레일만
.venv/bin/python tests/test_contract_rules.py      # 규칙 47건
.venv/bin/python tests/test_contract_samples.py    # 더미 3종의 기대 판정 고정
.venv/bin/python tests/test_contract_guard.py      # 가드레일 27건 (오탐 검사 포함)

# 실호출 — Document Parse + 추출 + 판정 대조
.venv/bin/python scripts/check_contract_api.py
.venv/bin/python scripts/check_contract_api.py --sample unfair --explain -v
.venv/bin/python scripts/check_contract_api.py --file 내계약서.pdf
```

`check_contract_api.py`가 보는 것은 **모델이 계약서를 얼마나 정확히 읽어내는가** 하나입니다.
규칙 엔진은 단위 테스트로 이미 고정돼 있어 흔들릴 곳이 없습니다.
`tests/test_contract_samples.py`에 손으로 채워 둔 기대 추출값과 필드별로 대조하고,
어긋난 필드를 출력합니다. 그게 `prompts/contract/extract.md`를 고칠 근거가 됩니다.

**심각도를 나눕니다.**

| | 처리 | 왜 |
|---|---|---|
| 🔴 오탐 | **실패** | 멀쩡한 조항을 위반이라고 말하면 사용자가 회사와 다투게 됩니다 |
| 🔴 누락 | **실패** | 잡아야 할 위반을 놓쳤습니다 |
| 🟡 누락 | 경고 | "확인해 보세요" 안내라 모델 재현율에 따라 실행마다 3~5건으로 달라집니다 |

🟡 누락을 실패로 세면 정작 위험한 🔴 오탐 신호가 그 안에 묻힙니다.

## 7. API

| 경로 | 설명 |
|---|---|
| `GET /contract` | 진단 화면 |
| `GET /api/contract/samples` | 더미 계약서 목록 |
| `GET /api/contract/samples/<id>` | 더미 계약서 PDF 원본 |
| `POST /api/contract/review` | multipart. `file` 또는 `sample`, `ocr=auto\|force` → 판정 |
| `POST /api/contract/explain/stream` | `{review_id, provider}` → SSE 해설 |

판정과 해설을 두 요청으로 나눈 이유 —
판정은 결정적이라 한 번만 계산하면 되고, 해설만 모델을 바꿔 여러 번 받습니다.
계약 내용을 브라우저가 되돌려 보내면 조작된 판정으로 해설을 만들 수 있어
서버가 `review_id`로 들고 있습니다 (프로세스 메모리, TTL 30분, 최대 50건).

## 8. 개인정보

계약서에는 이름·주민등록번호·주소·사업장명이 들어 있습니다.

- 업로드 원본을 **서버에 저장하지 않습니다.** 요청이 끝나면 메모리에서 사라집니다
- Document Parse 결과만 **파일 해시**로 캐시합니다 (`outputs/contract/parsed/`, 호출당 과금이라)
- 진단 로그는 **기본 OFF**입니다 (`SAVE_CONTRACT_LOG=0`). 켜기 전에 마스킹을 먼저 넣으세요
- 파일 내용은 Upstage API로 전송됩니다. 화면에 이 사실을 밝힙니다
