# 프롬프트 설계

작성 2026-08-01 · 대상 독자: 프롬프트를 고칠 사람

`knowledge/_source/프롬프트-학습노트.md`의 **계약 4요소**를 골격으로 삼았습니다.
RAG를 아직 붙이지 않았지만, 붙였을 때 구조를 다시 짜지 않아도 되도록 자리를 미리 만들어 두었습니다.

---

## 1. 계약 4요소를 어디에 넣었나

학습노트의 체크리스트가 [prompts/system/base/00-계약.md](../prompts/system/base/00-계약.md) 한 파일에 그대로 들어가 있습니다.

| 학습노트 | 구현 | 핵심 문장 |
|---|---|---|
| ① 권위 — 검색 컨텍스트 > 학습 지식 | `## ① 권위` | "`참고 자료` 블록이 주어지면 그 내용이 네 학습 지식보다 우선한다" |
| ② 범위 — 컨텍스트 불충분 시 행동 | `## ② 범위` | 모른다고 말할 때 **무엇을/왜/어디서** 세 가지를 함께 준다 |
| ③ 제약 — 형식·톤·인용 요건 | `## ③ 제약` + [10-형식.md](../prompts/system/base/10-형식.md) | 결론 먼저 → 근거 → 행동. 출처는 기관명 + 기준 시점 |
| ④ 폴백 — 엣지 케이스 | `## ④ 폴백` 표 | 빈 자료 / 모순 자료 / 오래된 자료 / 모호한 질문 / 위급 상황 |

**폴백 강도는 "근거 있을 때만 답한다" 쪽으로 잡았습니다.**
학습노트가 지적한 대로 이건 정책 결정입니다. 거절이 늘어 커버리지는 떨어지지만,
이 서비스는 틀린 답이 사용자에게 실질적 피해를 주는 도메인이라 충실성을 택했습니다.

## 2. 파일 구조

```
prompts/
├── registry.json              페르소나 정의 — 어떤 파일을 어떤 순서로 조립할지
├── system/
│   ├── base/
│   │   ├── 00-계약.md          ① 권위 ② 범위 ③ 제약 ④ 폴백
│   │   ├── 10-형식.md          길이·표기·어조
│   │   └── 20-가드레일.md       9개 금지 규칙 (표현이 아니라 존립 조건)
│   └── persona/
│       ├── general.md          의도 분기 (제도/조회/행동/계산/감정/범위밖)
│       ├── wage_arrears.md     관측 → 한계 → 체크리스트 구조
│       └── safety_risk.md      등급 → 신호 → 범위한정 → 확인항목 4단계
├── rewrite/
│   └── query_rewrite.md       호출 ① 멀티턴 질의 재작성
└── few_shot/
    ├── general.jsonl          3개
    ├── wage_arrears.jsonl     3개
    └── safety_risk.jsonl      3개
```

파일을 나눈 이유는 **가드레일과 형식을 페르소나마다 복사하지 않기 위해서**입니다.
가드레일을 고치면 세 페르소나에 동시에 반영됩니다.

## 3. 조립 순서 — Lost in the Middle 대응

학습노트가 지적한 U자 곡선(컨텍스트의 처음·끝은 잘 쓰이고 중간은 부분적으로 무시됨)에 맞춰
**가장 중요한 두 블록을 양 끝에** 놓았습니다.

```
[앞]  00-계약.md            ← 권위·범위·제약·폴백
      참고 자료 (<doc> 블록)  ← RAG 검색 결과가 들어갈 자리
      10-형식.md
      persona/*.md
[끝]  20-가드레일.md         ← 어기면 답변이 차단되는 규칙
─────────────────────────
      few-shot (user/assistant 쌍)
      최근 이력 5턴
      이번 질문
```

구현은 [app/prompts.py](../app/prompts.py)의 `system_prompt()`입니다.
`registry.json`의 `system` 배열 순서가 그대로 반영되므로 **가드레일 파일은 배열의 마지막**에 둡니다.
참고 자료는 첫 블록(계약) 바로 뒤에 삽입됩니다.

현재 조립 결과 크기:

| 페르소나 | system 프롬프트 | few-shot |
|---|---|---|
| general | 약 8,300자 | 3쌍 |
| wage_arrears | 약 13,700자 | 3쌍 |
| safety_risk | 약 12,000자 | 3쌍 |

## 4. 문서 삽입 포맷 — `<doc>` 태그

학습노트의 "문서 삽입 포맷(XML형 권장)"을 따랐습니다.

```
# 참고 자료
아래 <doc> 블록이 네 학습 지식보다 우선한다. …

<doc id="common/10-서비스정의">
…
</doc>

<doc id="wage/20-확인체크리스트">
…
</doc>
```

지금은 `knowledge/<주제>/*.md`를 파일명 순으로 통째로 넣습니다.
RAG를 붙이면 **같은 `<doc>` 태그 안에 검색된 청크가 들어갑니다.**
`app/prompts.py`의 `_load_knowledge()` 하나만 교체하면 되고 프롬프트 파일은 그대로 씁니다.

주입 상한은 `KNOWLEDGE_BUDGET = 16000`자입니다. 이 값에 자주 닿으면 RAG로 넘어갈 시점입니다.

**인용 문법(`[doc_001]`)은 아직 켜지 않았습니다.** 지금은 지식 문서가 고정이라 문서 번호를 화면에 노출할 이유가 없고,
상담 어조에 각주 기호가 섞이면 오히려 읽기 나빠집니다. 대신 자연어 출처 표기(기관명 + 기준 시점)를 요구합니다.
RAG 연결 시점에 `00-계약.md`의 `③ 제약`에 인용 문법 4요소를 추가합니다.

## 5. few-shot을 3개만 둔 이유

학습노트는 "예시는 1~2개만"이라고 적고 있습니다. 어투 전달이 목적이기 때문입니다.
여기서는 **유형이 겹치지 않는 3개**로 타협했습니다.

| 페르소나 | 예시 1 | 예시 2 | 예시 3 |
|---|---|---|---|
| general | 전형적 질문 (체불 대응) | 범위 밖 거절 | 위험 목록 생성 거절 |
| wage_arrears | 사업장 조회 (관측→체크리스트) | 명단 등재 (정부 공개 사실) | 데이터 부족 ("모른다") |
| safety_risk | 지역·업종 경보 | 생태학적 오류 방어 | 표본 부족 ("모른다") |

**"모른다"와 "거절한다"를 반드시 한 자리씩 넣었습니다.** 프로토타입에서 가장 자주 빠지는 경로입니다.
예시를 늘리면 답변이 예시에 갇혀 응용을 못 하므로 3개를 넘기지 않습니다.

## 6. 멀티턴 — 2회 호출 체이닝

학습노트의 구조를 그대로 구현했습니다. [app/chat.py](../app/chat.py) 참조.

```
호출 ①  이력 + 질문  →  독립 질문으로 재작성      prompts/rewrite/query_rewrite.md
   ↓    (RAG를 붙이면 여기서 검색이 일어납니다)
호출 ②  참고 자료 + 질문  →  답변 생성
   ↓
후처리  가드레일 검사                            app/guardrails.py
```

**재작성 프롬프트의 필수 규칙 3개**를 모두 넣었습니다.

1. 이력 없이 이해되는 독립 질문으로 재구성
2. 답하지 말 것 (재작성만)
3. 이미 독립적인 질문은 그대로 반환 — 억지로 바꾸면 의미가 표류합니다

실제 동작:

```
이력: "인천 건설현장 요즘 위험한가요?" → "인천광역시 건설업은 이번 주 주의 단계입니다…"
질문: "그럼 거기 산재 신청은 어떻게 해요?"
재작성: "인천 건설현장에서 산업재해가 발생했을 때 산재 신청은 어떻게 하나요?"   (2.2초)
```

### 구현 결정

| 학습노트 권고 | 이 프로젝트 | 설정 |
|---|---|---|
| 이력 범위 최근 3~5턴 | 재작성 3턴 / 답변 5턴 | `REWRITE_HISTORY_TURNS` / `MAX_HISTORY_TURNS` |
| 호출 2에도 최근 이력 포함 | 포함 ("아까 그 방식" 처리) | — |
| 호출 1은 작고 빠른 모델 | 지금은 두 모델뿐이라 Upstage 고정 | `REWRITE_PROVIDER` |

재작성은 `REWRITE_ENABLED=0`으로 끌 수 있습니다.
**끈 상태와 켠 상태의 답변 품질을 비교하는 것이 프로토타입 단계의 목적 중 하나입니다.**

### 두 모델 비교에서의 처리

재작성은 **요청당 한 번만** 실행하고 결과를 양쪽 모델에 똑같이 넘깁니다.
모델마다 따로 재작성하면 서로 다른 질의로 출발해 비교가 성립하지 않습니다.
프런트가 `POST /api/rewrite`를 먼저 호출한 뒤 `resolved_query`를 두 스트림에 실어 보냅니다.

## 7. 아직 하지 않은 것

| 항목 | 이유 |
|---|---|
| CoT (사고 유도) | 학습노트의 `[TODO]`. solar-pro3·A.X-K1 모두 지시 준수가 충분해 지금은 불필요. 답변이 복잡해지는 케이스가 나오면 재검토 |
| 프리필 (응답 시작부 지정) | 두 API 모두 assistant 프리필을 안정적으로 지원하는지 미확인. 형식은 few-shot으로 충분히 잡힘 |
| 인용 문법 `[doc_001]` | RAG 연결 시점에 추가 |
| 프롬프트 캐싱 | 고정 시스템 프롬프트를 앞에 배치하는 구조는 이미 갖춤. 두 API의 캐싱 지원 여부 확인 필요 |
| 오래된 이력 요약 압축 | 5턴 윈도우로 충분. 대화가 길어지는 사례가 쌓이면 도입 |
