# 계약서 진단 E2E — 추가 가상 계약서 설계

`product/integrations/contract-api` 의 진단 파이프라인을 **새 계약서 유형으로** 검증합니다.
기존 샘플 3종(정상·부당·경계)이 못 건드리는 구간을 노립니다.

## 왜 필요한가

진단은 4층입니다.

```
① PDF·사진  → Upstage Document Parse → 마크다운
② 마크다운  → solar-pro3             → 조항 JSON
③ 조항 JSON → 규칙 엔진(코드)         → 조항별 판정
④ 판정      → LLM                    → 해설 문장
```

[`tests/test_contract_samples.py`](../tests/test_contract_samples.py) 는 **③만** 검증합니다.
사람이 손으로 채운 추출 결과를 규칙 엔진에 직접 넣고, LLM도 Document Parse도 부르지 않습니다.

**①②는 사실상 미검증입니다.** 그리고 ②가 값을 잘못 읽으면 ③은 그 잘못된 값으로
완벽하게 판정합니다. 규칙 엔진은 자기가 받은 게 틀린 줄 모릅니다. 최저임금 미달 계약서가
🟢 로 나올 수 있고, 그 반대도 됩니다. 규칙 엔진 테스트로는 절대 안 잡힙니다.

기존 샘플 3종은 **전부 같은 생성기가 만든 같은 서식**(고용노동부 표준근로계약서)이라
"서식이 다르면 어떻게 되는가"를 한 번도 묻지 않았습니다.

## 판정 4단계

| 레벨 | 표시 | 뜻 |
| --- | --- | --- |
| `violation` | 🔴 | 법정 기준 미달 — 조문이 명확하고 계약서 문면으로 확인되는 것 |
| `check` | 🟡 | 확인 필요 — 그 자체로는 위법이 아니거나 실태를 봐야 하는 것 |
| `ok` | 🟢 | 기준 충족 |
| `excluded` | ⚪ | 적용 제외 — 5인 미만이라 해당 조문이 적용되지 않는 것 |

## 기준값 (2026년)

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 최저임금 시급 | 10,320원 | `standards.MIN_WAGE[2026]` |
| 월 209시간 환산 | 2,156,880원 | 같음 |
| 수습 최대 감액 기간 | 3개월 | `PROBATION_MAX_MONTHS` |
| 수습 감액 하한 | 90% | `PROBATION_MIN_RATE` |
| 수습 감액 가능 계약기간 | 12개월 이상 | `PROBATION_MIN_TERM_MONTHS` |
| 5인 미만 기준 | 5명 | `SMALL_WORKPLACE_THRESHOLD` |
| 퇴직급여 주당 시간 | 15시간 | `SEVERANCE_MIN_WEEKLY_HOURS` |
| 기간제 상한 | 24개월 | `FIXED_TERM_MAX_MONTHS` |

5인 미만에서 적용 제외되는 조문 — `EXCLUDED_UNDER_5`

```
근기법 제23조(해고) · 제46조(휴업수당) · 제50조(근로시간) · 제53조(연장한도)
제56조(가산수당) · 제60조(연차) · 제55조②(공휴일)
```

**주휴일(제55조①)은 목록에 없습니다.** 5인 미만에도 적용됩니다. 이걸 ⚪ 로 떨어뜨리면
거짓 음성이고, 사용자가 받아야 할 돈을 못 받게 됩니다.

## 유형 A — 자유 양식

같은 내용을 표준서식이 아닌 형태로 씁니다.

- 조항 제목이 `제1조` 가 아니라 `1.` 이거나 아예 없음
- 표 대신 줄글 — "월 급여 250만원(주 40시간 기준, 고정연장수당 20만원 포함)"
- 항목 이름이 다름 — `소정근로시간` → `근무시간`, `상여금` → `성과급`

**기대 판정: 대조군(표준서식 동일 내용)과 완전히 같아야 합니다.**

이 유형만 유일하게 절대 기대값이 아니라 **상대 기대값**입니다. 판정이 갈리면
서식 차이가 원인이므로 ② 추출 프롬프트 문제입니다.

---

## 유형 B — 값의 경계

규칙이 갈리는 지점을 1원·1%·1명 단위로 노립니다.

| # | 조건 | 기대 | 근거 |
| --- | --- | --- | --- |
| B1 | 월급 2,156,880원 (209h 정확히) | 🟢 `min_wage` | 미달 아님 |
| B2 | 월급 2,156,000원 (880원 미달) | 🔴 `min_wage` | 209h 환산 미달 |
| B3 | 수습 3개월 · 90% · 계약 12개월 | 🟢 `probation` | 하한 충족 |
| B4 | 수습 3개월 · 89% · 계약 12개월 | 🔴 `probation_rate_low` | 하한 미달 |
| B5 | 수습 4개월 · 90% · 계약 12개월 | 🔴 `probation_over_3m` | 감액은 3개월까지 |
| B6 | 수습 4개월 · 감액 없음 | 🟡 `probation_over_3m` | 감액 없으면 위반 아님 |
| B7 | 상시 5명 · 연차 미부여 | 🔴 `no_annual_leave` | 제60조 적용 |
| B8 | 상시 4명 · 연차 미부여 | ⚪ `no_annual_leave` | `_scale` 이 제외 처리 |

B2가 가장 중요합니다. **월급을 최저임금 월 환산액과 직접 비교하면 통과해 버립니다.**
규칙 엔진 주석에 *"프롬프트만으로 시켰을 때 두 모델 다 209시간 환산을 건너뛰었다"* 고
적혀 있습니다. ②가 고정연장수당을 분리해 뽑는지도 여기서 드러납니다.

## 유형 C — 근무기간에 따라 달라지는 것

기존 샘플 3종에 **전혀 없는 축**입니다. 전부 기간 조건이 고정되어 있습니다.

| # | 조건 | 기대 | 근거 |
| --- | --- | --- | --- |
| C1 | 계약 11개월 · 수습 3개월 90% | 🔴 `probation_short_term` | 1년 미만은 감액 불가 |
| C2 | 계약 12개월 · 수습 3개월 90% | 🟢 `probation` | 감액 가능 |
| C3 | 주 14시간 · 퇴직금 조항 있음 | 🟡 `severance_hours_threshold` | 15시간 미만 |
| C4 | 계약 30개월 | 🟡 `fixed_term_over_2y` | 2년 초과 |
| C5 | 계약 11개월 · "퇴직금 미지급" 명시 | 🔴 `severance_waived` | **아래 참고** |

### C5 — 확인이 필요한 지점

`standards.SEVERANCE_MIN_MONTHS = 12` (계속근로 1년 이상)가 **정의만 되어 있고 어디에서도
쓰이지 않습니다.** 저장소 전체에서 참조 0건입니다.

그래서 `rule_severance` 는 계약기간과 무관하게 `severance_waived` 를 🔴 로 냅니다.
11개월 계약에도 🔴 가 붙습니다.

이게 오탐인지 아닌지는 **코드가 아니라 법 해석의 문제**입니다.

- 오탐이라는 쪽 — 계속근로 1년 미만은 퇴직급여 대상이 아니므로 미지급 약정도 무효가 아니다
- 정탐이라는 쪽 — 계약이 갱신되면 1년을 넘고, 사전 포기 약정 자체가 무효다

**규칙 엔진을 고치기 전에 판단이 필요합니다.** 상수를 쓰지 않은 것이 의도인지 누락인지
확인해야 합니다. 이 문서는 현재 동작을 기대값으로 적어 두고, 판단이 서면 함께 고칩니다.

---

## 유형 D — 적용 제외를 명시한 계약서

계약서에 *"상시 근로자 5인 미만으로 연장·야간·휴일 가산수당은 적용하지 않음"* 처럼
**적법한 적용 제외가 적혀 있는** 경우입니다. 위법이 아니라 ⚪ 인데, 🔴 로 읽기 쉽습니다.

| # | 조건 | 기대 | 근거 |
| --- | --- | --- | --- |
| D1 | 상시 4명 · 연차 미부여 명시 | ⚪ `no_annual_leave` | 제60조는 `EXCLUDED_UNDER_5` |
| D2 | 상시 4명 · **주휴수당 미지급** 명시 | 🔴 `no_weekly_holiday` | 제55조①은 목록에 **없음** — 5인 미만도 적용 |
| D3 | 인원 미기재 · 연차 미부여 명시 | 🟡 `no_annual_leave` + 🟡 `headcount_unknown` | `small=None` → 위반 단정 안 함 |
| D4 | 상시 4명 · 해고 자유 조항 | ⚪ `at_will_dismissal` | 제23조는 `EXCLUDED_UNDER_5` |

**D2가 이 유형의 핵심입니다.** 5인 미만이라고 전부 면제되는 게 아닙니다. 주휴일은
적용됩니다. 여기서 ⚪ 가 나오면 거짓 음성이고, 오탐보다 위험합니다.

**D3도 중요합니다.** 인원을 안 적었다고 5인 이상으로 가정하면 안 됩니다. `_scale` 이
`small is None` 일 때 🔴 를 🟡 로 낮추도록 되어 있습니다.

### D 설계 시 주의 — 가산수당 조항 코드가 없습니다

`schema.CLAUSE_CODES` 에 제56조(가산수당 미지급)에 해당하는 코드가 **없습니다.**

```
penalty_predetermined · damages_actual · wage_offset · forced_saving · severance_waived
at_will_dismissal · marriage_retirement · no_annual_leave · no_weekly_holiday
noncompete · confidentiality_penalty · duty_change_broad · unpaid_training · other
```

따라서 "가산수당을 지급하지 않는다" 조항은 `other` 로 떨어지고, `other` 는 법령 없는
🟡 입니다. `_scale` 은 `law` 가 `EXCLUDED_UNDER_5` 에 있고 레벨이 🔴 일 때만 동작하므로
⚪ 로 바뀌지도 않습니다.

**즉 가산수당 미지급 조항은 5인 이상 사업장에서도 🔴 가 되지 않습니다.** 이건 D 유형이
아니라 별도 결함으로 기록합니다 — 유형 D는 위 표의 4개로 구성하고, 가산수당은
`CLAUSE_CODES` 보강 과제로 넘깁니다.

## 측정 항목

| 항목 | 보는 것 |
| --- | --- |
| `extract_match` | ② 가 뽑은 값이 계약서에 적힌 값과 같은가 |
| `verdict_match` | ③ 의 판정이 위 기대 판정과 같은가 |
| `no_false_positive` | 정상 조항에 🔴 가 생기지 않는가 |
| `no_false_negative` | 위반 조항을 ⚪·🟢 로 넘기지 않는가 |

`no_false_negative` 가 가장 무겁습니다. 오탐은 사용자가 놀라는 것으로 끝나지만
거짓 음성은 **받을 수 있는 돈을 못 받게** 합니다.

## 순서

| 단계 | 내용 | API 키 |
| --- | --- | --- |
| 1 | 유형별 계약서를 생성기에 추가 (기대값을 코드에 명시) | ✗ |
| 2 | 규칙 엔진 단독 검증 — 손으로 채운 값 → ③ | ✗ |
| 3 | 실제 파이프라인 측정 — ①②③ 전 구간 | **✓** |

2단계에서 이미 규칙 엔진의 기간 조건 처리 문제가 드러날 수 있고, 그건 API 호출 0회로
잡히는 것입니다. 3단계에서만 공용 키를 쓰며, **돌리기 전에 채팅방에 공유**합니다.
