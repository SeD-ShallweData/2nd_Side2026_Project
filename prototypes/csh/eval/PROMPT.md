# 상담 프롬프트 — 측정과 개선

`product/prompts/chat/system.md` 를 고친 기록입니다. "좋아진 것 같다"가 아니라
고치기 전후를 같은 방식으로 재서 비교합니다.

측정 도구는 둘입니다. 방법은 각 파일 첫머리에 있습니다.

| 도구 | 보는 것 | 케이스 |
| --- | --- | --- |
| [prompt_quality.py](prompt_quality.py) | 검색 경로 4가지에서 답변 계약 전체 | 16건 × 2모델 |
| [company_context.py](company_context.py) | 사업장 컨텍스트 상담 (제1원칙 경로) | 6건 × 2모델 |
| [citation_attach.py](citation_attach.py) | 인용 부착 하나를 깊게 | 20건 × 2모델 |

판정은 규칙으로만 합니다(심판 LLM 없음). 저장된 답변 원문에서 매번 다시 채점하므로
채점 규칙을 고치면 before 도 같이 다시 채점되고, before 와 after 가 서로 다른
잣대로 비교되지 않습니다.

---

## 1차 — 법령을 서술하면서 근거를 안 붙이는 문제

> 이 회차의 수치는 PR #10 이전 프롬프트를 기준으로 잰 것입니다. #10 이 프롬프트를
> 새로 쓰면서 답변 흐름은 크게 좋아졌지만 아래 원인은 그대로 남아 있었고,
> 2차에서 다시 고쳤습니다.

**증상** — Upstage 가 법령 내용을 서술하면서 근거 조문을 붙이지 않았습니다.
검색 거리 0.35 미만 안정 구간 20케이스에서 20건 중 9건이 무인용이었습니다(SKT 0건).

**원인** — 지시문 자체였습니다.

> 인용은 해당 설명·행동 문장 끝에 citation을 그대로 괄호로 붙이세요.

`citation` 은 주입되는 JSON의 필드 이름인데, 한국어 문장에 영어 낱말로 섞여 있어
모델이 **그 낱말을 적으라는 뜻으로** 읽었습니다. "그대로"가 이를 강화했습니다.

> 연차 유급휴가는 다음과 같이 발생합니다 citation.

조문 값이 사라진 경우(Upstage)와 값은 살아 있지만 필드 이름이 새는 경우(SKT)가
있었습니다. 두 모델 모두 20건 중 5건에서 나왔습니다.

**결과** — 무엇의 값인지와 출력 예시를 함께 적어 무인용 9건 → 0건, 필드 이름 유출
5건 → 0건이 됐습니다.

## 2차 — 프로토타입 기반 재작성

### 왜 다시 손댔나

PR #10 이 답변 흐름(설계 라벨 없는 자연스러운 문단, 행동 중심)을 크게 개선했지만
세 가지가 남아 있었습니다.

1. 1차에서 찾은 인용 결함이 그대로 있었습니다. `citation을 그대로 괄호로 붙이세요` 가
   문장만 바뀐 채 유지됐습니다.
2. 프로토타입(`prototypes/csh/prompts/`)에 있던 **폴백·범위 규칙**이 제품에
   없었습니다. 근거가 없을 때 무엇을 해야 하는지, 서비스 범위 밖 질문을 어떻게
   처리하는지가 빠져 있었습니다.
3. #10 이 RAG에 **공식 안내 문서**(`official_guides.json`)와 `out_of_scope` 주제
   신호를 추가했는데, 프롬프트가 그 경로를 다루지 않았습니다.

### 검색 경로를 나눠서 잰 이유

RAG가 돌려주는 상태가 하나가 아닙니다. 경로마다 옳은 답이 달라 같은 잣대로 재면
안 됩니다.

| 경로 | 상태 | 기대하는 답 |
| --- | --- | --- |
| `law` | 조문 matched | 조문 근거를 문장마다 붙인다 |
| `guide` | 공식 안내만 matched | 고용노동부 안내를 근거로 쓰고 조문을 지어내지 않는다 |
| `scope_gap` | `out_of_scope` (주제명 있음) | 수록 범위 밖임을 밝히고 절차 설명을 하지 않는다 |
| `off_topic` | `distance_threshold` | 서비스 범위 밖이라 밝히고 설명을 시작하지 않는다 |

### 결과

경로별 **전항목 통과** 수입니다. 괄호 안은 눈에 띄는 항목입니다.

| 모델 | 경로 | 개선 전 | 개선 후 |
| --- | --- | --- | --- |
| upstage | law | 2/8 (근거 있음 3/8) | **6/8** (근거 있음 6/8) |
| upstage | guide | 0/2 (근거 있음 0/2) | **2/2** |
| upstage | scope_gap | 0/4 | 0/4 |
| upstage | off_topic | 0/2 | 0/2 |
| skt | law | 4/8 (행동 경로 4/8) | **6/8** (행동 경로 7/8) |
| skt | guide | 1/2 | **2/2** |
| skt | scope_gap | 0/4 | 1/4 |
| skt | off_topic | 0/2 | **1/2** |

필드 이름 유출은 32건 중 5건 → **0건** 입니다.

`law` 과 `guide` 는 분명히 좋아졌고, `scope_gap` 과 `off_topic` 은 움직이지
않았습니다. 아래에 따로 적습니다.

### 가드레일을 함께 고친 이유

인용 형식을 프롬프트로 가르치자 모델이 그 형식을 **없는 문서에도** 적용했습니다.

> 종합소득세 신고 절차입니다 … (국세청 「종합소득세 신고 안내」)
> 노동조합 설립 절차입니다 … (고용노동부 노동포털 「노동조합 설립 절차」)

둘 다 존재하지 않는 문서입니다. 검색이 실패한 질문에 그럴듯한 출처가 붙어
나갔습니다. 프롬프트로 막으려 했지만(“검색 결과에 없는 문서 이름을 지어내지
마세요”) 계속 나왔습니다.

`guardrails.ts` 의 인용 검증에 구멍이 두 개 있었습니다.

- **적재 목록 밖 법령을 못 봤습니다.** 조문 정규식이 적재된 7개 법령만 알아서,
  "노동조합 및 노동관계조정법 제2조" 를 인용하면 인용이 아예 발견되지 않아
  검증을 통과했습니다.
- **공식 안내 문서명을 안 봤습니다.** 조문만 검사해서 지어낸 「」 문서명이
  그대로 나갔습니다.

둘 다 검증 대상에 넣었습니다. 이제 지어낸 근거는 `UNVERIFIED_LAW_CITATION` 으로
걸려 정책 baseline 으로 교체됩니다. 측정에서도 "모델이 지어냈는가"(`no_fabrication`)와
"사용자에게 닿았는가"(`no_leak`)를 나눠 봅니다. 배포 기준은 뒤쪽입니다.

개선 후 지어낸 근거가 사용자에게 닿은 경우는 **경로 전체에서 0건**입니다.
대신 가드레일 교체가 7건 생겼습니다(대부분 `scope_gap`·`off_topic`).

### 프롬프트로 고치지 못한 것

`scope_gap` 과 `off_topic` 은 **프롬프트 네 번을 고쳐도 움직이지 않았습니다.**

검색은 정확히 신호를 줍니다. `retrieval_reason=out_of_scope`,
`retrieval_topic=노동조합`, 그리고 정책 baseline 이 "현재 공식 근거 검색 범위에는
노동조합 자료가 수록되어 있지 않습니다" 를 제한사항으로 넣어 줍니다. 그런데도 두
모델 모두 자기가 아는 절차를 설명합니다.

시도한 것과 결과입니다.

| 시도 | 결과 |
| --- | --- |
| 금지 규칙을 명시 | 변화 없음 |
| 위반 사례를 열거(산재 신청 절차, 노조 설립 절차 …) | 변화 없음 |
| `[답변 흐름]`보다 우선한다고 절 제목에 명시 | 변화 없음 |
| 첫 문장을 그대로 쓰라고 문장 템플릿 제공 | 12건 중 1건만 따름 |

내용도 부정확합니다. Upstage 는 "노동조합 설립 시 근로자 3인 이상", SKT 는
"근로자 3분의 2 이상 동의" 라고 답했는데 둘 다 근거 없는 서술입니다.

### 교차검증 — 검색은 제대로 하고 있다

넘기기 전에 검색 쪽 문제인지 따로 확인했습니다. **아니었습니다.**

**거짓 양성 없음.** 재해보상 조문(근로기준법 제78~84조)은 DB에 있고, 관련 질문은
`out_of_scope` 에 막히지 않고 정상적으로 매칭됩니다.

| 질문 | 결과 |
| --- | --- |
| 일하다 다쳤는데 회사가 치료비를 안 줍니다 | matched — 근로기준법 제84조, 제80조 |
| 업무상 부상으로 쉬는 동안 보상을 받을 수 있나요? | matched — 제84조, 제79조, 제78조 |
| 업무 중 사고로 사망하면 유족에게 보상이 있나요? | matched — 제82조, 시행령 제51조 |
| 일하다 다쳤는데 **산재 신청은 어떻게** 하나요? | out_of_scope — 절차는 산재보험법 소관이라 맞는 판정 |

**거짓 음성 없음.** DB 밖 주제는 주제명이 안 붙더라도 전부 `no_match` 로 옵니다
(노조 가입, 특수고용직, 플랫폼 노동, 안전장비 등 확인). 즉 **모델은 항상 신호를
받습니다.**

**그래서 검색 문제가 아니라 답변 계층 문제입니다.** 코드를 보면 강제 장치가 없습니다.

- `emergency_guidance` 는 LLM을 아예 부르지 않고 정책 응답으로 **단락**시킵니다
  (`chatComparisonService.ts`, `execution_mode: "policy_short_circuit"`).
- `no_match` 는 `limitations` 에 문장 하나를 덧붙이고 **그대로 LLM에 넘깁니다.**
- 가드레일은 인용과 단정 표현만 봅니다. "범위 밖 주제의 절차를 설명하는 것"을
  보는 규칙은 없습니다.

이미 있는 단락 장치가 `out_of_scope` 에는 걸려 있지 않은 것입니다. 브리핑에 HB
대기 항목으로 적힌 **no_match 응답 품질**과 같은 문제라, 측정과 근거만 남기고
넘깁니다. `results/quality-after.json` 에 답변 원문이 그대로 있습니다.

지금은 가드레일이 지어낸 근거만 막고 있어서, 사용자는 **틀린 절차 설명**은 그대로
보게 됩니다. 근거가 안 붙었을 뿐입니다.

### 측정 자체에서 고친 것

교차검증 중에 채점 규칙과 프롬프트에서 각각 하나씩 잘못을 찾았습니다.

- `gap_stated` 정규식이 "공식 자료 범위에 **없습니다**" 를 못 잡아, 실제로 범위 밖임을
  밝힌 SKT 답변 1건을 미달로 셌습니다. 고쳐서 skt `scope_gap` 은 0/4 이 아니라
  1/4 입니다. 위 표는 고친 뒤 숫자입니다.
- 프롬프트에 문장 템플릿을 `“{주제}는 …”` 로 적었더니 모델이 중괄호까지 그대로
  옮겨 `“{노동조합}은 현재 …”` 를 출력했습니다. 템플릿에서 중괄호를 빼고 예시
  문장을 직접 적는 방식으로 고쳤습니다. 저장된 결과는 고치기 전 것입니다.

## 3차 — 사업장 컨텍스트

`company_id` 를 붙인 상담은 한 번도 측정된 적이 없었습니다. 제품 프롬프트에는
"사업장 컨텍스트가 있으면 필요한 확인 행동만 고르세요" 한 줄뿐이었고, 프로토타입에
있던 조회 골격과 가드레일은 옮겨지지 않은 상태였습니다.

이 경로가 서비스의 제1원칙이 걸린 곳입니다 — 아직 체불하지 않은 사업장을 공개적으로
"위험"이라 부르면 사실이라도 명예훼손 소지가 있습니다([ADR-0001](../docs/ADR/0001-위험카드-표시정책.md)).

### 이 경로만 다른 점

사업장 질문은 법령 질문이 아니라서 RAG 가 `no_match` 를 돌려줍니다. 그런데 답변에
쓸 근거는 있습니다 — DB에서 온 사업장 판정 결과입니다. **"검색 실패"와 "근거 없음"이
같지 않은 유일한 경로**입니다. 2차에서 추가한 근거 없을 때 규칙이 여기까지 적용되자
모델이 멀쩡한 사업장 질문을 "범위 밖"이라며 거절했습니다.

### 결과

위험 조합이 서로 다른 실제 사업장 4곳(안정 / 확인 유보 / 자료 없음 / 산업안전 상위
구간)에 6개 질문입니다.

| 모델 | 전항목 통과 | 내부값 노출 | 지역·업종 한정 | 확인 행동 |
| --- | --- | --- | --- | --- |
| skt | 4/6 → **6/6** | 5/6 → 6/6 | 5/6 → 6/6 | 6/6 |
| upstage | 2/6 → **4/6** | 5/6 → 5/6 | 3/6 → 5/6 | 5/6 → 6/6 |

안전·위험 판정(`no_verdict`)과 명단 등재 정확성(`listing_ok`)은 개선 전에도 6/6
이었습니다. 가드레일과 기존 프롬프트가 가장 위험한 두 가지는 이미 막고 있었습니다.

### 말하면 안 되는 값은 주지 않는다

`상위1%`, `PUBLISHED_SAFETY_PRIORITY_BAND`, 내부 배치·파이프라인 이름이 사용자
답변에 그대로 나왔습니다. 프롬프트에 "등급·순위·근거 코드를 말하지 마세요"라고
적어도 소용이 없었습니다. **컨텍스트가 그 값을 쥐여 주고 있었기 때문입니다.**

`DualLlmChatProvider` 가 모델에게 넘기는 사업장 판정 사본에서 내부 값을 걷어냈습니다
(`publicSignalForPrompt`). 사람이 읽을 요약문과 면책 문구는 남기고, 근거 코드·등급
토큰·생성 시각·내부 출처 이름을 빼고 순위 표기를 "상위 구간"으로 바꿉니다. 화면이
쓰는 `/api/companies/{id}/risk` 응답은 건드리지 않습니다 — 프롬프트에 넣을 사본만
정리합니다. 이 한 번으로 `no_internal` 이 두 모델 모두 6/6 이 됐습니다.

### 남은 것

- upstage 가 `배치` 라는 낱말을 그대로 옮기는 경우가 있습니다. 자료 없음 사업장의
  요약문이 "최신 **배치**에서 판정 결과를 확인하지 못했습니다" 라서 그렇습니다.
  내부 용어가 사용자 화면 문구에 들어 있는 것이라 요약문을 만드는 쪽에서 고칠 일로
  보고 남겨 둡니다.
- 답변이 컨텍스트에 없는 기준을 만들어 붙이는 경우를 한 건 봤습니다("체불액이
  3천만원 이상인지", "2회 이상 유죄 확정"). 지금 채점에는 이 항목이 없습니다.

## 배운 것

**프롬프트 안의 필드 이름은 값으로 치환되지 않습니다.** 주입되는 JSON의 키를
지시문에 그대로 쓰면 모델은 그 낱말을 출력합니다. 무엇의 값인지와 출력 예시를
함께 적어야 합니다.

**지시를 더하면 다른 지시가 밀려납니다.** 1차에서 인용 규칙을 5줄로 늘렸더니 인용
지표는 좋아진 대신 "지금 할 행동"이 사라졌습니다(upstage 18 → 10, skt 12 → 7).
규칙을 3줄로 압축하고 형식 규칙에 한 줄을 덧붙여 되돌렸습니다. 인용만 재고
끝냈으면 이 손실을 못 봤을 것이므로, 측정에 행동 경로를 같이 넣어 뒀습니다.

**형식을 가르치면 엉뚱한 데까지 적용합니다.** 인용 형식을 가르치자 검색되지 않은
질문에도 그럴듯한 출처를 지어 붙였습니다. 형식을 요구할 때는 **어디에 쓰면 안
되는지**를 같은 강도로 적어야 하고, 그래도 새면 코드로 막아야 합니다.

**여지를 주면 느슨한 쪽으로 갑니다.** 목록형 답변을 잡으려고 "번호나 불릿으로
나열할 때는 목록을 여는 문장 끝에 조문을 붙이면 됩니다"를 덧붙였더니 오히려
목록으로 답하는 경우가 늘어 나빠졌습니다. 되돌렸습니다.

**모델의 도움 본능은 프롬프트보다 셉니다.** 아는 주제에 대해 "설명하지 말라"는
지시는 네 번 고쳐도 통하지 않았습니다. 지켜야 하는 경계는 코드에 두는 편이
낫습니다.

**말하면 안 되는 값은 프롬프트로 막지 말고 주지 마세요.** 컨텍스트에 등급·순위·근거
코드가 들어 있는 한 모델은 그것을 옮깁니다. 금지 문구를 늘리는 것보다 주입 사본에서
빼는 쪽이 한 번에 끝났습니다.

**절이 길어지면 다른 경로로 샙니다.** 사업장 절을 7줄로 붙였더니 사업장과 무관한
답변까지 "확인 체크리스트:"로 끝나고 공식 안내 인용이 사라졌습니다(guide 2/2 → 1/2).
절 머리에 적용 조건을 못박고 5줄로 줄이자 되돌아왔을 뿐 아니라 skt `law` 가 8/8 로
올랐습니다. 규칙을 더할 때는 **어디에 적용되지 않는지**를 같이 적어야 합니다.
