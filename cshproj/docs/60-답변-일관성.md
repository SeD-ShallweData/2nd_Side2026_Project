# 답변 일관성

작성 2026-08-01 · 측정 [scripts/check_consistency.py](../scripts/check_consistency.py)

같은 질문에 매번 다른 답이 나오면 상담 서비스로 쓸 수 없습니다.
이 문서는 **어디까지 맞출 수 있고 어디부터는 불가능한지**, 그리고 무엇으로 맞췄는지 정리합니다.

---

## 1. 먼저 확인한 것 — 완전한 재현은 불가능합니다

`샘플A건설 어때요?`를 5회 반복한 결과 (2026-08-01, temperature=0.3):

| 모델 | 서로 다른 답변 | 길이 |
|---|---|---|
| Upstage solar-pro3 | **5회 / 5종** | 322~410자 |
| SKT A.X-K1 | **5회 / 5종** | 340~583자 |

SKT는 같은 자료에서 서로 모순되는 답까지 냈습니다.

```
1회차: "가입자 수가 25.5% 감소한 것이 관찰됩니다"
2회차: "고용 감소 신호가 확인되지 않았습니다"   ← 51명 → 38명인데 감소가 아니라고 함
```

### 샘플링 파라미터로는 해결되지 않았습니다

| 시도 | Upstage | SKT |
|---|---|---|
| `temperature=0` | 4회 / **4종** | 4회 / **4종** |
| `temperature=0` + `seed=42` | 3회 / **3종** | 3회 / **3종** |
| `+ top_p=1` | 3회 / **3종** | 3회 / **3종** |

**두 API 모두 `seed`를 받기만 하고(HTTP 200) 무시합니다.**
비트 단위로 동일한 출력은 이 두 API로 얻을 수 없습니다.

> 참고로 이건 두 API만의 문제가 아닙니다. 대부분의 상용 LLM API는 배치 처리·하드웨어 차이 때문에
> `temperature=0`에서도 완전한 결정성을 보장하지 않습니다.

## 2. 그래서 무엇을 맞췄나 — 표현이 아니라 사실과 구조

실무에서 필요한 일관성은 "글자가 똑같은 것"이 아니라
**"같은 사실을, 같은 순서로, 같은 결론으로"** 말하는 것입니다. 세 가지를 걸었습니다.

### ① temperature 0.0

기본값을 `0.3 → 0.0`으로 내렸습니다. 완전한 재현은 안 되지만 표현 흔들림의 폭은 줄어듭니다.
표현 다양성을 볼 일이 있을 때만 `config.env`에서 올리세요.

### ② 출력 골격 고정 — 가장 큰 레버

페르소나 프롬프트에 **항목과 순서를 못박았습니다.** 이전에는 "관측 사실 → 한계 → 체크리스트"라고만
적혀 있어서 모델이 매번 다른 항목을 골랐습니다.

`prompts/system/persona/wage_arrears.md`:

```
① 명단 등재 여부   — 체불사업주 명단 / 건강보험 체납 명단. 등재면 공개 시점을 함께.
② 관측 지표       — <record>에 적힌 순서 그대로:
                     국민연금 가입자 변화 → 이직률 → 1인당 고지금액 → 최근 3개월 결측
③ 해석의 한계     — "이 수치들은 임금체불을 뜻하지 않습니다." 한 문장.
④ 확인 체크리스트  — <record>의 항목을 그대로. attention 먼저.
⑤ 면책            — 고정 문구 한 문장.
```

산재 페르소나에도 같은 방식으로 5단계를 못박았습니다.

**"자료에 없는 줄은 통째로 생략한다"** 를 함께 넣은 것이 중요합니다.
이게 없으면 빈 슬롯을 추정치로 채웁니다.

### ③ 조회 대상이 없으면 사업장 데이터를 아예 넣지 않는다

`"회사가 위험한지 알고 싶어요"`처럼 회사명도 지역·업종도 없는 질문에
**사업장 14건을 전부 프롬프트에 넣고 있었습니다.** 모델은 그중 아무거나 골라 수치를 인용했고,
회차마다 고르는 대상이 달라 사실이 통째로 흔들렸습니다.

`demo.filter_records()`를 고쳐 조건이 없으면 **빈 목록**을 돌려주고,
"조회 대상이 지정되지 않았습니다. 사업장명 또는 지역·업종을 받기 전에는
어떤 사업장의 수치도 인용하지 않습니다"를 대신 넣습니다.

이름이 나온 질문은 **그 사업장만** 넣습니다. 이전에는 `샘플A건설 어때요?`에
건설업 5건을 전부 넣었습니다 — 후보가 많을수록 흔들립니다.

### ④ 수치 재계산 금지

`prompts/system/base/10-형식.md`에 「일관성」 절을 신설했습니다.

> - **수치는 `<record>`에 적힌 값을 그대로 옮긴다.** 새로 계산하거나 반올림하지 않는다.
>   적혀 있지 않은 파생값(증감률, 평균, 배수)을 직접 만들어 쓰지 않는다.
> - **자료의 값과 어긋나는 서술을 하지 않는다.** 가입자 수가 줄어든 기록에 대해
>   "감소 신호가 확인되지 않았다"고 쓰지 않는다.
> - **결론을 먼저 정하고 근거를 붙인다.** 같은 자료에서 어떤 날은 "확인이 필요하다",
>   어떤 날은 "특별한 신호가 없다"가 나오면 안 된다.

SKT가 `-25.5%`를 직접 계산해 놓고 다음 회차에는 정반대로 서술한 것이 이 규칙을 만든 이유입니다.

### ⑤ few-shot을 골격에 맞춘다

골격을 넣었는데도 `예시C물류` 답변만 흔들렸습니다.
원인은 **few-shot 예시가 새 골격을 따르지 않는 것**이었습니다 — 체크리스트 없이 끝나는 예시였습니다.
모델이 골격과 예시 사이에서 갈렸습니다.

**예시가 골격과 다르면 예시가 이깁니다.** few-shot을 ①~⑤ 순서에 맞춰 다시 썼더니
두 모델 모두 4회 완전 동일로 안정됐습니다.

## 3. 결과 (2026-08-01)

같은 질문 4회 반복. `check_consistency.py` 기준.

| 질문 | 모델 | 사실 일치 | 골격 | 길이 편차 |
|---|---|---|---|---|
| 샘플A건설 어때요? | Upstage | 100% | 100% | **0%** |
| | SKT | 50% | 100% | 3% |
| 예시C물류는요? | Upstage | 100% | 100% | **0%** |
| | SKT | 100% | 100% | **0%** |
| 인천 건설현장 요즘 위험한가요? | Upstage | 100% | 100% | **0%** |
| | SKT | 100% | 100% | 0% |
| 예시G디자인 어때요? | Upstage | 100% | 100% | 5% |
| 샘플E식자재는 어때요? | Upstage | 100% | 100% | **0%** |
| | SKT | 25% | 100% | 5% |
| 회사가 위험한지 알고 싶어요 | SKT | 100% | 100% | 9% |
| | Upstage | 75% | 100% | 36% |

시작점은 **5회 전부 다른 답변, 길이 편차 28~97자**였습니다.
지금은 사업장 조회에서 **Upstage가 4회 완전 동일**하고, 골격은 두 모델 모두 100% 유지됩니다.

### 남은 것

| 증상 | 빈도 | 메모 |
|---|---|---|
| SKT가 미등재 사업장에 다른 사업장의 명단 공개일을 붙임 | 4회 중 1~2회 | 프롬프트에 "미등재면 날짜를 붙이지 않는다"를 넣어 줄었으나 완전히 사라지지는 않음 |
| SKT가 `<record>`에 없는 파생값(증감률 등)을 만듦 | 가끔 | 재계산 금지 규칙이 있으나 SKT가 더 자주 어김 |
| 회사명 없는 개방형 질문의 분량 편차 | Upstage ±36% | 조회 대상이 없으므로 자유 서술. 골격·사실은 안정적 |

**Upstage가 지시를 더 엄격히 따릅니다.** 같은 프롬프트에서 SKT가 더 자주 벗어납니다 —
시연에서 재현성이 중요하면 Upstage를 기본으로 두는 편이 안전합니다.

## 4. 측정 방법

```bash
.venv/bin/python scripts/check_consistency.py
.venv/bin/python scripts/check_consistency.py --ids wage-02,wage-03 --runs 5
.venv/bin/python scripts/check_consistency.py --provider skt
```

글자 일치는 애초에 불가능하므로 **세 가지 대리 지표**를 봅니다.

| 지표 | 무엇을 보나 | 목표 |
|---|---|---|
| **사실 일치** | 답변에 등장한 수치 집합이 매번 같은가 | 100% |
| **골격 유지** | 정해진 항목이 매번 나오는가 | 100% |
| **길이 편차** | 분량이 들쭉날쭉하지 않은가 | 15% 이하 |

**사실 일치가 가장 중요합니다.** 표현이 달라도 숫자가 같으면 상담으로 쓸 수 있고,
표현이 같아도 숫자가 흔들리면 못 씁니다.

결과는 `outputs/eval/<타임스탬프>_consistency.jsonl`에 답변 원문까지 저장되므로
프롬프트를 고치기 전후를 직접 비교할 수 있습니다.

## 5. 가드레일 차단이 들쭉날쭉하던 것도 같은 원인

"어떤 때는 막히고 어떤 때는 안 막힌다"는 별개 버그가 아니라 **변동성의 증상**이었습니다.
모델이 회차마다 다른 문장을 만들다 보니 어떤 회차에서만 규칙에 걸린 것입니다.

골격을 고정하면 차단 빈도도 함께 떨어집니다.
프롬프트를 다듬는 동안에는 `GUARDRAIL_MODE=warn`으로 두고 원문을 보면서 작업하세요
([20-가드레일.md](20-가드레일.md) 참조).

## 6. 남은 한계

| 항목 | 메모 |
|---|---|
| 문장 단위 완전 일치 | 두 API가 seed를 무시하는 한 불가능 |
| 캐시로 고정하기 | 같은 질문의 답을 저장해 재사용하면 완전히 고정되지만, 이력·맥락이 반영되지 않음. 시연 안정성이 최우선이면 검토 가치 있음 |
| 모델 간 골격 차이 | 같은 프롬프트라도 SKT가 Upstage보다 길고 굵게 표시를 많이 씁니다. 골격은 같아도 분량은 다릅니다 |
| 후속 질문 일관성 | 아직 측정하지 않았습니다. 재작성 체이닝이 회차마다 다른 질의를 만들면 그 뒤가 전부 흔들립니다 |
