## 3. 값 수준 — 9항목

### V1. 불리언 컬럼이 0/1 🔴

적재 캐스팅이 `nullif(x,'')::numeric::int::bool` 이라 문자열 불리언은 **캐스팅 실패**한다.

| 값 | 판정 |
| --- | --- |
| `0` · `1` · `0.0` · `1.0` · 빈 칸 | 통과 |
| `TRUE` · `FALSE` · `True` · `False` · `t` · `f` · `Y` · `N` | **오류** |

대상 컬럼

```
scored:  G1_고용안정 · G2_성실납부 · G3_인건비안정 · G4_인력유지 ·
         G5_업력3년 · G6_낮은변동성 · 체불배제 · 체납배제      (8)
queue:   door1_체납이력 · 이미_임금체불공개                      (2)
safe:    체불배제 · 체납배제                                     (2)
```

- **메시지**: `[V1] 불리언 표기 오류: G1_고용안정 3행에 'True' — 0/1 로 저장하세요 (pandas: astype(int))`
- **보고 방식**: 위반 값의 **종류와 첫 5행 번호**를 보고. 전체 행을 나열하지 않는다

> `door1_ever` 는 불리언처럼 보이나 `::real` 캐스팅이다. **V1 대상이 아니다.**
> 다만 실측상 값이 0/1뿐이므로 V6에서 범위만 본다.

### V2. `risk_full` 결측이 빈 칸 🔴

```
risk_full = (빈 칸)  →  NULL  →  "이력 부족으로 채점 불가"
risk_full = 0        →  0     →  "위험도 0인 안전한 회사"
```

**의미가 정반대다.**

- **판정**: 값이 `NaN` · `nan` · `NULL` · `null` · `None` · `#N/A` 중 하나면 오류
- **메시지**: `[V2] 결측 표기 오류: risk_full 에 'NaN' — 빈 칸으로 저장하세요 (fillna 금지)`

> 🔴 **`0` 으로 채운 것은 이 검사로 잡을 수 없다.** 정상값과 구분이 불가능하다.
> 대신 **V3에서 정황을 본다.**

### V3. `scored` 의 `risk_full` 빈 칸 비율 🟡

`0` 으로 채운 사고를 **간접 탐지**한다.

- **판정**: `scored` 의 `risk_full` 빈 칸 비율이 **1% 미만**이면 경고
- **근거**: 운영 DB 실측 배치 7종 전부 **8.6~9.2%** 가 NULL이다. 0%에 가까우면 `fillna(0)` 정황
- **메시지**: `[V3] risk_full 빈 칸이 0.0% 입니다 — 과거 배치는 8.6~9.2% 였습니다. fillna(0) 여부를 확인하세요`
- **심각도가 경고인 이유**: 모델이 바뀌어 실제로 결측이 줄었을 수 있다. **단정할 수 없다**

### V4. `판정` 이 허용 6종 🔴

```
안정신호
유보
유보_정보부족
배제_임금체불공개
배제_공개체납
배제_4대보험체납(door1)
```

- **판정**: `safe` 의 `판정` 컬럼 전 행이 위 6종 안에 있는가. **공백·괄호까지 정확히 일치**
- **메시지**: `[V4] 알 수 없는 판정값: '배제_4대보험체납' 12행 — 허용 6종과 한 글자도 달라선 안 됩니다`
- **근거**: 화면 매핑(`MlRiskProvider.VERDICT_META`)이 이 문자열에 1:1로 걸려 있다.
  전 배치 3,524,726행 실측에서 7번째 값은 없었다

### V5. `위험등급` 이 허용 4종 🔴

```
긴급 / 우선 / 주의 / 관찰
```

- **판정**: `queue` 의 `위험등급` 전 행이 위 4종 안에 있는가
- **메시지**: `[V5] 알 수 없는 위험등급: '높음' 45행`

### V5-1. 위험등급 쿼터 🟡

- **판정**: `긴급 100 · 우선 400 · 주의 1,000 · 관찰 1,500` 과 다르면 경고
- **근거**: 전 배치 7회 **예외 없이 동일** [실측]
- **메시지**: `[V5-1] 위험등급 개수가 다릅니다: 긴급 120 (과거 7배치 모두 100)`
- **심각도가 경고인 이유**: 쿼터 변경은 계약 변경일 뿐 오류가 아니다. 다만 **말없이 바뀌면 안 된다**

### V6. `risk_full` 값이 0~1 🟡

- **판정**: `0 ≤ x ≤ 1` 을 벗어난 값
- **근거**: 전 배치 3,855,848행에서 **위반 0건** (범위 0.004816~0.990447)
- **메시지**: `[V6] risk_full 범위 밖: 1.0231 (3행) — 0~1 이어야 합니다`
- **심각도가 경고인 이유**: **이론상 범위 이탈 가능성이 미확인**이다 (Q2, 모델 담당 회신 대기).
  오류로 막으면 정상 산출물이 반려될 수 있다. **회신을 받으면 🔴로 올린다**

### V7. `핵심_위험사유` 구분자 🔴

구분자는 **`공백 + 가운뎃점(U+00B7) + 공백`** 이다.

```
정상  체납액 · imputed_months_count · door1_maxmonths
오류  체납액·imputed_months_count            (공백 없음)
오류  체납액, imputed_months_count           (쉼표)
오류  체납액 - imputed_months_count          (하이픈)
```

**구분자가 틀려도 적재 시 에러가 나지 않는다.** 배열 원소가 1개인 채로 저장된다.

- **판정 1**: `' · '` 로 분리했을 때 원소가 **3개**가 아니면 오류
- **판정 2**: 분리 후 원소에 `·` 가 남아 있으면 오류 (구분자 오인)
- **메시지**: `[V7] 위험사유 구분자 오류: 7행이 1개 원소 — 구분자는 ' · '(공백+U+00B7+공백)입니다`
- **근거**: 전 배치 21,000행 **전부 원소 3개**, 원소 내 가운뎃점 0건 [실측]

### V8. `순위` 가 1부터 연속 🔴

- **판정**: 정렬했을 때 `1..N` 과 정확히 일치. 중복·결번 없음
- **메시지**: `[V8] 순위 결번: 1523 이 없습니다` / `[V8] 순위 중복: 88 이 2회`

### V9. 사업자번호 문자열·앞자리 0 보존 ⚪ **검사 불가**

**CSV만 보고 원본에 앞자리 0이 있었는지 알 수 없다.**
0이 이미 떨어진 파일과, 애초에 0이 없던 파일이 **구분되지 않는다.**

- **대신 검사하는 것 🟡**: 값의 **길이가 일정한가**
- **판정**: `사업자번호` 의 길이 종류가 2개 이상이면 경고
- **근거**: 운영 DB 639,137건 전부 **6자리** [실측]. 길이가 섞이면 0이 떨어진 정황
- **메시지**: `[V9] 사업자번호 길이가 섞여 있습니다: 5자리 12건 · 6자리 553,586건 — 앞자리 0 유실 가능성`
- **보고서 표기**: **「앞자리 0 보존 여부: 검사하지 않음(원리상 불가). 길이 일관성만 확인」**

### V10. `sido_code`·`industry_category` 가 문자열 ⚪ **검사 불가**

**CSV에는 타입이 없다.** 모든 값이 문자열이다.

- 정수로 저장돼 앞자리 0이 떨어지는 사고를 노려야 하는데,
  실측상 `sido_code` 는 **11~50 범위라 0으로 시작하지 않는다** [실측].
  즉 **이 사고가 일어나도 CSV에서 흔적이 남지 않는다**
- **보고서 표기**: **「문자열 여부: 검사하지 않음(CSV에 타입 없음)」**
- **대신 필요한 것**: 제출 코드에서 `dtype={'sido_code': str, ...}` 를 쓰는지가 실질 방어다.
  계약 문서 **부록 C** 의 저장 예시를 따르면 된다

## 4. 관계 수준 — 4항목

식별키는 **`(사업장명, 사업자번호)`** 쌍이다. `firm_id` 는 적재 시 생성되므로 CSV에 없다.

### R1. `safe ⊆ scored` 🔴

- **메시지**: `[R1] safe 에 있으나 scored 에 없는 사업장 3건 — 예: (○○건설, 123456)`

### R2. `queue ⊆ safe ⊆ scored` 🔴

- **판정**: `queue ⊆ scored` 와 `queue ⊆ safe` 를 각각 본다
- **메시지**: `[R2] queue 에 있으나 safe 에 없는 사업장 1건`

### R3. `scored` 내 식별키 중복 없음 🔴

- **메시지**: `[R3] scored 에 중복 사업장 2건 — (○○물산, 123456) 이 2회`
- **왜 중요한가**: 중복이 있으면 `firm_id` 가 충돌해 적재가 깨지거나 한쪽이 덮인다

### R4. 세 파일의 `risk_full` 일치 🔴 **— 허용오차로 판정한다**

> 🔴 **등호로 검사하면 안 된다.** 운영 DB 실측에서 **21,000행 중 20,774행(98.9%)이 불일치**한다.

원인은 **`queue` 의 값이 소수 4자리로 반올림돼 있기 때문**이다 [실측].

```
queue 값이 4자리가 아닌 행        0 / 21,000     ← 전부 반올림돼 있음
scored 를 4자리 반올림하면 일치   20,893 / 21,000  (99.49%)
최대 차이                         0.0000500083
차이가 6e-5 를 넘는 행            0
```

남은 107행은 `real`(float4) 표현 한계로 보인다.

- **판정**: `abs(a − b) ≤ TOLERANCE`, 기본값 **`1e-4`**
- **상수로 뺀다**: `RISK_FULL_TOLERANCE = 1e-4`
- **메시지**: `[R4] risk_full 불일치: (○○건설, 123456) queue 0.9899 vs scored 0.9704 (차 0.0195 > 1e-4)`

> **모델 담당이 「큐에도 전체 정밀도를 넣겠다」고 회신하면 `0` 으로 낮춘다.**
> 회신 전까지는 `1e-4` 를 쓴다.

## 5. 메타데이터 — 4항목

`manifest.json` 은 계약상 **「권장」**이다. 없으면 이 절 전체를 **⚪ 미검사**로 남긴다.

### M0. `manifest.json` 존재 🟡

- **메시지**: `[M0] manifest.json 없음 — M1~M3 을 검사하지 않았습니다`

### M1. `model_version` 지정 🟡

- **판정**: `manifest.json` 에 값이 있고 비어 있지 않은가
- ⚪ **값이 옳은지는 검사할 수 없다.** 형식만 본다

### M2. `as_of` 형식 🟡 · **의미는 ⚪ 검사 불가**

- **판정 가능**: `YYYY-MM` 형식인가
- ⚪ **판정 불가**: 그 값이 **실제로 관측창 종료월인지**는 CSV·manifest 밖의 사실이라 확인할 수 없다
- **보고서 표기**: **「`as_of` 가 관측창 종료월인지: 검사하지 않음(파일 밖 정보)」**

> `as_of` 는 적재 시 `--as-of` 로도 들어간다. 둘이 다르면 **경고**한다.
> `target_month = as_of + 6개월` 은 DB가 자동 계산하므로 검사 대상이 아니다.

### M3. `expect_rows` 3개 값 🟡

- **판정**: `manifest` 의 예상 행수 3개가 **실제 파일 행수와 일치**하는가
- **메시지**: `[M3] 행수 불일치: scored manifest 553,598 vs 실제 553,412`
- **비고**: 이건 **실질적으로 유용하다.** 파일이 잘렸거나 일부만 저장된 사고를 잡는다
