> 기존 설계 `docs/mlops/batch-switch-design.md`(이하 "배치 설계서")의 Phase 2를 현재 코드 기준으로 갱신하고,

## 0. 한 장 요약

| 기능 | 지금 | 목표 |
| --- | --- | --- |
| 프롬프트 | 운영 관리자 화면(`/inspector/prompts`)에서 **읽기만** 된다. 편집한 내용은 브라우저에만 남는다 | 화면에서 고치고 → 검증 → 시험 실행 → 적용 → 이력·되돌리기 |
| 배치 | 새 배치를 적재하면 **기준월이 가장 늦은 배치가 즉시 서비스**된다. 되돌릴 수단이 없다 | 적재만 해 두고 비교한 뒤 전환, 이상하면 이전 배치로 되돌리기 |

두 기능 모두 **웹 프로세스가 DB에 써야** 한다는 같은 벽에 부딪힌다. 그래서 쓰기 경로를 한 번만 설계한다.

- 새 DB 계정 `wg_ops`는 **SECURITY DEFINER 함수 몇 개만** 실행할 수 있고, 테이블 직접 쓰기 권한은 없다.
- 웹은 `OPS_DATABASE_URL`이 설정됐을 때만 이 함수를 부른다. 설정이 없으면 기능 자체가 없는 것처럼 동작한다.
- 이는 "웹은 쓰기 자격증명을 갖지 않는다"는 현재 보안 계약의 **예외**이므로 팀 합의(§6 D1)가 먼저다.

## 1. 현재 상태 (2026-09-29 main 기준)

### 1.1 프롬프트

- 파일: `product/prompts/{chat,inspector,rewrite}/system.md` — 로더(`server/promptLoader.ts`)가 수정 시각을 보고 다시 읽는다.
- API: `GET /api/inspector/prompts`(admin 전용, `editable:false`). 화면 `PromptStudioPage`는 "저장한 내용은 이 화면에서만 유지"된다.
- 파일을 운영 중에 고칠 수 없는 이유
  - web 유닛이 `ProtectSystem=strict` + 프로젝트 루트 `ReadOnlyPaths`라 웹 프로세스는 저장소 파일을 쓸 수 없다.
  - 서버에서 파일을 직접 고치면 `git` 작업트리가 dirty가 되어 다음 배포가 `--allow-dirty` 없이는 멈춘다.
  - route 주석이 말하는 "자산 무결성 해시"(`contractHealth.ts`)는 **계약서 서비스 자산 26개**용이다. `product/prompts`는 그 대상이 아니다(확인함).
- 정책 문장 보호: `promptLoader.test.ts`의 "빠지면 안 되는 정책 문장" 목록 — **테스트에만** 있어 런타임 검증에는 못 쓴다.

### 1.2 배치

- 최신 배치 규칙: `server/latestBatchSql.ts`의 `WHERE as_of_date IS NOT NULL ORDER BY as_of_date DESC, ingested_at DESC, id DESC LIMIT 1` + DB 뷰 `v_current_batch`. 규칙 문자열은 CI와 드리프트 검사가 문자 그대로 단언한다 → **ORDER BY는 유지하고 WHERE만 넓힌다**(배치 설계서 §3).
- 배치 설계서 Phase 0(readiness 하드코딩 제거)·Phase 1(배치 현황 화면 `/inspector/batches`, `/api/admin/batches`)은 구현됨.
- Phase 2(전환)는 **미구현**. 설계서의 `0010_batch_activation.sql`은 번호가 이미 다른 migration에 쓰였으므로 **`0021_*`로 새로 낸다**.
- 산업재해는 `industrial_safety.pipeline_runs.is_current`가 이미 있어 별도다. 이번 범위는 **임금체불 월 배치만**.

## 2. 공통 쓰기 경로 — `wg_ops`

```text
브라우저(admin) ─POST─▶ Next.js API ─(CSRF·세션·role=admin·사유 필수)─▶ server/postgresOps.ts
                                                                    │  함수 호출만 export
                                                                    ▼
                                         wg_ops ──EXECUTE──▶ SECURITY DEFINER 함수
                                                              ├ activate_batch / deactivate_batches
                                                              ├ save_prompt_draft / activate_prompt_version
                                                              └ deactivate_prompt (파일 기본값 복귀)
```

| 항목 | 설계 |
| --- | --- |
| DB 계정 | `create-ops-role.sh`: `REVOKE ALL` 후 위 함수 `EXECUTE`만 부여. 테이블 권한 0. CONNECTION LIMIT 2 |
| 앱 | `server/postgresOps.ts` 신규. 별도 Pool(`max: 2`). **범용 query 함수를 export하지 않는다** — 쓰기 경로가 코드상 함수 5개로 한정 |
| 설정 | `databaseConfig.getOpsConnectionString()`. `validate-service-envs.py`에 `OPS_DATABASE_URL` 허용 + 사용자 `wg_ops`·loopback 고정 검사 |
| 인증 | 실DB 인증에서만 켠다. Mock admin(비밀번호가 env로 공개)에서는 `OPS_NOT_AVAILABLE_IN_MOCK`로 막는다 |
| 이력 | 모든 함수가 `ops_audit_log(action, target, by_user_id, reason, before, after, at)`에 한 행을 남긴다 |

## 3. 프롬프트 편집

### 3.1 저장 방식 — "파일은 기본값, DB는 덮어쓰기"

파일을 고치지 않고 **DB에 버전을 저장**한다. 파일은 기본값이자 비상 복귀점으로 남는다.

```sql
-- 0021_ops_console.sql (초안)
CREATE TABLE prompt_versions (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name        text NOT NULL CHECK (name IN ('chat/system','inspector/system','rewrite/system')),
  version     integer NOT NULL,
  body        text NOT NULL CHECK (char_length(body) BETWEEN 1 AND 20000),
  body_sha256 text NOT NULL,
  status      text NOT NULL CHECK (status IN ('draft','active','retired')),
  validation  jsonb NOT NULL,              -- 정책 문장·금지 패턴 검사 결과
  trial       jsonb,                       -- 시험 실행 요약(통과 수·실패 사례 ID)
  reason      text NOT NULL,
  created_by  uuid NOT NULL REFERENCES users(id),
  created_at  timestamptz NOT NULL DEFAULT now(),
  UNIQUE (name, version)
);
CREATE UNIQUE INDEX prompt_versions_one_active ON prompt_versions(name) WHERE status = 'active';
```

- 로더: `loadPrompt(name)` = **활성 DB 버전 → 없으면 파일**. 30초 캐시. DB 조회 실패 시 파일로 떨어지고 경고 로그.
- 파일을 바꾼 PR이 머지되면? 활성 DB 버전이 있으면 DB가 이긴다 → 화면에 "파일 기본값과 다름" 배지를 보여 준다.

### 3.2 적용 전 검증 (서버에서 강제)

1. **정책 문장**: 테스트에만 있던 목록을 `server/promptPolicy.ts`로 옮겨 테스트와 런타임이 같은 목록을 쓴다. 하나라도 빠지면 적용 불가.
2. **금지 패턴**: API 키 형태, URL·접속 문자열, 내부 필드명(`risk_full`, `risk_tier`, `shap` 등), 20,000자 초과.
3. **형식**: 마크다운 머리말·코드 블록 금지(README 규칙과 동일).
4. **시험 실행**(선택 → 권장): 초안으로 답변 계약 평가 일부(AQ 사례 10개)를 돌려 PASS 수와 가드레일 결과를 보여 준다. 호출 수 상한(예: 1회 20호출)으로 비용을 묶는다. **PASS가 기존 활성 버전보다 줄면 경고**.

### 3.3 화면 (`/inspector/prompts` 확장)

편집 → [검증] → [초안 저장] → [시험 실행] → 사유 입력 → [적용]. 이력 탭에서 버전별 diff와 [이 버전으로 되돌리기], [파일 기본값으로 복귀].

| 메서드 | 경로 | 권한 |

## 4. ML 대시보드 배치 전환

배치 설계서 §8을 그대로 따르되 아래만 바꾼다.

| 항목 | 배치 설계서 | 이번 설계 |
| --- | --- | --- |
| migration | `0010_batch_activation.sql` | `0021_ops_console.sql`에 프롬프트 테이블과 함께 |
| 이력 | `batch_activations` | 공통 `ops_audit_log` |
| 규칙 | `WHERE` 확장 | 동일: 활성 배치가 있으면 그것, 없으면 기존 규칙(ORDER BY 불변) |
| 순서 | 2a CLI → 2b 화면 | 동일. 2a(`activate-batch.sh`)만으로 되돌리기가 먼저 가능 |

화면(`/inspector/batches`, `/inspector/ml-dashboard`)에 추가할 것:

1. **서비스 중 배치 표시**: "자동(최신 규칙)" / "고정(운영자 지정, 사유·지정자·시각)".
2. **후보 배치와 비교**: 배치 설계서 §7 지표 — 상위 100 겹침, 순위 상관, 등급 분포 변화, 사유 상위 10 변화. 기준선 띠(§7.7) 밖이면 빨간 표시.
3. **전환 / 자동 규칙 복귀** 버튼 + 사유 모달. 전환 직후 비교 화면을 자동으로 연다.
4. `ingest.sh`는 **활성 배치를 덮어쓰지 않는다**(배치 설계서 §8.5).

## 5. 배포와 순서

1. **팀 합의**(§6 D1) — 안 되면 §2의 웹 쓰기 경로를 빼고 CLI(2a)만 한다.
2. `0021_ops_console.sql` + `create-ops-role.sh` + 드리프트 후조건 → **관문 경로**(`db/migrations/`, `infra/scripts/`)라 수동 배포: 덤프 → `npm run migrate` → 롤 생성 → `--ack-guarded`.
3. `web.env`에 `OPS_DATABASE_URL` 추가(검증기 갱신 PR이 먼저 배포돼야 한다).
4. 기능 플래그 없이 **설정 유무로 켠다**: 키가 없으면 버튼·API가 없다.
5. 롤백: `web.env`에서 키 삭제 → 웹 재시작이면 기능이 사라진다. DB 테이블은 남아도 무해.
