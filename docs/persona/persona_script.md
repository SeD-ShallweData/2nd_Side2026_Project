# Co끼리 페르소나 및 앱 사용 흐름

# 시스템 권한 및 공통 원칙

* DB의 **role 컬럼은 삭제**되고 **auth\_role 하나만 남습니다**(일반 사용자 / 감독관 / 관리자)
* firm\_id는 "일반 사용자" 계정에 선택적으로 연결되는 별도 컬럼이며, **role과 무관하게 firm\_id 유무만으로** 화면이 갈립니다
* 비로그인(공통): 사업장 검색, 신호 카드 열람, AI 상담, 근로계약서 업로드 및 검토 (DB 저장 없이 즉시 휘발)
* 로그인(공통): 커뮤니티 글쓰기, 댓글(현재 미제공), 리뷰 작성, 신고, 피드백 제출
* 로그인 실패 5회 연속 시 15분 잠금, **서버 메모리에 저장** — 서버 재시작 시 잠금이 초기화되는 것은 의도된 동작

## 랜딩 분기 (확정 — 기준은 firm\_id 유무 하나뿐)

|auth\_role|firm\_id|랜딩 화면|
|-|-|-|
|일반 사용자|없음|사업장 검색|
|일반 사용자|있음|내 사업장 게시글·리뷰 조회|
|감독관|-|별도 2차 인증 → 감독관 대시보드|
|관리자|-|신고 관리 화면|

> role 값은 더 이상 보지 않습니다. firm\\\_id 컬럼이 비어 있는지만 확인해서 위 두 "일반 사용자" 행 중 하나로 갑니다.

## firm\_id 연결

* 회원가입 또는 설정 화면에서 **사용자 본인이 직접 회사를 골라 연결**합니다(회원가입 화면은 지유 담당)
* 실제로 그 회사 직원·대표인지 확인하는 절차는 **이번 시연 범위에 없음** — 화면에 "검증 없음" 문구가 노출됩니다
* 감독관·관리자가 승인하는 흐름은 없습니다

## 1\. 사용자 (일반 사용자) — 김도전 (28세)

> firm\\\_id 유무에 따라 같은 계정이 두 시나리오를 오갑니다. 분기 기준은 firm\\\_id 유무 하나뿐입니다.

**핵심 고충:** 회사에 대한 정보를 확인할 방법이 마땅치 않거나(구직·재직 시), 반대로 근거 없는 신호로 자기 사업장이 낙인찍히는 걸 걱정함(사업장 연결 시).

### 시나리오 A — firm\_id 없음

1. 검색창에 회사명 입력 → 동명 사업장 있을 경우 지역·업종으로 후보 구분
2. 위험 카드 확인: 체불 위험 / 산재 위험 / 데이터 신뢰도를 분리 확인(합산 점수 없음)
3. 지역·업종 커뮤니티 게시판에서 같은 업종 종사자 경험 확인 (열람은 비로그인, 글쓰기는 로그인)
4. AI 상담: "이 정도면 정상인가요?", "월급이 밀리면 어떻게 하나요?"
5. 근로계약서 업로드 → 규칙 엔진 검토 (로그인 불필요, 공통 기능)
6. 최종 판단은 스스로, 필요 시 게시판에 질문 남김 (로그인 필요)

### 시나리오 B — firm\_id 있음

1. 회원가입/설정에서 본인이 직접 회사를 선택해 firm\_id 연결 (검증 없음, 승인 절차 없음)
2. 로그인 후 "내 사업장 게시글·리뷰" 화면으로 자동 랜딩 (firm\_id 유무만으로 결정)
3. 본인 사업장의 신호 카드·데이터 출처·게시글·리뷰 열람
4. 부정확한 게시물에 신고 기능 사용
5. AI 상담으로 관련 법령·의무사항 확인
6. 신호는 확인 신호일 뿐, 실제 대응은 본인 몫임을 UI로 재확인

## 2\. 감독관 — 박감독 (34세)

> auth\\\_role='감독관'. 로그인 + 별도 2차 인증 통과 시에만 진입 가능한 전용 대시보드. (변경 없음)

**핵심 고충:** 흩어져 있는 산재·체불 데이터를 취합·비교하는 데 시간이 오래 걸림.

**사용 동선**

1. 로그인 + 2차 인증 → 감독관 대시보드 진입
2. 지역·업종 필터로 관할 사업장 목록 일괄 조회
3. 위험 큐(top 3,000)와 SHAP 근거·G1\~G6 지표로 우선순위 정렬
4. 신호 높은 사업장의 근거 데이터 상세보기, 커뮤니티 제보는 참고용으로만 교차 확인
5. AI 점검 보조로 현장 확인 항목 정리
6. "신호는 단서, 최종 판정은 감독관 권한" 원칙 유지 — 원점수는 항상 "확률 아님"으로 표기

## 3\. 관리자 — 최운영 (30대)

> auth\\\_role='관리자'. 이번 시연 범위에서 신고 처리 기능이 확정됐습니다.

**핵심 고충:** 커뮤니티에 신고된 게시글을 빠르게 확인하고 처리해야 하는데, 처리 기준이 없으면 대응이 늦어짐.

**사용 동선 (확정 범위)**

1. 로그인 후 신고 관리 화면으로 진입
2. 신고 접수된 게시글 목록 확인 (신고 상태값: 대기(pending) 등)
3. 게시글 내용을 확인하고 **숨김(hidden) 처리** — 이번 시연 범위는 여기까지
4. (범위 밖, 별도 초안 진행 중) 신고 누적 임계치에 따른 자동 숨김, 경고/삭제/정지 등 조치 단계
5. (범위 밖, 나연 회신 대기) 기각된 신고를 다시 신고할 수 있는지 여부

> 🔶 4, 5번은 이번 PR 이후 별도로 초안을 만들어 나연(DB 상태값)·민규(API)에게 전달할 예정입니다.
