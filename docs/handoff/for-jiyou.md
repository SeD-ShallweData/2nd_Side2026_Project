# 지유에게 전달할 사항

작성·관리: 민규(API) · 최종 갱신 2026-09-04

인증·커뮤니티·신고 API를 Mock에서 실제 DB로 연결하는 작업에서 지유에게 알리거나
요청해야 하는 것을 모으는 문서다. 작업이 진행되면서 계속 갱신한다.

관련 문서
- 나연 전달 사항: [`for-nayeon.md`](./for-nayeon.md)

## 가장 중요한 약속

**주고받는 데이터 형태는 바꾸지 않는다.**

지유의 커뮤니티 클라이언트는 민규가 만든 타입 계약을 그대로 가져다 쓰고,
그 위에 테스트 683줄이 얹혀 있다. 이번 작업은 겉모습은 그대로 두고 속만
Mock에서 실제 DB로 갈아끼우는 것이다.

**지유 코드와 테스트가 손대지 않고 그대로 통과하는 것이 이번 작업의 성공 기준이다.**
아래 항목들은 그 약속의 예외이거나, 화면에서 눈에 보이게 달라지는 것들이다.

## J1. 환경설정 파일에 항목이 늘었습니다

**구분: 조치 요청 (지금 바로)**

`product/.env.example`에 기능별 모드 설정 세 줄과 임시 로그인 비밀번호 세 줄을 추가했다.
**본인 `.env.local`에도 반영해야 한다.**

추가한 이유가 중요하다. 지금까지 예시 파일에는 전체 모드만 있고 기능별 설정이 없었다.
그래서 예시 파일을 그대로 복사하면 **로그인·커뮤니티·제보가 전부 오류를 낸다.**
지금까지는 각자 알아서 수동으로 맞춰 쓰고 있었을 것이다.

이제 세 기능의 모드가 파일에 명시돼 있고, 각 줄에 지우면 왜 깨지는지 주석이 달려 있다.

나중에 실제 DB 연결이 끝나면 인증·커뮤니티 두 줄을 실제 모드로 바꾸게 된다.
그때 다시 알리겠다.

## J2. 회원가입 화면이 필요합니다

**구분: 요청 (이번 작업에서 새로 생긴 것)**

실제 DB에는 회원이 0건인데 회원가입 기능이 없어서, 그대로 전환하면 아무도 로그인할 수 없다.
민규가 회원가입 API를 만들기로 했고, 그러면 **가입 화면이 필요해진다.**

지금까지 "지유 무영향"을 목표로 했는데 여기서 처음으로 지유 작업이 생긴다.
미리 알리는 이유는 병렬로 진행할 수 있게 하기 위해서다.

화면에서 받아야 하는 값

- 이메일, 비밀번호
- 이름
- 직업 구분 — 구직자 / 재직 근로자 / 기업·노무 담당자 / 사업주 / 감독관 중 하나 (필수)
- 사업장 연결 — **사업주 또는 기업·노무 담당자로 가입할 때만** 노출

권한 등급(일반·관리자·감독관)은 화면에서 받지 않는다. 가입은 무조건 일반 사용자로 고정된다.

API 규격이 확정되면 이 문서에 추가하겠다.

## J3. 예시 게시글 4건이 사라집니다

**구분: 알림**

지금 커뮤니티 목록에 보이는 게시글 4건은 Mock 저장소에 손으로 넣어둔 값이다.
실제 DB의 게시글은 0건이라 **전환 직후 목록이 비어 보인다.**

확인하고 싶은 것

- 빈 목록 화면이 정상적으로 나오나?
- 발표·시연용으로 예시 글이 필요한가? 필요하면 몇 건 정도?

## J4. 지금 쓰던 로그인 계정이 안 먹습니다

**구분: 알림**

`user@mock.donworry.local` 등 임시 계정 3종은 Mock 전용이라 실제 DB에서는 동작하지 않는다.

회원가입 기능이 생기면 직접 가입해서 쓰면 되고, 감독관 계정처럼 가입으로 못 만드는 것은
민규가 별도로 만들어 전달하겠다.

## J5. 데이터 출처 표시값이 바뀝니다

**구분: 확인 요청**

응답에 담기는 출처 표시가 임시 저장소에서 실제 DB를 뜻하는 값으로 바뀐다.
값 자체는 원래 계약에 정의돼 있던 것이라 타입이 깨지지는 않는다.

**확인**: 이 값을 보고 화면을 다르게 그리거나 분기하는 코드가 있나?

## J6. 사업장 식별값 형식이 바뀝니다

**구분: 확인 요청 (조심할 부분)**

게시글에 연결하는 사업장 식별값이 Mock 전용 값에서 실제 사업장 식별값으로 바뀐다.
형식 자체가 다르다.

그래서 **사업장 검색 기능과 커뮤니티가 반드시 같은 모드로 함께 전환돼야 한다.**
한쪽만 실제 모드가 되면 게시글의 사업장 연결이 전부 깨진다.

**확인**: 사업장 식별값을 화면 코드에 직접 적어둔 곳이 있나? 있다면 알려주면 좋겠다.

## J7. 새 오류 상황이 생길 수 있습니다

**구분: 알림 (생기면 갱신)**

실제 DB에는 Mock에 없던 제약이 걸려 있다. 예를 들어 같은 사람이 같은 글을 중복 신고하면
DB가 막는다. 이런 상황을 사용자가 이해할 수 있는 안내로 바꾸는 것은 민규 쪽 일이지만,
**화면에서 새로 처리해야 하는 오류가 생기면 이 문서에 추가하고 알리겠다.**

현재까지 확정된 것: 없음.

## J8. 좋아요는 계속 비어 있습니다

**구분: 알림 (조치 불필요)**

확인해 보니 좋아요는 누를 수 있는 기능이 아예 없다. 화면에 숫자만 보이는데 그것도
Mock에 손으로 적어넣은 값이고, 새 글은 0으로 고정이다. DB에도 좋아요 테이블이 없다.

실제 DB로 가면 이 값은 계속 비어 있게 된다.
**지유 화면이 이미 대비돼 있는 것을 확인했다** — 값이 비어 있으면 공감 표시 자체를 감추게
되어 있어서 따로 고칠 것이 없다.

좋아요 기능을 실제로 만들려면 DB 테이블과 API가 새로 필요하다. 이번 범위 밖이다.

## J9. 로그인 화면이 아예 없습니다

**구분: 확인 요청 (2026-09-04 확인)**

로컬에서 앱을 직접 띄워 확인해 보니, **로그인 화면과 로그인 버튼이 어디에도 없었다.**

- 상단 메뉴는 소개·사업장·계약서·커뮤니티·AI 상담 다섯 개뿐이다
- 로그인을 위한 페이지 경로가 없다
- 글쓰기 화면은 비로그인일 때 "로그인이 필요합니다"라고만 하고 데려갈 곳이 없다

로그인 API는 민규가 만들어 둔 상태라 서버 쪽은 준비되어 있다. 화면만 없다.

**확인**: 지금까지 로그인은 어떻게 테스트했나? 다른 곳에 화면이 있는데 내가 못 찾은 것이면 알려주면 좋겠다.

**없다면**: J2의 회원가입 화면과 함께 **로그인 화면도 필요하다.** 실제 DB로 전환하면
임시 계정이 없어지므로, 로그인 화면이 없으면 **글쓰기·신고 기능을 아무도 쓸 수 없다.**
회원가입보다 이쪽이 더 급할 수 있다.
