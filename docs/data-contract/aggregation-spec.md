# 지역·업종 집계 정의

> 지역별·업종별 통계 화면이 **무엇을 어떤 분모로 세는지** 정한다.
> 집계 뷰·API·화면은 이 문서를 기준으로 만든다.

- 버전 `v1.0` · 2026-09-09
- 기준 배치 `as_of_date = 2026-06-01` · `target_month = 2026-12-01`
- 모든 수치는 **운영 DB 실측** [2026-09-09 13:0x~13:3x KST]
- 표현 정책 정본은 `product/docs/service-policy.md` (POL-01~POL-14). 여기서 중복 정의하지 않는다

---

## 0. 세 줄 요약

```
1. 탭이 둘이고 분모도 둘이다.  임금체불 553,598  ·  산업재해 515,608
2. 임금체불 표시는 4단계. review 를 빼면 합이 100% 가 되지 않는다
3. 사업장 30곳 미만 칸은 숨긴다. 한 곳짜리 칸이 39개 있다
```

- **임금체불 탭** — §1 ~ §7
- **산업재해 탭** — §8 (분모·축·등급이 전부 다르다)

> 🔴 **모집단을 503,887 로 잡으면 안 되는 이유**
> 판정이 없는 49,711곳도 **개별 조회 화면에서는 `unknown` 으로 정상 표시된다** [실측].
> 집계에서 빼면 「자료 부족」이 **12.15% → 3.48%** 로 줄어, 클릭해 들어가면 나오는 회사가
> 집계에는 없는 상태가 된다. 설계 원칙 4번 위반이다.

## 1. 🔴 모집단 4종 — 섞으면 안 된다

프로젝트에 크기가 다른 집계 대상이 **넷** 있다. 지금 화면 설계가 두 개를 섞고 있다.

| 모집단 | 곳 | 출처 | 무엇인가 | 이 화면 |
| --- | ---: | --- | --- | :-: |
| **채점 대상 전체** | **553,598** | `v_current_scored` | 최신 배치가 다룬 사업장 전체 | ✅ **분모** |
| 판정 있음 | 503,887 | `v_current_safe` | 그중 판정이 붙은 곳 | 부분집합 |
| 감독관 큐 | 3,000 | `inspector_queue` | 점검 우선순위 상위 | ❌ |
| 산업재해 | 515,608 | `industrial_safety.firm_risk_results` | 별도 축 (아래 §1.3) | ❌ 별도 카드 |

> ⚠️ **`v_current_scored` 를 모집단으로 쓰지만 `risk_tier` 는 쓰지 않는다.**
> 이 뷰에서 가져오는 것은 **사업장 목록과 `industry_category` 뿐**이다.
> 등급은 `safe_recommendation.판정` 에서만 온다. `risk_tier` 는 감독관 전용이다(§6).

### 1.1 이 화면이 쓰는 모집단은 **553,598 하나뿐이다**

```
v_current_scored   553,598     ← 채택. 최신 배치의 채점 대상 전체
v_current_safe     503,887     ← 판정이 붙은 곳만. 이걸 분모로 쓰면 안 된다
────────────────────────────
차이                49,711     ← 채점 자체가 불가능한 곳
```

### 🔴 49,711곳을 빼면 안 된다

이 곳들은 **판정이 없을 뿐 화면에서 사라지지 않는다.** 실제 API 응답이다.

```json
"company_name": "(주)지앤지엔지니어링",
"wage_risk": { "availability": "ready", "level": "unknown",
               "confidence": "unavailable" }
```

**개별 조회에서는 `unknown` 으로 정상 표시된다.** 집계에서만 빼면 두 화면이 어긋난다.

이 49,711곳은 **세 조건이 모두 같은 집합**이다 [실측, 차집합 양쪽 0].

```
risk_full IS NULL          49,711
industry_category IS NULL  49,711
n_months < 6               49,711 중 전부 포함
```

내역은 감독관 등급 기준 `정보부족` 49,703 + `이미공개` 8 이다.
**판정이 없을 뿐이므로 `unknown` 으로 집계한다.**

> 🔴 **분모 혼용이 실제로 일어나고 있다.**
> `docs/ui-spec/dashboard_spec.md` 의 KPI 카드가 `553,598곳` 옆에
> `normal 6.5% / watch 85.7% / unknown 3.5%` 를 붙여 놓았다.
> 이 백분율은 **503,887 기준**이다. 두 수를 나란히 두면 49,711곳만큼 어긋난다.

### 1.2 큐 3,000 은 이 API에 넣지 않는다

`inspector_queue` 는 감독관 전용이다. DB 주석에 명시돼 있다.

> `risk_tier` — 감독관 전용, **구직자 화면에 노출 금지(명예훼손 리스크)**

지역·업종 통계는 **사용자 화면**이므로 큐를 같은 응답에 담지 않는다.

### 1.3 산업재해는 **다른 축이다. 분모도 따로 정의한다 → §8**

| | 임금체불 | 산업재해 |
| --- | --- | --- |
| 테이블 | `v_current_scored` + `v_current_safe` | `industrial_safety.v_llm_firm_safety_context` |
| 분모 | **553,598** | **515,608** |
| 시간 단위 | **월** 배치 | **주(週)** |
| 예측 대상 | 2026-12 (미래) | 2026-04-20~26 (**이미 지남**) |
| 값 | 판정 6종 → 표시 4단계 | 밴드 4종 (일반/상위10%/상위5%/상위1%) |
| 교집합 | \- | 471,869 (산재에만 43,739) |

**예측 시점이 약 8개월 어긋나 있어 같은 분모로 셀 수 없다.** 설계 원칙 2번(합산 금지)과 별개 문제다.
탭을 분리하고 **뷰도 따로 만든다.** (현재 화면 설계의 「※ 합산 금지」 표기는 맞다)

> 🔴 **「합산 금지」가 「정의하지 않음」을 뜻하지 않는다.**
> 산업재해 탭도 지역·업종별 집계를 하려면 자기 분모·축 정의가 필요하다. **§8이 그것이다.**

## 2. 🔴 표시 등급은 4단계다

`판정` 6종을 화면 4단계로 접는다. 매핑 정본은 `MlRiskProvider.ts` 의 `VERDICT_META`.

| 표시 | 판정 | 곳 | 비중 | 문구 (2026-09-08 결정) |
| --- | --- | ---: | ---: | --- |
| `normal` | `안정신호` | 32,613 | 5.89% | 뚜렷한 이상 신호 없음 |
| `watch` | `유보` | 431,646 | **77.97%** | **안전 신호 미확인** ⚪ 회색 |
| **`unknown`** | **`유보_정보부족` + 판정 없음** | **67,241** | **12.15%** | 분석 자료 부족 |
| `review` | `배제_*` 3종 | 22,098 | 3.99% | 우선 확인 필요 |
| | | **553,598** | **100.00%** | |

`unknown` 내역 — `유보_정보부족` 17,530 + 판정 없음 49,711 = **67,241** [실측].
**개별 조회 화면에서 둘 다 `unknown` 으로 보이므로 집계도 같이 센다.**

> 🟡 판정 있는 503,887만 세면 `unknown` 이 **3.48%** 로 나온다. 실제의 약 4분의 1이다.

### 🔴 `review` 를 빼면 안 되는 이유

현재 화면 설계는 `normal`·`watch`·`unknown` 셋만 그린다. **합이 95.61% 다.**

더 중요한 문제는 **업종 순위가 뒤집힌다**는 것이다.

```
watch 로 줄 세우면        건설업 76.9%  →  19개 업종 중 하위권
review 로 줄 세우면       건설업 12.3%  →  1위 (2위의 약 2배)
```

**`review` 는 「공개 명단에 실제로 오른 곳」이다.** 모델 예측이 아니라 공표된 사실이며,
사용자가 가장 알아야 할 정보다. 빼면 건설업이 평범해 보인다.

### 표현 금지

- `watch` 에 **노랑·주황·빨강 금지**. 회색만 쓴다 (사업장 85% 이상이 이 상태)
- 「추가 확인 권장」·「주의」·「발견」 류 표현 금지 (2026-09-08 결정으로 폐기)
- `unknown` 에 초록·긍정 아이콘 금지. 자료 부족은 안전이 아니다

## 3. 업종 축

### 3.1 `industry_category` 를 쓴다. `firms.industry` 원문은 쓰지 않는다

| 컬럼 | 종수 | 「건설업」 | 판단 |
| --- | ---: | :-: | --- |
| `scored_active.industry_category` | 20 (+NULL) | ✅ | **채택** |
| `firms.industry` | 1,234 | ❌ 없음 | 드롭다운 불가 |

`firms.industry` 는 `아파트 건설업`·`도로 건설업` 처럼 잘게 쪼개져 있어 「건설업」이 없다.
그리고 **대분류로 되돌릴 수 없다** [실측].

```
원문 1,225종 중
  대분류 1개로 결정   1,200종  (97.96%)
  대분류가 갈림          25종  ← 결정론적 매핑 불가
```

### 3.2 실제 업종은 **18종**이다

`industry_category` 20종 중 2종(`BIZ_NO_MISSING`·`UNKNOWN`)은 업종이 아니다.

```
건설업 · 광업 · 교육서비스업 · 금융 및 보험업 · 농업, 임업 및 어업
도매 및 소매업 · 보건업 및 사회복지 서비스업 · 부동산업
사업시설관리, 사업지원 및 임대 서비스업 · 수도, 하수 및 폐기물처리, 원료재생업
숙박 및 음식점업 · 예술, 스포츠 및 여가관련 서비스업 · 운수 및 창고업
전기, 가스, 증기 및 공기조절 공급업 · 전문과학기술서비스업 · 정보통신업
제조업 · 협회 및 단체, 수리 및 기타 개인서비스업
```

### 3.3 🔴 비업종 값은 **「업종 미상」 한 칸으로 묶는다. 빼지 않는다**

**실측** [분모 553,598]

```
BIZ_NO_MISSING    사업자번호 없음     75,099
NULL              값 자체가 없음      49,711
UNKNOWN           미상                 8,628
──────────────────────────────────────────
합계                                133,438곳   전체의 24.1%
```

**「업종 미상」이 가장 큰 칸이다.** 제조업(93,686)보다 많다.

> 🔴 **모집단에 따라 미상 비율이 1.5배 달라진다.** 이것이 이 문서가 필요한 이유다.
> ```
> 553,598 기준   비업종 133,438곳 = 24.1%   ← 이 화면이 쓰는 값
> 503,887 기준   비업종  83,727곳 = 16.6%   (NULL 49,711 이 빠져서)
> ```
> **`industry_category` 가 NULL 인 곳과 판정이 없는 곳은 같은 집합**이므로,
> 판정 모집단만 쓰면 업종 미상이 조용히 줄어든다.

**드롭다운에 `BIZ_NO_MISSING` 을 그대로 노출하지 않는다.** 「업종 미상」으로 표시한다.

**통계에서 제외하지 않는다.** 133,438곳은 **19칸 중 가장 큰 칸**이며 제조업(93,686)보다 많다.
빼면 분모가 조용히 줄어 다른 업종 비율이 왜곡되고, `unknown` 의 대부분이 사라진다.

### 3.4 🟡 `보건업 및 사회복지 서비스업` 이 61곳뿐이다

전체 19칸 중 유일하게 세 자리 미만이다. 실제 보건·복지 사업장 수와 크게 다르다.
**원인 미확인.** 드롭다운에 남기되 이 칸만 별도 확인이 필요하다. §9에 올려 둔다.

## 4. 지역 축

### 4.1 🔴 `firms.sido` 를 쓴다. `scored_active.sido_code` 가 아니다

| 컬럼 | 결측 (판정 모집단) | 판단 |
| --- | ---: | --- |
| `scored_active.sido_code` | NULL 49,711 | 코드라 표시 불가 |
| **`firms.sido`** | **169곳 (0.031%)** | **채택** |

`firm_id` 로 조인하며 **조인 손실은 0건**이다 [실측 553,598 → 553,598 전부 매칭].
코드↔이름 **다중 매핑도 0건**이다.

> `sido_code` 는 모델 피처라 TEXT 유지가 필요하다(정수로 바꾸면 모델이 범주로 인식하지 못한다).
> 표시에는 이름이 필요하므로 `firms.sido` 를 쓴다. **`sido_code` 를 화면에 내보내지 않는다.**

### 4.2 🟡 코드 체계가 섞여 있다

| 값 | 사업장 | 비고 |
| --- | ---: | --- |
| `전남광주통합특별시` | 30,733 | 🔴 **표준 시도가 아님** |
| `강원특별자치도` | 13,371 | 신 명칭 |
| `전북특별자치도` | 16,128 | 신 명칭 |
| `강원도` | **6** | 구 명칭 잔재 |
| `전라북도` | **18** | 구 명칭 잔재 |

**드롭다운에 `강원도`와 `강원특별자치도`가 같이 뜬다.** 잔재는 24곳으로 작지만
사용자에게는 중복 항목으로 보인다.

- 표시 시 **구 명칭을 신 명칭으로 합친다** (`강원도` → `강원특별자치도`, `전라북도` → `전북특별자치도`)
- `전남광주통합특별시` 는 광주·전남이 합쳐진 값으로 보이나 **확인되지 않았다.** §9 참조

### 4.3 결측은 「지역 미상」

169곳(0.031%). 업종과 같은 원칙으로 **한 칸으로 묶되 빼지 않는다.**

## 5. 🔴 최소 칸 크기 — 낙인 방지

지역 × 업종 조합은 **321칸**이다. 그 안에 아주 작은 칸이 있다.

```
     1~9곳    39칸        137곳
   10~29곳    24칸        487곳
   30~99곳    29칸      1,617곳
 100~999곳   136칸     56,174곳
   1000곳~    93칸    495,183곳
 ─────────────────────────────
             321칸    553,598곳
```

**사업장이 1곳뿐인 칸이 여럿 있다.**

```
제주특별자치도 × 보건업 및 사회복지 서비스업     1곳
울산광역시     × 광업                            1곳
강원도         × 제조업                          1곳
```

이 칸에 「watch 100%」가 뜨면 **특정 사업장 한 곳을 지목한 것과 같다.**
설계 원칙 1번(판정하지 않는다)과 낙인 방지에 정면으로 걸린다.

### 규칙

```
사업장 30곳 미만 칸은 비율을 표시하지 않는다.
   대신 「표본이 적어 표시하지 않습니다」로 대체한다.
   총 사업장 수는 표시해도 된다.
```

- 억제 대상: **63칸 · 624곳** — 전체의 **0.11%**
- 잃는 정보는 거의 없고, 얻는 보호는 크다
- 억제된 칸도 **상위 합계에는 포함**한다 (지역 합계·업종 합계·전체 합계)

## 6. 화면에 내보내면 안 되는 값

| 금지 | 이유 |
| --- | --- |
| `risk_full` | **확률이 아니다.** 1:1 다운샘플링 값. 순위로만 해석 |
| `risk_calibrated` | 전 행 NULL |
| 순위 · 백분위 | 순위 노출은 사실상 등급 부여 |
| **`risk_tier` 6종** | 감독관 전용. DB 주석에 노출 금지 명시 |
| SHAP `shap_value` 원값 | POL-03 금지 목록 |
| `inspector_queue` 전체 | 감독관 전용 |
| `sido_code` · `industry_category` 원값 | 코드값. 이름으로 변환해 표시 |
| `firm_id` · `biz_no` | 집계 화면에 개별 식별자를 두지 않는다 |

> `biz_no` 는 마스킹 6자리이며 **고유하지 않다** — 최대 950곳이 같은 값을 쓴다.

## 7. 집계 SQL — 운영 DB에서 검증됨

아래는 **실제로 실행해 확인한 쿼리**다 [2026-09-09 13:3x KST].
이대로 뷰로 만들면 된다.

### 7.1 기준 집합

```sql
SELECT
  COALESCE(NULLIF(f.sido, ''), '지역 미상')                       AS sido,
  CASE WHEN s.industry_category ~ '업$' THEN s.industry_category
       ELSE '업종 미상' END                                       AS industry,
  CASE
    WHEN v.판정 = '안정신호'   THEN 'normal'
    WHEN v.판정 = '유보'       THEN 'watch'
    WHEN v.판정 LIKE '배제%'   THEN 'review'
    ELSE 'unknown'          -- 유보_정보부족 + 판정 자체가 없는 곳
  END                                                             AS signal_level
FROM v_current_scored s
LEFT JOIN v_current_safe v USING (firm_id, batch_id)   -- ← LEFT. 판정 없는 곳도 남긴다
JOIN public.firms       f USING (firm_id)
```

> 🔴 **`LEFT JOIN` 이어야 한다.** 안쪽 조인을 쓰면 판정이 없는 49,711곳이 사라져
> 모집단이 503,887 로 줄고, `unknown` 이 실제의 4분의 1로 축소된다.
>
> `industry_category ~ '업$'` 로 실업종 18종을 가려낸다.
> `BIZ_NO_MISSING`·`UNKNOWN`·`NULL` 은 「업종 미상」으로 떨어진다.
> `ELSE 'unknown'` 이 받는 것은 `유보_정보부족` 과 **판정이 없는 곳** 둘이다 —
> 개별 조회 화면에서 둘 다 `unknown` 으로 보이므로 집계도 같아야 한다.

### 7.2 집계 뷰 (제안)

```sql
CREATE OR REPLACE VIEW public.v_region_industry_signal AS
WITH base AS (
  SELECT
    COALESCE(NULLIF(f.sido, ''), '지역 미상')                       AS sido,
    CASE WHEN s.industry_category ~ '업$' THEN s.industry_category
         ELSE '업종 미상' END                                       AS industry,
    CASE
      WHEN v.판정 = '안정신호' THEN 'normal'
      WHEN v.판정 = '유보'     THEN 'watch'
      WHEN v.판정 LIKE '배제%' THEN 'review'
      ELSE 'unknown'
    END                                                             AS signal_level
  FROM v_current_scored s
  LEFT JOIN v_current_safe v USING (firm_id, batch_id)
  JOIN public.firms       f USING (firm_id)
)
SELECT
  sido,
  industry,
  COUNT(*)                                            AS firm_count,
  COUNT(*) FILTER (WHERE signal_level = 'normal')      AS normal_count,
  COUNT(*) FILTER (WHERE signal_level = 'watch')       AS watch_count,
  COUNT(*) FILTER (WHERE signal_level = 'review')      AS review_count,
  COUNT(*) FILTER (WHERE signal_level = 'unknown')     AS unknown_count
FROM base
GROUP BY 1, 2;

COMMENT ON VIEW public.v_region_industry_signal IS
  '지역·업종별 표시등급 집계. 모집단은 최신 배치 채점 대상 553,598(v_current_scored). unknown 은 유보_정보부족과 판정 없음을 합친 값으로 개별 조회 화면과 같은 기준. 개별 사업장 점수·순위 없음';

GRANT SELECT ON public.v_region_industry_signal TO wg_bot;
```

**개수만 담고 비율은 담지 않는다.** 비율은 API에서 계산한다 —
그래야 최소 칸 규칙(§5)을 한 곳에서 적용할 수 있다.

## 8. 산업재해 탭 — 분모가 다르다

화면 설계에 탭이 둘이다. **각각 분모가 다르므로 따로 정의한다.**

```
신호 선택 탭:  [ 임금체불 확인 신호 뷰 ]  |  [ 산업재해 확인 우선순위 뷰 ]  (※ 합산 금지)
     분모 553,598                              분모 515,608
```

### 8.1 모집단

| 항목 | 값 |
| --- | --- |
| 분모 | **515,608** |
| 출처 | `industrial_safety.v_llm_firm_safety_context` |
| 등급 | `provisional_population_priority_band` 4종 |

> `industrial_safety.v_firm_accident_risk` 는 **0행**이다. 선행 데이터가 Path B 복원 범위 밖이라
> 비어 있는 것이며 결함이 아니다. **앱과 동일하게 `v_llm_firm_safety_context` 를 쓴다.**

### 8.2 🔴 임금체불과 같은 분모로 셀 수 없다

「합산 금지」이기 이전에 **애초에 같은 축이 아니다** [실측].

| | 임금체불 | 산업재해 |
| --- | --- | --- |
| 시간 단위 | **월** 배치 | **주(週)** |
| 관측 기준 | `as_of_date` 2026-06-01 | `prediction_as_of` 2026-04-19 |
| 예측 대상 | `target_month` 2026-12-01 (**미래**) | `target_week` 2026-04-20~26 (**이미 지남**) |
| 시점 상태 | 유효 | 전 행 `stale_target_week` |
| 매칭 | `firm_id` | 이름·마스킹사업자번호·시도·업종 **4개 일치** |

**예측 시점이 약 8개월 어긋나 있다.** 한 칸에 넣으면
「지난 주 기준」과 「반년 뒤 기준」을 같은 수로 읽게 된다.

모집단도 겹치지 않는다 [실측].

```
산업재해            515,608
임금체불 채점대상    553,598
교집합              471,869
산재에만 있음         43,739     ← 최신 임금 배치에 없는 곳
임금에만 있음         81,729
```

### 8.3 등급 4종 — 배타 구간이다

| 밴드 | 곳 | 비중 | 누적 |
| --- | ---: | ---: | ---: |
| `상위1%` | 5,161 | 1.00% | 1.00% |
| `상위5%` | 20,739 | 4.02% | 5.02% |
| `상위10%` | 25,690 | 4.98% | 10.00% |
| `일반` | 464,018 | 89.99% | 100% |
| | **515,608** | 100% | |

**`상위5%` 는 상위 1%를 뺀 1~5% 구간**이다. 겹치지 않는다.
이름이 누적 임계값을 가리키므로 화면에서 「상위 5%가 4%뿐」처럼 보이지 않게 한다.

### 8.4 🔴 밴드의 기준은 **전국 전체**다 — 필터링 시 오독 주의

DB 컬럼에 기준이 명시돼 있다 [실측, 전 행 동일].

```
priority_reference_population = all_scored_workplaces_national_not_similar_workplace_peers
                                「전국 전체 채점 사업장 기준. 유사 사업장군 대비가 아님」
population_tier               = nps_public_observed_population
```

**지역·업종으로 필터해도 밴드가 다시 계산되지 않는다.**

```
잘못된 읽기   "건설업 안에서 상위 1%인 곳"
올바른 읽기   "건설업 사업장 중, 전국 상위 1%에 드는 곳의 비율"
```

지역별로 실제 편차가 크다 [실측].

| 지역 | 사업장 | 상위1% | 상위5% | 상위10% | 일반 |

### 8.6 집계 SQL — 검증됨

```sql
SELECT
  COALESCE(NULLIF(a.sido, ''), '지역 미상')                       AS sido,
