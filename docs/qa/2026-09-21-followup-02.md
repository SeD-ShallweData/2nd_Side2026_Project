## 원인·수정·검증

### 확인한 원인

1. `hasUnverifiedCitation`은 검색된 인용인지 확인하지만 시간구간/상시 인원/신청 목적을 검증하지 않았다. 제56조 또는 제12조 검색 성공만으로는 적용 조건이 보존되지 않았다.
2. Dual의 RAG 실패와 가드 교체는 모두 일반적인 기록 정리 안내로 귀결되기 쉬웠다. 법률 오답을 막아도 사용자가 묻는 기준·절차를 잃었다.
3. `publicSignalForPrompt`은 일부 요약/label만 순위를 지웠다. disclaimer, policy baseline, limitations, history, Responses의 전체 risk 도구 응답은 별도 유입 경로였다. assistant digest는 `[이전 답변 근거: ...]`를 직접 만들어 전달했다.
4. 실제 합성 AQ20에서 회사 지표 분류가 개인 미지급 상담을 선점했다. 1차 자동 PASS였지만 최종 답변에 ‘과거 체불 기록이 없다는 뜻’이라는 오답이 남았다. 이를 근거로 라우팅·단정 검사를 수정했다.
5. 실제 모델은 일부 요구 조건을 여전히 생략했다. 야간 답변 검사에서 반대 규모의 모든 조건까지 요구하던 초기 버전은 과도하게 교체하므로 현재 질문의 규모/시간 조건에 맞게 좁혔다. 회사 근거만 있는 상태의 대지급금·진정 절차 생성도 별도 차단한다.

### 수정

- `reviewedLaborGuidance.ts`: 야간근로, 진정 채널, 확인서 쟁점에 검토일·출처를 가진 좁은 근거 묶음을 제공. 조문/범위/예외/절차가 함께 전달된다. `ragService`는 해당 쟁점에 `reviewed_applicability_bundle`을 반환하고 나머지 주제의 기존 벡터 검색은 유지한다. 이는 벡터 검색 성공이나 RAG 서버 복구가 아니다. trace의 `reviewed_evidence_count/as_of`도 구분한다.
- 명시적인 쟁점 및 실제 미지급 질문은 의도 분류 실패/회사 분류보다 노동 상담을 우선한다. 관련 근거 조회에는 원질문을 사용해 rewrite가 시간 조건을 바꾸지 못하게 한다.
- Dual/Responses 모두 적용 조건 누락 검사와 쟁점별 근거 있는 대체 답변을 사용한다. 모든 질문을 일반 fallback으로 보내지 않는다. 정상 조건을 충족한 모델 답변은 그대로 보존하는 회귀 검사 포함.
- 회사용 allowlist DTO를 공용화. 요약/면책/기본 답변/요약 메모리/이전 대화/도구 출력 사본의 순위·결측 라벨을 정리하고, 생성 결과의 재노출도 검사한다. 저장된 이력/원본 risk DTO는 수정하지 않는다. 숫자 `50%` 같은 법률 근거는 지우지 않는다.
- 긍정 지표의 체불 부재 추론을 금지하고, 실제 미지급 질문은 지표와 별개인 진정·기록 확인 경로로 다룬다. 일반 긍정 지표 설명도 ‘0개’에만 답하지 않도록 수정했다.
- AQ15~AQ22 합성 개발 계약 추가, AQ07의 split을 development로 정정했다. 기존 ID는 실행 호환을 위해 유지하나 이름에 independent가 남아 있어도 독립 평가로 집계하지 않는다. 사용한 사례로 수정했으므로 이번 결과를 독립 평가 성능으로 부르지 않는다.

### 회사 데이터 계약 대조

`domain/risk.ts`, `MlRiskProvider.toWageRiskPublic`, `riskService`, Dual prompt, Responses tool-output 직렬화를 대조했다.

- 공개 긍정 신호는 고용 안정·성실 납부·인건비 안정·인력 유지·업력·변동성의 6항목이다. 배치 일치, boolean 6개, 집계 개수 일치 조건을 통과해야 확인 개수가 제공되며, 불일치/부족이면 null/unavailable이다. 이를 체불 이력 조회 결과로 바꾸지 않는다.
- `official_listing`의 listed/not_listed/unavailable은 별도 값이다. 납부 신호로 이 값을 생성하지 않고, 명단 기준일이 없는 경우 임의의 배치 날짜로 채우지 않는다. listed 사실과 자료 부족도 보존한다.
- 기존 회사 API의 level/verdict/공개 요약 필드는 이번 작업에서 잠그거나 바꾸지 않았다. 상담 모델에 전달할 필드와 자유문장 표현을 기존 상담 공개 정책에 맞춘 것이다. ‘상위5%’는 표현/컨텍스트 문제이며 전체 DB 유출 증거가 아니다.
- 실제 운영 DB 행/배포 API 반환은 조회하지 않았다. Real adapter 변환 및 mock DTO 테스트 결과이지 운영 데이터 정확성 확인이 아니다. 작업 1의 공개 API 정책 미확정 항목은 계속 남는다.
