## 7. 단계 13 판정과 PR 차단 사유

**FAIL. merge-ready 또는 단계 13 완료로 선언하지 않는다. PR 제목·본문도 작성하지 않는다.** 다음 항목은 main과 현재 저장소에서 결정·증거를 찾지 못했거나 실제 UI 최종 검증이 남았다.

1. 운영 다중 인스턴스에 process-local quota를 대신할 gateway/shared store, trusted proxy header 정규화, provider budget circuit breaker와 alert가 없다.
2. Upstage/SKT/OpenAI의 실제 계약상 보존 기간, 학습 제외, 처리 지역, 삭제 요청 지원 여부를 확인하지 못했다. 코드의 요청별 동의만으로 이를 대신하지 않는다.
3. 운영 backup 최대 30일 TTL과 restore 시 live 삭제/expiry를 다시 적용하는 절차·리허설 증거가 없다.
4. feedback 저장은 안전하게 꺼 두었다. 공개 사용하려면 server-issued comparison ledger와 90일 rotation/purge를 먼저 구현·검증해야 한다.
5. 실제 Chrome 계정 삭제 prompt의 최종 제출은 자동화 포커스 문제로 서버 DELETE까지 도달하지 못했다. 사용자가 승인한 합성 계정은 로컬 API `DELETE 200`으로 정리했지만, 이는 Chrome UI PASS를 대신하지 않는다.
PR을 만들지 않았으므로 실제 GitHub hosted CI green은 없으며 로컬 Linux 상당 결과와 구분한다. 이는 PR 생성 뒤 확인할 병합 조건이지만, PR 초안 여부를 순환적으로 막는 독립 사유로 세지 않는다.

1~4는 저장소 밖 운영·공급자 책임자가 확정하거나 증거를 제공해야 한다. 5는 Chrome prompt 자동화가 정상인 환경에서 새 합성 Mock 계정으로 다시 확인한다.

## 8. 병합 후 운영 적용 초안

현재는 실행하지 않았다. 차단 항목이 해소되고 PR/CI가 통과한 같은 target SHA에서 수행한다.

1. backup 형식·SHA-256·복원 가능성과 30일 TTL을 확인하고 운영 DB read-only drift를 실행한다. `partial`, `schema_ahead`, `diverged`면 중단한다.
2. **migration**: guarded 절차로 0020만 적용한다. ledger 21, 마지막 0020, postcondition 115, pending 없음과 replay no-op을 확인한다. 기존 migration이나 DB를 초기화하지 않는다.
3. **role**: auth/conversation role script를 env secret 경로로 실행하고 owner/least-privilege smoke를 한다. 비밀번호를 argv에 넣지 않는다.
4. **app**: 동일 SHA의 build를 배포하고 readiness, login, 공개 count cap, risk public source, 요청별 AI 동의, 익명 429, request replay/409를 확인한다.
5. **worker**: 동일 SHA bundle을 설치한 뒤 service/timer를 시작한다. 단일 tick, 중복 worker, summary stale reclaim, expiry와 backlog를 확인한다.
6. **smoke**: 합성 계정으로 저장→새로고침→복원→재로그인→이어하기, A→B→해제, 임금 질문의 제43조/진정 근거, AQ21 미확인 의미, 탈퇴 cascade를 확인한다. 실제 provider는 사례당 최대 3회다.
7. 실패 시 app·worker/timer를 먼저 이전 SHA로 되돌리고 쓰기를 중지한다. migration 0020은 destructive down migration을 하지 않는다. nullable lease columns/index/check는 forward-compatible하게 유지한 채 원인을 수정해 재배포한다. drift와 ledger를 수동 변경하지 않는다.
