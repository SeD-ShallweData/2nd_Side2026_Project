## 원인과 실제 답변 경로

검토 순서는 분류 → 재작성 → 검색 → 근거 조립 → 생성 → 가드레일 → 공개 출력이다. **현재 구현의 실제 실행 순서는 회상/긴급 선분기 → 재작성 → 분류/answer plan → 검색**이다. 이를 문서상 순서와 혼동하지 않는다.

1. **분류**: Product는 `받지 못했다`를 인식했지만 Python의 일반 체불 신호에는 없었다. `미입금`, `안 줬다`도 보강했다. 명시적 실제 미지급을 회사 지표 설명으로만 보내지 않는 기존 원칙을 유지한다. 회상은 계속 `conversation_recall_no_retrieval`, 회사 설명은 `company_context_only`다.
2. **재작성**: 후속07 오답은 단순 기억 손실이 아니다. 이번 실제 AQ30 재작성 원문도 사용자 질문 그대로였고, 분류는 labor였다. 선행 사용자 진술은 문맥으로 사용하되 퇴직·금액·달력 날짜·연장 합의의 증거로 만들지 않는다. 명시적 지급 조건 질문은 기존 reviewed-topic 우선 경로를 통해 현재 질문으로 검색한다.
3. **검색**: 생활어 체불 신호가 맞으면 검색 질의에 제43조/정기 지급/진정 용어를 추가하고 검토된 제43조+노동포털 안내를 선택한다. threshold **0.42**, strong **0.30**, BGE-M3 revision·583 chunk 원본은 변경하지 않았다. 일반 체불 가이드가 퇴직금·지연이자·하도급 책임을 덮지 않도록 특수 주제를 제외한다.
4. **근거 조립**: 지급 약속/기록/청산 질문에만 `payment` 검토 근거 묶음을 추가했다. 퇴직·사망·제36조·기일 연장 조건을 다루지 않는 AQ30에는 제36조를 붙이지 않는다. 제36조의 부적용을 묻는 AQ33에는 조건 설명용 근거로 제공하되 퇴직 사실을 추정하지 않는다. 단순 matched가 아니라 제43조와 노동포털 근거가 함께 있을 때만 일반 체불 절차 대체 답변을 만든다. 제37조 하나만 있으면 그 근거로 진정 절차를 지지한다고 보지 않는다.
5. **생성**: 공유 prompt v10에 기산점·합의 조건, 문자 원문/발신자/수신 일시/금액/대상 기간/지급일, 미확인 항목 추가 확인, ‘다음 주’ 원문 보존을 명시했다. 기록 제안을 법정 제출 요건으로 만들지 않도록 했다.
6. **가드레일**: 14일/2주와 지급·청산의 적용 조건 및 기산점 관계, 연장 조건 누락, 회사 약속을 이유로 진정을 늦추는 안내, 문자 항목·불확실성 누락, 모든 증빙 선확보 의무를 검사한다. 한 개 금지 문장의 치환이 아니다. Dual/Responses가 같은 적용 조건 검사를 사용한다. 이는 제한된 관측 검사이지 완전한 법률 정확성 판정기는 아니다.
7. **공개 출력**: 문제가 있으면 이번 질문의 관련 근거·기록 항목·접수 경로를 보존한 답변으로 교체한다. 모든 질문에 일반 fallback을 적용하지 않는다. 생성 원문과 최종 출력의 차이는 실제 파일과 trace에 남겼다.
