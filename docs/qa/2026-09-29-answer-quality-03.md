# 답변 품질 잔여 작업 3 — 질문별 행동과 출처

## 출처와 가드 확인

- 새 답변의 공식 내용 중 **정기 지급일**은 현행 [근로기준법 제43조 제2항](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029727927), **노동포털 온라인 진정·관할 관서 방문**은 [고용노동부 노동포털 체불임금 해결 방법](https://labor.moel.go.kr/minwonSysInfo/wagesolway.do)의 신청방법으로 확인했다. 기존 S05 명세서 요청의 구성항목·계산방법·공제내역은 [고용노동부 상담의 제48조 제2항 설명](https://1350.moel.go.kr/rtmview.do?id=1000271960)과 맞는다. 이번 수정은 14일 기한이나 5인 미만 적용 법리를 바꾸지 않았다.
- 생성/교체 응답의 출처 DTO는 해당 답변에 등장한 공식 조문·절차 또는 실제 설명한 공개 카드 범주로 제한한다. 노동법 검색이 성공해도 무관한 제56조를 제43조 설명에 붙이지 않는 회귀, 카드 주장 없는 면접 질문에서 회사 공개 출처를 없애는 회귀를 확인했다. 이는 **출처의 자동 의미 판정 전체를 증명하지 않으며**, 아래 표본 주장을 수동으로 대조한 결과다.
- S17과 D2T24의 현행 no-match 응답은 공식 법률 근거가 확인되지 않았다고 명시하고 `sources=[]`로 둔다. 사용자 진술과 회사 공개 카드를 법적/개인 사실의 증거로 바꾸지 않는다. 인용만 출력한 원시를 교체하는 기존 `CITATION_ONLY_ANSWER`, 14일 신고기한 혼동, 응급 우선, 5인 미만 가산 조건 가드는 그대로 두고 전체 회귀에 포함했다. S21 회사 데이터 장애의 HTTP 503 계약은 변경하지 않았다.

## 검증과 남은 범위

- 수정 전 새 재현 테스트: S17 일반론, D1T11 8일 누락, D1T19 무관 출처, D2T24 분류 단락이 각각 FAIL. 수정 후 네 영역 및 합성 원시→가드→최종 D1T11/D2T24 회귀 PASS. S05/D2T19는 현행 작업 11 수정이 이미 있음을 확인했으며 새 결함으로 세지 않았다.
- Windows 로컬 최종 `npm.cmd run check`: **110 테스트 파일, 1,152 PASS, 92 opt-in skip**; typecheck PASS, lint 오류 0/기존 경고 8, Next 빌드 PASS. `git diff --check` PASS. 실제 공급자 호출 **0회**. 현재 프로세스에 공급자 키가 없고, RAG 두 합성 질문의 직접 요청도 연결/요청 단계에서 실패했다. 원시 문자열 주입은 실제 생성 품질 증거가 아니다.
- 실제 Upstage/SKT 원시·가드·최종과 실제 RAG 매칭의 출처 적합성, 긴 누적 대화에서 D2T24의 회사별 사실 정확성, 브라우저/운영 품질은 미검증이다. 작업 4에서는 연결 가능한 환경에서 S05·S17·D1T11·D2T19·D2T24, D1T19, 응급·14일·5인 미만 및 작업 1·2 회사/정정을 **소수 합성 입력**으로 원시/가드/최종/출처를 따로 확인해야 한다. 연결 실패·대체 응답은 생성 품질 PASS로 세지 말고 호출 제한을 지킨다. S21 503은 그대로 확인한다. 원인이 계속 불명확할 새 왜곡은 입력→검색/생성 입력→원시→가드→최종 추적으로 격리한 뒤 Astra High 전환을 사용자에게 알린다.

Git 쓰기·커밋·푸시, DB/schema/migration, 기억 구조, 운영/배포/계정 변경 및 전체 사용자 QA는 수행하지 않았다.
