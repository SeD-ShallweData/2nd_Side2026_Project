## 수정

- 같은 표시명은 다른 회사를 가리킨다는 증거가 아니다. 선택 회사와 질문의 지역이 일치하면 선택 상태를 사용하고, 지역이 다른 회사로 명시될 때만 재선택 경계를 유지한다. 다른 이름의 회사 요청은 기존 재선택 정책을 유지한다.
- 임금 `watch` 배지·생성 DTO는 “추가 확인 필요”로, 안전 `watch` 배지는 기존 “안전 신호 미확인”으로 구분한다. 임금 카드 신호를 산업안전 신호로 제시하지 않는다.
- 공개 카드 비교 질문은 owner 확인 대화에 이미 등장한 회사 ID와 공개 지역·주소만으로 대상을 정한다. 인천·김포 양쪽 카드의 임금 확인 항목과 안전 자료 범위를 생성 입력에 별도 ID로 제공한다. 선택 회사와 질문 대상이 다르면 명시된 소유자 확인 회사 카드를 사용한다. 화면에서 선택을 해제한 뒤 “이 회사”처럼 대상이 없는 질문은 이전 카드를 붙이지 않는다. 공개 요청에서 주입한 `conversation_recall`은 파서가 폐기한다.
- 두 회사를 구분해 달라는 질문에는 회사별 사용자 진술과 공개 카드를 다른 근거로 사용하도록 생성 지침을 붙인다. 임금 카드만으로 개인 체불을 확정하거나, 확인 신호가 있는 임금 카드를 이상 없음으로 바꾸지 않도록 한다.
- 임금 확인 신호 반전, 카드→체불 확정, 지역 없는 동명 비교, 명시적으로 분리 요청한 임금/부상 항목의 교차 혼입을 좁은 가드로 탐지한다. 카드 왜곡은 양쪽 공개 카드 사실을 담은 제한 응답으로, 주제 혼입은 사실을 새로 만들지 않는 확인 응답으로 교체한다. 원시 오류와 교체된 최종 응답을 같은 품질 통과로 세지 않는다.

## 검증

- 동명 A=인천/가입자 감소·이직 변동, B=김포/짧은 관측 기간의 합성 자료로 선택 A·B, 전환 뒤 상대 지역 명시, 해제 뒤 무대상 질문, 두 회사 비교를 단위/서비스 경로에서 확인했다. 다른 이름 회사의 기존 재선택 테스트도 통과했다.
- 합성 원시 문장으로 D1T24형 “양쪽 이상 없음”과 D2T10형 발목 항목의 임금 서류 혼합을 주입했다. 전자는 `WAGE_WATCH_REVERSED`, 후자는 `CROSS_COMPANY_TOPIC_LEAK`로 `guardrail_replaced`가 되며 왜곡 문장은 최종에서 제거된다. 정상적인 임금 추가 확인/안전 지역·업종 한계 설명과 “체불 확정이 아님”은 유지했다.
- 최종 로컬 Windows/Node 25.9.0: `npm.cmd run check` — Vitest **108 파일, 1,131 PASS**, opt-in 92 skip; 타입 검사 PASS; lint 오류 0/기존 경고 8; Next 16.3.5 빌드 PASS (`X797xkZmryoYb1Wp8Sys6`). `git diff --check` PASS. 샌드박스의 기존 `.runtime` 읽기 거부로 한 차례 빌드가 중단됐고 허용된 로컬 재실행은 성공했다. 이 검사는 Linux/Node 22, 실제 PostgreSQL, 브라우저, 배포 증거가 아니다.
- 현재 프로세스의 provider 키는 없고 `.env.local`에서 지시한 공유 키 파일도 존재하지 않았다. 비밀값은 읽거나 출력하지 않았다. 실제 Upstage/SKT 호출 **0회**, 실제 원시·가드·최종 답변의 동시 재검증 **미실행**. 연결 실패나 정책 대체 응답을 생성 품질 통과로 세지 않는다.

**작업 4 경로 정정(2026-09-29):** 공유 키 경로 `../api_key.env`는 `product/` 작업 디렉터리 기준 프로젝트 루트의 파일이며, 현재 존재하고 두 공급자 키 항목이 비어 있지 않다. 위 “파일 없음”은 상대경로 해석 오류였다. 이 작업의 공급자 호출 0회와 원시 품질 미검증은 그대로이며, 뒤의 연결 확인을 당시 검증으로 소급하지 않는다.

## 남은 문제와 전달

이번 수정은 카드 비교에 필요한 공개 자료를 제공하고 관측된 왜곡을 제한한다. 임의의 긴 대화에서 원시 모델이 회사별 사용자 사실을 정확히 보존한다는 증거는 없다. 특히 D1T24·D2T10의 **현재 후보 실제 provider 원시/가드/최종**, 장기 저장·요약·복원 후 회사 전환, 소수의 실제 RAG 영향 회귀가 남는다. 확인할 때도 작업 10 원본 FAIL은 그대로 두고 새 개발 회귀로 기록한다. 후속 답변 품질 작업은 이 범위가 닫힌 뒤 별도로 시작한다.
