## 실행 전 고정한 조건

| 조건 | 제공하는 기억 |
| --- | --- |
| A 최근 메시지 | 질문 전 완료된 최근 5턴(최대10개 user/assistant 메시지)만. 오래된 원문·요약·구조화 회상 슬롯 없음 |
| B 서버 원문 | 동일 owner 상담방의 완료 원문 전체(실험상 최대26턴/52메시지), 예산 내 최신 완전한 턴만. 요약 없음 |
| C 요약+최근 원문 | 기존 `extractive-v2`로 실제 격리 DB에 만든 완료 checkpoint 중 마지막 1턴보다 앞선 최신 checkpoint + 그 이후 원문. 매10메시지 경계, 별도 LLM 요약 없음. 예: 10메시지→요약0+원문10, 12→요약10+원문2, 40→요약30+원문10, 52→요약50+원문2 |

세 조건 모두 마지막1턴은 동일한 `recent_messages` 슬롯, 나머지는 동일한 서버 내부 참고 문맥 wrapper로 넣는다. 이는 기존 생성기의 recent10 제한이 B를 다시 A로 잘라버리지 않도록 한 **평가 도구의 주입 방식**이다. 공개 route/parser는 변경하지 않는다. C가 현재 제품의 최신 checkpoint를 그대로 사용하는 경우와 달리, 공통 마지막1턴을 확보하려고 checkpoint를 한 턴 이전으로 선택한다는 차이를 공개한다.

공통 기억 예산: **BGE-M3 tokenizer 기준 4,096 evaluation tokens**. 봉인된 로컬 tokenizer.json을 사용하며 실제 Solar tokenizer/과금 토큰이라고 부르지 않는다. wrapper+원문 최근1턴을 포함해 센다. 초과 시 가장 오래된 완전한 턴부터 제거하며 C 요약은 하나의 atomic block으로 제거한다. 최근1턴도 혼자 초과하면 호출하지 않고 BLOCKED로 남긴다. 전체 outgoing message payload 상한은 최종 **12,288 evaluation tokens**다. 처음8,192로 정했으나 F26-B의 생성 전 검사에서 고정 system/policy를 포함한 입력이 초과해 중단했다. **기억 예산/실제 payload/prompt/모델 설정은 그대로**, 검사 상한만 높였다. 기존 유효10행을 보존하고 무효 F26-B 및 미실행 조건만 재개했다. 공급자 실제 usage는 반환값으로 별도 집계한다.

공통 설정: Node22/lock 의존성, Upstage `solar-pro3`, generation temperature0.1/max_tokens700, rewrite0/120, intent0/100, 기존 prompt/guardrail. 고정된 기존 reviewed labor 근거 묶음과 같은 회사 Mock DTO를 사용한다. 재작성·분류는 실행·계측하지만 검색/자료 선택에는 되먹이지 않아 retrieval 차이가 기억 비교를 혼동하지 않게 한다. 기대값은 출력 평가에만 쓰며 prompt에 넣지 않는다.

이 실험은 생성에 제공하는 기억의 차이를 보는 로컬 ablation이다. 현재 제품의 deterministic recall shortcut은 세 조건 모두 거치지 않는다. 기존 owner 검사를 통과한 DB 원문만 B/C에 제공하며, 다른 owner/방 접근과 공개 forged memory 폐기는 별도 회귀로 확인한다. 실제 HTTP/UI 전체 비교로 주장하지 않는다.

### 비교 해석의 중요한 제한

- **F05 A/B/C의 생성 prompt SHA가 완전히 동일**(`56a43ced2b8ab7b59235097d37b64b24d636dcdf674ec6cdde98a3680e1c936f`), 세 입력 모두 evaluation6881/실제prompt4542tokens인데 결과는P/P/F였다. 해당 차이는 기억 방식의 인과 효과가 아니다. 동일 설정에서도 생성 편차가 관측됐다. seed 고정/반복 통계 실험은 하지 않았다.
- 기존 개발 주제를 합성한 이력의 assistant25턴은 같은 일반 확인 문구다. 그 문구의 반복 출력과, C 연속 대화의 직전 일반 법률 문구 반복이 관측됐다. 인과 원인은 아직 미확정이며 **현실적인 다양한 assistant 이력의 대표 표본이라고 주장하지 않는다**. 결과를 보고 전체 재호출하거나 유리한 표본으로 교체하지 않았다.
- C F26 checkpoint50에는 급여일/약속 슬롯이 남지만 최초 계약서 원본·통장 사본은 없다. 반면 F20/L23의 필요한 급여일이 입력에 남아도 답변에서 사라진다. **정보 압축 손실과 생성 단계의 무시를 분리**했다.

- 실측24건에서4096 기억 예산에 의한 잘림은0. 긴 경우도 짧은 합성26턴이므로 훨씬 긴 실제 원문/한도 경계의 품질은 NOT RUN. 잘림 규칙 자체는 회귀 테스트로만 검증했다.

## 03 시작점과 보류

1. **현재 제품 경로에서 우선 재현할 실패**: 회사B에 회사A의 지급 약속/미지급이 붙는 경우, 현재 질문의18일 정정을 무시하는 경우, 과거 assistant 문구만 반복하는 경우. 이번 ablation은 deterministic회상 우회이므로 바로 제품 전체 결함으로 확정하지 말고 기존 회상/혼합질문 경로에서 좁게 확인한다. 기대값을 prompt에 넣지 않는다.
2. **기억 손실과 사용 실패를 각각 수정 후보로**: 최초 보유자료 같은 비슬롯 사실의 요약 누락, 입력에 남은 급여일 무시, 회사별 부정 사실/현재 선택/원문출처 보존. schema 추가나 B전체원문 채택부터 시작하지 않는다.
3. **원시 생성/가드 의미 계약**: AQ32의14일 진정기한 생성, AQ21의미확인 카드 의미, AQ12의정확 문구 기반 교체를 우선순위에 반영. 모든자료 확보를 접수 선행요건처럼 쓰는 표현, 회사ID노출·상대날짜 임의 구체화도 좁은 회귀 후보다.
4. **평가기 보강 후 소규모 전후 비교**: lexical PASS가 회사귀속/추가거짓을 놓친 L26-B를 음성 조건으로 확장하고, 반복 fixture에 치우치지 않는 기존 개발 대화를 사용한다. 동일입력 F05의편차를 감안한 제한된 반복/순서 교차를 사전예산으로 정한다. 이번 데이터를 지우거나 소급해 다른 실험으로 부르지 않는다.
5. **비용은 정확도 다음**: C의UUID/중복문구·비관련주제 포함, 분류 enum조합 불일치와 rewrite 답변복사/길이종료를 확인하되 정확도를 희생한 토큰 절감은 채택하지 않는다.

미실행: 실제 공개HTTP/UI의 A/B/C(제품 기능 아님), 재로그인/재시작/worker운영, 실제vector검색 변동, 독립 평가셋, 사용자 전체수동QA, 실청구액/TTFT, 더긴 실제원문·반복통계. 운영migration/권한/worker/backlog/quota/proxy/알림/backupTTL·삭제재적용은 팀원 회신 대기 그대로다. 이 미실행 부분을 우수성이나 운영PASS로 바꾸지 않는다. **02에서 종료하며03은 자동 시작하지 않는다.**
