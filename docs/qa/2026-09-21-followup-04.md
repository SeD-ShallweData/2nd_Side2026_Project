## 변경과 전후 근거

### 검색·corpus

- `wage_arrears`/`wage_evidence` 의도는 단순 한 문구가 아니라 미지급 신호와 증빙·행동 표현을 조합한다. `월급이 두 달 밀렸`, `밀린 월급`, `월급날이 지났`, `입금되지 않음` 변형을 처리한다.
- 질의 확장은 검색용 문자열에만 “임금 지급일·제43조·체불 진정”을 보탠다. 사용자 원문이나 저장 대화를 바꾸지 않는다.
- 검수 가이드를 거리 경계의 잡음보다 우선하되, 대지급금/확인서/퇴직/실업/최저임금/포괄임금/시효 등은 원래 전용 법령 검색으로 남긴다.
- 일반 체불 가이드가 맞은 경우 선택 문서는 검수된 공식 가이드만 사용한다. 관련 없는 vector 문서를 limit 채우기용으로 섞지 않는다. threshold는 0.42 그대로다.
- HTTP DTO에 공식 자료 검토일 `as_of`를 전달한다. Chroma 파일을 사용하는 평가기는 Windows handle을 명시적으로 닫아 임시 DB 삭제 실패를 막는다.

### 제품 라우팅·최종 답변

- 일반 미지급은 `AnswerPlan`의 labor 경로로 보내되, “이 회사 지표가 임금이 밀린다는 뜻인가” 같은 회사 해석은 `company`에 남긴다. 실제로 못 받았다는 사용자 진술은 잘못된 company 분류보다 우선한다.
- 검색이 `matched`된 일반 체불에만 source-linked recovery baseline을 만든다. `no_match`나 `unavailable`을 근거 있는 답변으로 승격하지 않는다.
- baseline은 지급일·월별 미지급액, 계약/급여/근무/입금/약속 기록, 1350 상담과 노동포털/관할 관서의 정식 진정을 구분한다. 복합 질문은 같은 노동 안내 뒤 투자 추천을 제한한다.

- 공식 노동포털 일반 가이드에서 확인서 한 줄을 제거했다. 확인서 목적·조건·절차는 후속 2의 좁은 검수 번들에서만 안내한다.

2. 실제 Responses/SKT 경로는 미실행이다. 공통 DTO·guard 단위 회귀만 있으며 live provider 동등성은 후속 통합 acceptance에서 확인한다.
3. RAG core의 기존 3개 miss(가족만 사업장 최저임금, IRP, 파산 시 퇴직금)는 이번 목표와 무관하고 기존 top1/top5 gate는 통과했다. 광범위 corpus 재적재·threshold 튜닝으로 확대하지 않았다.
4. Windows에서 read-only parent 권한을 POSIX와 동일하게 판정하는 자산 unit 1건은 여전히 환경 제한이다. Linux release/startup gate 검증을 대체하지 않는다.
5. 후속 03의 Real PG16 로그인 연속 대화·재시작·browser BLOCKED와 후속 01의 공개 API 정책 미확정은 그대로다.
6. **후속 05 시작점**: 답변 내용/RAG를 다시 튜닝하기보다 최종 표시 경로를 점검한다. 수동 QA의 반복 번호, 출처·provider/history 라벨 노출, 복원 회사 ID 대신 표시명, 긴 답변의 단계/출처/한계 UI를 실제 browser에서 재현한다. 모델 원문·API DTO·렌더링 parser·CSS 책임을 분리하고, 현재 AQ09/AQ25~29와 후속 2·3 계약을 회귀해 유용한 내용을 일반 fallback으로 잃지 않도록 한다.
