## 실제 API와 사용량

수정 전 비교점은 [02 보고서](2026-09-23-personal-02.md)의 동일 개발용 AQ12/AQ21/AQ32 진단이다. AQ12는 야간수당 조건 누락으로 교체, AQ21은 카드 의미를 틀렸어도 raw가 통과, AQ32는 14일 진정 기한을 새로 만들어 교체됐다. 이번 실행도 동일한 Mock 회사·real 대화·Upstage 경로와 개발용 질문을 사용했지만 제품 프롬프트/가드 변경 후 별도 생성 결과이므로 단일 seed의 결정론적 전후 점수로 간주하지 않는다.

- 진단 묶음 1 (`1790154682928-9d54f7`): AQ12/AQ21/AQ32 3건, 예상 7~9호출·hard cap 9, 실제 **Upstage HTTP 200 7호출 / 반환 usage 합 14,452 tokens**, 자동 재시도 0. AQ12 야간수당 적용 조건은 raw 누락으로 교체; AQ21은 위 오교체; AQ32는 새 접수 기한은 없어졌지만 법정 연장 조건 누락으로 교체. 세 건 모두 최종 계약과 raw 유용성을 별도로 검토했다.
- 진단 묶음 2 (`1790154831894-ee7e98`): 영향받은 AQ21만, 예상 3호출·hard cap 3, 실제 **HTTP 200 3호출 / 4,992 tokens**, 자동 재시도 0. 원시/최종 답변 일치, guard passed. 두 묶음 합 **10호출 / 19,444 반환 tokens**. 분류·재작성·생성 단계별 JSONL은 ignored runtime에 보존. 반환 usage만 합산했으며 청구 금액/TTFT는 제공되지 않아 미측정.

## 부분 브라우저 및 DB 결과

- 합성 계정 생성→3턴 저장→새로고침→상담 상세 복원→로그아웃·재로그인→저장 목록 재표시 확인. 정정 15일과 약속 부재, 공식 출처 3개 링크, 다음 행동 표시 확인. 이어하기와 회사 A(한빛테크)→B(다온제조) 선택/변경 화면은 수행했다.
- **QA 실행기 결함**: Mock 화면의 B는 초기 격리 DB `firms`에 없었다. B 전환 PATCH가 실패하고 A 문맥으로 한 번 저장됐으며, 이는 유효한 A→B 기억 평가가 아니다. 실행기에 B 합성 행을 추가하고 현재 전용 tmpfs DB에도 같은 행을 넣은 뒤 PATCH 성공·B 화면 연결/새 턴의 '당시 사업장: 다온제조'를 확인했다. 실패 턴은 지우거나 성공으로 재해석하지 않는다.
- **제품 잔여 결함**: 잘못 A로 저장된 B 언급이 A 사실 추출에 섞일 수 있고, B 연결 후 'A와 B의 지급 약속을 각각' 묻는 질문은 '현재 B만 연결'이라는 일반 확인 답변으로 끝났다. 사용자 진술 입력만 한 턴도 질문 확인 fallback으로 끝났다. 이 두 경로의 사실 귀속·교차 회사 회상은 03-B에서 원문/턴 회사 ID/회사 표시명을 분리해 재현·수정해야 한다. 이 결함 때문에 03 전체를 완료로 판정하지 않는다.
- 회사 연결 해제, 과거 회사명 순서 회상, 20~30턴 summary 재시작, 즐겨찾기 연동, 계약서 API, 화면 번호 목록은 이번 Chrome 부분 QA에서 **NOT RUN**. 관련 기존 단위/API 검사는 전체 검사에 포함되지만 화면/실서비스 증거로 확대하지 않는다.
- 삭제 **전용** 합성 계정은 Chrome에서 확인 문구 입력 후 최종 제출했다. 홈으로 이동하며 로그인 링크가 나타났고, 격리 DB `users`에 해당 합성 이름의 행 **0**, 삭제된 자격으로 재로그인 거부를 확인했다. 서버의 개별 DELETE HTTP 상태 코드는 이번 브라우저 도구에서 직접 포착하지 못해 **NOT MEASURED**; DB 삭제와 세션 해제는 확인됐다.
- 종료 시 해당 앱/전용 tmpfs 컨테이너를 중지·제거하고 migration replay no-op을 확인했다. 브라우저 실행 동안 제품 코드가 바뀌어 `source_unchanged=false`이며 그 브라우저 결과를 최종 코드 빌드의 재검증으로 간주하지 않는다.

## 검사·남은 작업과 인수

- 관련 테스트는 실패 재현 후 수정. 최종 `npm.cmd run check`: Vitest **101 files/1 skipped, 1,043 pass/85 live opt-in skip**, typecheck PASS, ESLint 0 errors/기존 7 warnings, Next production build PASS. 실행기 문법 검사 PASS. 처음 build의 `.next` reparse-point EPERM은 Git 무시 빌드 캐시를 격리 이동하고 재시도해 PASS한 환경 문제다. 실제 운영/호스팅 CI 결과는 아니다.
- **03-B 시작점**: (1) 회사명이 명시된 사용자 진술을 현재 선택 회사 ID에 무조건 귀속하지 않도록 원문 출처와 선택 문맥의 충돌을 처리, (2) A/B 각각 또는 해제 후 과거 회사 질문을 기존 owner/server-hydrated 사실에서만 회상, (3) 인용만 출력하는 경우 새 빌드 실호출 1건과 정상 답변 회귀, (4) 영향받은 20~30턴·해제·과거 이름·번호/출처 화면 및 실패 복구 부분 QA. 팀원 독립 평가셋은 읽지 않는다. schema가 필요하면 우회하지 말고 담당자 요구로 분리한다.
