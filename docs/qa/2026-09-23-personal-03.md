### 평가 도구와 재현

- `product/scripts/personal03-proxies.mjs`: loopback 앱/Upstage 계측, 본문 prompt 대신 hash, 원시 답변·반환 usage·지연·가드 결과를 **Git 제외 runtime**에 기록. 인증 헤더·키·세션을 기록하지 않는다. fault 파일은 로컬 도구에서만 읽으며 공개 제품 API 실험 모드를 추가하지 않았다.
- `product/scripts/run-personal03b-http.mjs`: disposable 합성 계정, 26턴/owner/저장/복원/replay/favorite/계약 API/정상 생성/실패 주입/탈퇴. 최초 완료된 26턴 결과는 append JSONL에 보존하고 `--remaining-only`, 이미 검증한 fault를 생략할 때 `--live-only`로 영향을 받는 부분만 수행했다.
- 기존 `db/scripts/run-personal-memory-comparison.mjs --serve`는 새 DB만 만들고 app/proxy를 시작한다. `restart.once`는 자기 앱만 재시작, `shutdown.flag`는 자기 자원 종료용이다. 비교 도구의 요약 방법 표기도 하드코딩 v2 대신 실제 summary_version으로 기록한다.
- 최종 종료 도중 실행 중인 도구의 잔여 행 집계에 잘못된 테이블명 `conversations`가 남아 **42P01**이 났다. 소스는 `conversation_threads`로 수선했으나 이미 로드된 프로세스는 옛 코드였다. 따라서 해당 프로세스의 최종 replay 단계는 NOT RUN으로 보존한다. 종료 직전 정확한 이름/label/포트의 같은 전용 DB에서 별도 실행한 **기존 migration replay no-op / ledger 21**과 위의 삭제 후 6종 0행이 독립 증거다. 오류 후 finally에서 전용 컨테이너는 정상 제거됐으며 전체 UI/API 결과가 무효가 되는 오류는 아니다.

재현은 Node 22, lock과 맞는 설치, Docker Engine, 현재 소스의 `npm.cmd run check` 빌드가 필요하다. 사용자 지정 키 파일은 bootstrap에서 dotenv로 읽어 **자식 환경의 UPSTAGE_API_KEY에만** 전달하며 명령줄·문서·로그에 값을 넣지 않는다. 이미 준비된 자식 환경에서 저장소 루트 기준:

```text
node db/scripts/run-personal-memory-comparison.mjs --serve --bundle offline --max-calls 18 --live
```

`local_browser_app_ready`가 출력된 뒤 product 디렉터리에서:

```text
node scripts/run-personal03b-http.mjs .runtime/personal03/<출력된 실행 ID>
```

Chrome은 `http://127.0.0.1:3127`의 새 합성 계정만 사용한다. 실제 환경 URL을 넘기는 옵션은 없다. 종료 시 해당 runtime의 `shutdown.flag`를 만든다. 원문/계측은 `.runtime/personal03/1790563251291-be0f1e`와 `1790563838253-a3f714`에 남겼으며 `git check-ignore`를 확인했다. 마지막 환경의 `final-acceptance-build.json`, `metrics-final.json`, `browser-*-delete-counts.json`, `migration-replay-final.json`이 안전한 로컬 근거다.

- **03:** 03-A/03-B의 우선 결함 수정과 명시된 로컬 부분 검증은 완료하여 이번 실행을 종료한다. **모든 답변·기억 약점 해결/전체 인수 완료는 아님.** 특히 실제 raw의 서문 반복은 마지막에도 남고 가드가 복구했다. 02의 일반 문서 사실 압축 손실, 64개 밖의 장기 사실, 모든 상호 별칭, 일반 질문에서 여러 회사 답변의 초점은 별도 개선 후보다. 가드 fallback을 raw 정확도 향상으로 보고하지 않는다.
- 후속 우선순위는 (1) 실제 long-history raw 반복의 문맥/생성 원인을 분리한 제한 실험, (2) 일반 문서 사실의 압축 손실과 회사별 답변 초점 평가다. 최종 빌드의 fault HTTP 반복·추가 브라우저 폭넓은 QA는 아직 하지 않았으며 기존 관련 단위 회귀/이번 부분 검증과 구분한다. 새로운 단계나 대규모 평가를 자동 시작하지 않는다.
- 팀원의 운영 migration/권한/실제 저장·worker/timer/backlog·shared quota/알림·backup TTL/복구 삭제 증거, 독립 평가 결과, 사용자의 최종 전체 수동 QA는 대기다. 로컬 성공을 최신 배포본 성공으로 표현하지 않는다. **04는 01 이후 별도, 05/06도 별개**다. Git·운영 조치는 사용자 담당이다.
