## 다음 구현 전 고정할 답변 계약

1. 내부 지침·컨텍스트·정책 문구가 최종 답변에 포함되면 다른 내용과 무관하게 실패다.
2. 회사 미선택의 일반 지표 질문은 특정 사업장 조회를 요구하지 않고 설명 가능한 범위를 답한다.
3. 이미 제공된 임금체불 맥락의 문의처 후속 질문은 같은 정보를 다시 요구하지 않는다.
4. 복합 요청은 답할 수 있는 노동 부분과 범위 밖 부분을 구분한다. 모든 복합 요청을 무조건 같은 `unclear` 문구로 끝내지 않는다.
5. 선택 회사 질문은 같은 설정에서 3회 반복해 분류·최종 답변·가드레일 결과를 함께 판단한다.

이 문서는 배포 또는 브라우저 인수 결과가 아니다. 실제 팀 QA 원문을 받으면 원문 ID를 유지한 채 위 항목에 추가하고, 합성 사례와 구분한다.

## 1차 후보 변경과 재측정

기준선 뒤 다음 공통 변경을 적용했다. 아직 커밋·PR·배포하지 않았다.

1. 내부 응답 작성 흔적(`제공된 컨텍스트`, `답변 구성/작성`, `작성 지침`)을 공통 출력 가드레일로 탐지하고, 생성 프롬프트에도 사용자용 본문만 출력하도록 명시했다.
2. RAG가 일치한 노동 질문이 가드레일 교체될 때는 회사 선택을 다시 묻지 않고, 근로계약·근로시간·임금 기록과 1350 확인을 안내하는 관련 fallback으로 교체했다.
3. 의도 분류에 `company_scope`를 추가했다. 특정 사업장 자료가 필요한 `specific`과 회사 미선택으로도 답할 수 있는 일반 지표 의미 `general`을 분리한다.
4. 짧은 생략형 후속 질문의 재작성 모델이 원문을 그대로 돌리거나 실패하면, 마지막 **사용자** 발화만 결합해 검색한다. 과거 assistant 안내는 사용자 사실로 결합하지 않는다.

후보 실측:

- `QA-LABOR-01` 3회: 1회 정상 생성, 2회 `INTERNAL_RESPONSE_INSTRUCTION` 교체. 세 최종 답변 모두 내부 작성 문구 없음; 교체된 두 답변 모두 근로시간·임금 기록과 1350 안내를 유지.
- `QA-GENERAL-01` 3회: 모두 `company/general` → `general_company_explanation` 정책 응답. 사업장 선택 강제 없음.
- `QA-FOLLOWUP-01` 3회: 모두 재작성·RAG `matched`·생성 경로. 임금체불 맥락을 다시 묻지 않음.

전체 자동 검증: 65개 테스트 파일 766 통과, 85개 opt-in 실제 의도분류 테스트 skip, TypeScript 통과. 브라우저·Real DB·배포는 여전히 미검증이다.
