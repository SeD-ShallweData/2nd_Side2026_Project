# QA 테스트 계획 (실제 데모 화면 기준)

## 1. 인수 테스트(Acceptance Test) 체크리스트 — 권한·게시판·위험카드

| 번호 | 영역 | 항목 | 채점 기준 (O/X) |
|---|---|---|---|
| 1 | 사업장 검색 | 자동 선택 방지 | "건설" 등으로 검색 시 결과가 다건 노출되고, 화면 안내("첫 번째 결과가 자동 선택되지 않습니다")대로 **첫 번째 결과가 자동으로 선택되지 않는다** |
| 2 | 사업장 검색 | 동명 사업장 구분 | 검색 결과 각 카드에 지역·업종·"일부 일치" 등 구분 정보가 함께 표시되어 동명 사업장을 구분할 수 있다 |
| 2-1 | 사업장 검색 | 지역·업종 필터 | 검색 결과 화면에서 필터로 지역·업종을 선택하면 해당 조건에 맞는 사업장만 노출되고, 필터 해제 시 전체 결과로 복원된다 |
| 3 | 사업장 검색 | 읽기 전용 DB 고지 | 검색 화면에 "READ ONLY DB" 배지가 노출되고, 실제로 검색·조회 동작에서 데이터 변경이 발생하지 않는다 |
| 4 | 사업장 검색 | 페이지네이션 | 검색 결과가 10개 단위로 분할되어 노출되고, 페이지 이동이 정상 동작한다 |
| 5 | 위험카드 | 임금·산업안전 카드 분리 | 사업장 상세 화면에서 "임금 지급 관련 정보"와 "산업재해 확인 우선순위 신호"가 **별도 카드로 분리**되어 있고 합산 점수가 존재하지 않는다 |
| 6 | 위험카드 | 비낙인 고지 배너 | 카드 하단에 "결과를 하나의 점수로 합치지 않습니다" 문구와 함께, 두 신호 모두 사고확률·안전판정이 아니라는 고지 문구가 노출된다 |
| 7 | 위험카드 | 데이터 결측 표시 | 미연동 지표(이직률, 고용추이, 데이터충실도 등)는 **"확인할 수 없음"**으로 표시되고, "값을 추정하거나 내부 ML 지표를 사용자 수치로 바꾸지 않습니다" 원칙에 따라 임의값·추정치가 노출되지 않는다 |
| 8 | 위험카드 | 일치 결과 없음의 오독 방지 | 체불사업주 명단에 일치 결과가 없는 경우 "안전"으로 해석되지 않도록, "연계 데이터 범위에 존재하지 않는다는 의미이며 실제 신뢰 여부와는 관계가 없다"는 고지 문구가 함께 표시된다 |
| 9 | 위험카드 | 데이터 기준일·출처 표기 | 두 카드 모두 데이터 신뢰도, 데이터 기준일, "데이터 출처 보기" 토글이 노출된다 |
| 9-1 | 위험카드 | 배지 종류별 정확성 | 사업장 상태에 따라 "추가 확인 권장"(임금), "우선 확인 필요"/"뚜렷한 이상 신호 없음"(산재) 배지가 실제 데이터 상태와 일치하게 노출되고, 각 배지 옆에는 해당 배지를 오독하지 않도록 하는 설명 문구가 함께 표시된다 |
| 9-2 | 위험카드 | 데이터 신뢰도 등급 표시 | 데이터 신뢰도 필드가 "자료 충분" 외에 "제한적 자료" 등 낮은 등급으로도 정상 표시되며, 등급이 낮을 때 사용자에게 그 사실이 명확히 전달된다 |
| 10 | 체크리스트 | 상태 초기화 정책 | 입사 전 행동 체크리스트(8개 항목)는 새로고침 시 **의도대로 초기화**되며(브라우저 로컬 상태만 유지), 이 동작이 데이터 유실 버그가 아님을 화면 안내 문구("현재 브라우저 화면에서만 유지되며 새로고침하면 초기화됩니다")로 확인한다 |
| 11 | 체크리스트 | 카운터 정확성 | 항목 체크 시 상단 카운터("0/8 확인")가 실시간으로 정확히 갱신된다 |
| 12 | 화면 분리 | 상세 화면 범위 제한 | 사업장 상세 화면은 신호·체크리스트까지만 다루고, AI 상담·계약서 검토는 버튼을 눌러 **별도 화면으로 이동**해야만 진입된다 |
| 13 | 커뮤니티 | 데모 기능 제한 고지 | 커뮤니티 화면 상단에 "DEMO" 배지와 함께 "검색과 분류만 화면에서 동작합니다. 작성·댓글·신고는 DB API 연결 전까지 제공하지 않습니다" 안내가 노출되고, 실제로 작성·댓글·신고 버튼이 비활성화(또는 미제공) 상태와 일치한다 |
| 13-1 | 커뮤니티 | 카테고리 필터 | "전체/입사 전 확인/근로계약서/현장 안전/임금" 필터 선택 시 해당 태그가 붙은 게시글만 노출된다 |
| 13-2 | 커뮤니티 | 게시글 검색 | 게시글 검색창에 키워드 입력 시 제목·본문 기준으로 결과가 걸러진다 |
| 14 | 권한 | 감독관 화면 접근 제한 | 근로감독관 대시보드는 별도 인증을 거친 계정만 진입 가능하고, 일반 사용자 계정으로는 접근이 차단된다 |
| 15 | 커뮤니티 | 데모 게시물 표식 | 게시글이 화면 구조 확인용 더미 데이터임을 상단 안내문("현재 게시물은 화면 구조 확인용 더미 데이터입니다")으로 명확히 고지한다 |
| 16 | AI 상담 | 사업장 컨텍스트 연동 | "이 사업장을 기준으로 AI 상담" 버튼으로 진입 시 해당 사업장 정보가 재입력 없이 답변에 반영되고, 화면 하단에 "특정 회사에 관해 질문하려면 사업장을 먼저 검색해 선택하세요" 안내가 노출된다 |
| 17 | AI 상담 | 두 모델 병렬 비교 | 같은 질문에 대해 Upstage Solar와 SKT A.X 답변이 동일 화면에 나란히 비교 표시되고, "동일 질문을 실제 Upstage Solar·SKT A.X API에 병렬 전송합니다" 고지가 노출된다 |
| 17-1 | AI 상담 | 판정 요구 방어 | 빠른 질문 버튼 "이 회사는 안전한가요?" 클릭(또는 동일 취지 입력) 시, AI가 안전 여부를 단정하지 않고 확인 항목·다음 행동으로 응답한다 |
| 17-2 | AI 상담 | 전문가 상담 대체 아님 고지 | 화면 상단에 "법률 판단이나 전문가 상담을 대신하지 않습니다" 문구가 노출된다 |
| 17-3 | AI 상담 | 범위 밖 질문 처리 | 근로 관련이 아닌 질문 입력 시 "수록 범위 밖 주제는 해당 이유와 공식 창구 안내를 안내합니다" 원칙대로 억지 답변 없이 사유와 공식 창구가 안내된다 |
| 17-4 | AI 상담 | API 키 비노출 | "API 키 값은 프론트엔드 브라우저에 노출되지 않습니다" 고지대로, 브라우저 개발자도구 네트워크 탭에서 API 키가 노출되지 않는다 |
| 18 | AI 상담 | 긴급 상황 차단 | "산업재해로 다쳤다" 등 긴급 사고 표현 입력 시, 상담 답변 생성 전에 119·안전 확보 안내를 우선 반환한다 |
| 19 | 계약서 진단 | 결과 3분류 | 계약서 업로드 시 "확인된 항목 / 누락 가능 항목 / 회사에 다시 물어볼 질문" 3분류로 항목별 결과가 제공된다(결과 화면 배지 기준으로는 "문서에서 확인됨 / 누락 가능 / 추가 확인") |
| 19-1 | 계약서 진단 | 파일 형식·용량 제한 | "PDF, PNG, JPG · 최대 10MB" 조건에 맞지 않는 파일 업로드 시 적절한 오류 메시지가 노출된다 |
| 19-2 | 계약서 진단 | 원문 미저장 고지 | "DOCUMENT ANALYSIS" 배지와 함께 "파일은 내부 계약서 분석 서비스로 전달되며 원문을 제품 서버나 Git에 저장하지 않습니다" 문구가 업로드 전후로 노출되고, 실제로 원문이 영구 저장되지 않는다 |
| 19-3 | 계약서 진단 | 검토 버튼 활성화 조건 | 파일을 선택하기 전에는 "선택한 파일 검토" 버튼이 비활성 상태이며, 파일 선택 후에만 활성화된다 |

## 2. 테스트에 필요한 계정·게시글·사업장 상태 정의

### 계정
| 계정 유형 | 상태 | 용도 |
|---|---|---|
| 미로그인(게스트) | - | 커뮤니티 열람·필터·검색은 가능한지, 작성·댓글·신고 기능은 (로그인 여부와 무관하게) 현재 미제공 고지가 뜨는지 확인 |
| 일반 회원 A | 정상 활성 | 검색·위험카드 조회·체크리스트·AI 상담·계약서 업로드 전체 플로우 테스트 |
| 일반 회원 B | 정상 활성 | 커뮤니티 게시글 작성·타인 글 신고 테스트용(A와 상호작용 확인) |
| 근로감독관 계정 | 별도 인증 완료 | 감독관 대시보드 접근 및 일반 계정의 접근 차단 확인 |
| 관리자/운영자 | 관리자 권한 | 신고된 게시글 처리, 위험카드 데이터 표시 오류 등 백오피스 확인 |
| 정지된 계정 | 이용 제한 | 제한된 계정이 실제로 글 작성·상담 이용이 차단되는지 확인 |

### 게시글
> ⚠️ 현재 데모는 "검색과 분류만 동작하며 작성·댓글·신고는 DB API 연결 전까지 제공하지 않는다"고 고지되어 있음. 아래 항목 중 작성·신고·삭제 관련 상태는 **DB·API 연동 이후 단계에서 실제 테스트가 필요**하며, 현재 데모 단계에서는 "제한 고지가 정확히 노출되는지"만 확인한다.

| 상태 | 설명 | 확인 목적(현재 데모 단계) |
|---|---|---|
| 정상 게시글(더미 데이터) | 화면 구조 확인용 더미 게시글(태그·지역·업종·작성자유형·시간·공감·댓글 수 포함) | 목록·상세 조회 정상 노출, 카테고리 태그·메타정보 정확히 표시되는지 |
| 작성/댓글/신고 시도 | 사용자가 작성·댓글·신고 버튼을 눌렀을 때 | 기능이 아직 제공되지 않는다는 안내가 뜨고, 오류 없이 예외 처리되는지 (DB API 연동 후에는 아래로 대체) |
| (연동 후) 신고 접수된 게시글 | 다른 사용자가 신고한 상태 | 신고 임계치 도달 시 노출 제한/관리자 검토 큐 이동 여부 |
| (연동 후) 삭제된 게시글 | 작성자 또는 관리자가 삭제 | 삭제 후 목록·검색에서 사라지는지, 댓글은 어떻게 처리되는지 |
| (연동 후) 익명 게시글 | 작성자 정보 비노출 | 익명성 보장되는지, 관리자 화면에서도 개인정보 과다 노출 없는지 |

### 계약서 파일 (계약서 진단 테스트용)
| 상태 | 설명 | 확인 목적 |
|---|---|---|
| 정상 근로계약서(PDF) | 지원 형식·용량 이내 파일 | 확인된 항목/누락 가능/다시 물어볼 질문 3분류 정상 출력 |
| 정상 근로계약서(PNG/JPG) | 이미지 형식 계약서 | 이미지 인식(OCR) 기반 구조화 추출이 PDF와 동일하게 동작하는지 |
| 용량 초과 파일 | 10MB 초과 파일 | "최대 10MB" 제한 안내와 함께 업로드가 거부되는지 |
| 미지원 형식 파일 | PDF/PNG/JPG 외 형식(예: docx, hwp) | 적절한 오류 메시지가 노출되고 서버 오류로 이어지지 않는지 |
| 필수 항목 누락 계약서 | 임금 지급일 등 특정 항목이 비어있는 계약서 | 해당 항목이 "누락 가능"으로 정확히 분류되는지 |

### 사업장 (배지·데이터 신뢰도 상태 기준)
| 상태 | 설명 | 확인 목적 |
|---|---|---|
| 공식 명단 등재 사업장 | 체불사업주 명단에 실제 등재된 사업장 | "공식 명단 1개 확인" 문구가 정확히 표시되고 사전 신호와 구분되는지 |
| 명단 일치 결과 없음 사업장 | 체불사업주 명단에 등재되지 않은 사업장 | "연계 데이터 내 일치 결과 없음" 표시가 뜨고, 이것이 "안전"으로 오독되지 않도록 고지 문구가 함께 노출되는지 |
| **임금카드 "추가 확인 권장" 배지** | 임금 지표가 판단하기에 불충분하거나 애매한 사업장 | 임금 카드 상단에 "추가 확인 권장" 배지가 뜨고, 카드 본문에 "현재 자료만으로 판단하기 어려워 근로조건을 추가로 확인하는 것이 좋습니다" 문구가 함께 노출되는지 |
| **산재카드 "우선 확인 필요" 배지** | 공표된 산업안전 자료에서 우선 확인 범위가 높게 표시된 사업장 | "우선 확인 필요" 배지와 함께 "이 신호는 해당 회사의 사고확률이 아닙니다" 고지 문구가 함께 노출되는지 |
| **산재카드 "뚜렷한 이상 신호 없음" 배지** | 우선 확인 범위가 낮거나 "일반"으로 표시된 사업장 | 이 배지가 "안전 인증"으로 오독되지 않고, 여전히 현장 확인을 권장하는 문구가 함께 있는지 |
