## 제품 경로와 이미 정한 서비스 기준

`product/src/server/llmConfig.ts`는 기본 Upstage `solar-pro3`와 비교 SKT `A.X-K1`을 구성한다. `product/src/server/responses/responsesConfig.ts`의 기본 모드는 `dual_api`이고 `product/src/components/chat/ChatPanel.tsx`는 비교를 켠 요청에만 SKT를 보낸다. 계약 API도 `product/integrations/contract-api/app/config.py`에서 Upstage를 기본으로 하며 SKT를 옵션으로 둔다. 로컬 `.env.local`은 `dual_api`와 두 모델명을 표시한다. 이는 운영 서버의 현재 값이나 SKT 실호출 증거가 아니다. 최근 개인 04·05 QA는 Upstage 실호출만 기록했다. 제품 예제의 `SAVE_COMPARISON_FEEDBACK=true`와 로컬 값도 확인했으나 공개 운영의 **피드백 OFF** 정책을 바꾸거나 운영 활성이라고 추정하지 않는다.

기존 [개인정보 정책 계약](../data-contract/public-ai-privacy.md)은 요청별 외부 전송 동의, 현재 질문·최근 최대 10개 메시지·서버 30일 요약·공개 회사 정보·공식 근거의 전송 범위, 로컬 상담 30일과 백업 최대 30일, 외부 LLM의 **무학습·승인 지역·계약상 최소 보존 또는 최대 30일** 확인을 요구한다. 철회 이후 새 전송과 로컬 식별 데이터 삭제는 제품 책임이며 과거 공급자 사본은 해당 계약의 삭제 수단/TTL에 따른다. 이는 계정에 적용된 공급자 조건이 확인되었다는 주장이 아니다.

### 정책 결론과 기술적으로 가능한 범위

Upstage 유료 동기 API에 무학습 기본 원칙이 공개되어 있으나, **현재 계정의 상품 구분, 별도 동의, 저장 예외의 상한, 처리 지역**이 빠져 있어 기존 계약을 충족했다고 판정할 수 없다. 특히 무상 API 상품이면 무학습/30일 기준에 맞지 않을 수 있다. SKT 비교 기능 역시 계정 조건 확인 전에는 충족 판정 불가다. 공개 문서에서 확인한 이 차이를 고지문 수정만으로 해소하지 않는다.

코드·전송 범위에서 줄일 수 있는 것은 현재 동의와 비교 opt-in 유지, 서버 검증된 회사 정보·공식 근거만 전송, 과거 메시지/요약의 한도 축소 또는 민감 정보 제거, 불필요한 계약 원문/첨부 외부 전송 금지 등이다. 보존·학습·지역은 요청 본문 축소만으로 공급자 조건이 바뀌지 않는다. 공급자 상품 전환, 지역 고정, 특약 수용, 비교 기능 운영 여부, 기준을 충족하지 못할 때 서비스 정책 변경은 사용자 결정 사항이다. 기존 상담 30일·백업 최대 30일·피드백 OFF는 그대로 둔다.

## 비용 기록 경계

개인 05의 Upstage 56 HTTP 200과 반환 usage 213,483 토큰은 **입력/출력 및 캐시 구분이 없는 합계 기록**이다. [공식 Solar API 가격표](https://www.upstage.ai/pricing/api)는 모델·시기·입출력·캐시별 단가가 다르다. 현재 계정의 할인·크레딧·청구 내역도 읽을 수 없어 이 보고서의 **추정 비용과 실제 청구액은 모두 미확인**이다. 반환 토큰을 청구액으로 환산하거나 0원으로 채우지 않았다. 테스트 예산 승인이나 결제 변경을 제안하지 않는다.

## 사용자가 직접 해야 할 행동 — Git 제외

1. **Upstage 계정 상품과 데이터 조건 확인.** Codex에는 콘솔 로그인/MFA/비공개 계약 열람 권한이 없다. [Upstage Console](https://console.upstage.ai/)에 로그인해 **API Keys**에서 Money Worry 키가 속한 조직·상품의 이름만 확인하고, **Billing/Usage**에서 유료 API·무상 API·무료 크레딧/판촉 구분을 확인한다. 계정의 **Terms/Privacy, Data controls/API Logging, 계약·특약** 화면에서 API 입출력 로깅 opt-in, 학습/개선 동의, 보존/오류·오남용 로그 상한, 추론·보관 지역, 삭제 요청/API와 처리 기한을 확인한다. 화면 명칭이 다르면 같은 항목을 찾되 설정은 변경하지 않는다. **권장안:** 일반 유료 동기 Solar API, 학습/로깅 opt-in 없음, 승인 지역과 예외 포함 최대 30일이 문서로 확인되는 조건만 공개 상담에 사용. 무상 API나 장기/무기한 보존이면 민감 상담 전송을 허용할지, 상품·계약을 바꿀지 사용자 결정이 필요하며 서비스 제공 범위에 영향이 있다. 답장은 **상품 구분, 각 항목의 예/아니오/불명, 기간, 국가/리전, 근거 화면·문서 제목/적용일**만 보내면 된다. 키·세션·카드·계약 원문/스크린샷은 보내지 않는다. 수령 뒤 Codex가 계정 적용 행과 서비스 일치 판정을 갱신한다.
2. **SKT 비교 API 계약 확인.** Codex에는 해당 SKT 계정/계약 접근 수단이 없다. `awf-gw.adot.ai` A.X-K1 키를 발급·관리하는 **SKT A.X API 콘솔/계약 포털의 해당 상품 상세·이용약관·개인정보/데이터 처리·사용량/청구** 화면에서 요청/응답과 오남용 로그의 보존, 학습·개선 사용, 추론/저장 지역, 개별 삭제 요청/API·TTL, 특약 우선순위를 확인한다. 포털 이름을 모르면 **키 발급 주체와 상품명**만 먼저 확인하면 된다. **권장안:** 네 기준이 문서로 확인될 때에만 비교 모드를 공개 운영하고, 확인되지 않거나 충돌하면 비교 전송을 보류할지 계약 조건을 확보할지 결정. 비교 답변 제공 가능 여부에 영향이 있다. 답장은 **포털/상품명, 항목별 결과와 기간·지역, 근거 제목/적용일, 비교 운영 선택**만 비밀값 없이 보낸다. 수령 뒤 Codex가 SKT 행과 비교 경로의 운영 조건을 갱신한다.
3. **운영 활성 모드와 비용 구분 확인.** Codex는 운영 서버나 공급자 청구 화면에 접근하지 않았고, 결제/설정 변경은 사용자 책임이다. 운영자의 **Money Worry web 서비스 환경 설정 화면**에서 `CHAT_EXECUTION_MODE`, Upstage/SKT 모델명과 URL의 **공급자 도메인**, 비교 사용 여부만 확인하고 값에 비밀이 없는 부분만 전달한다. 두 공급자 콘솔의 **Billing/Usage**에서 해당 기간·모델·입출력/캐시 usage, 적용 단가/할인, 실제 청구액을 구분해 확인한다. **권장안:** 비용 승인이 없으면 공개 운영 비용을 추정치로 확정하지 않고, 기존 설정을 건드리지 않는다. 활성 모드가 다르면 조사 범위가 달라진다. 답장은 **모드, 모델, 공급자 도메인, 비교 사용 여부, 청구 기간의 집계/적용 단가/청구 총액 또는 확인 불가**만 전달한다. Codex가 활성 범위와 비용 표를 다시 맞춘다.

계정 확인이 오지 않아도 위 공개 조사 자체는 완료 상태다. 고객센터/공급자에게 문의를 보내지는 않았다.
