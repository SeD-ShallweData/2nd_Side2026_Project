## eval 복구 결과

### 고정 이력 재생

- 요청 헤더에 기존 로컬 점검 스크립트와 같은 `sec-fetch-site: same-origin`을 추가했다. 이는 API 게이트 호환용이며 브라우저 실행 또는 인증/인가 증거가 아니다.
- 중첩 `error.code/message`와 top-level 오류를 모두 읽는다.
- HTTP 200 비 JSON은 `parse_error`, 비정상 HTTP 비 JSON은 `http_error/NON_JSON_HTTP_ERROR`다. 응답 결과 누락은 `missing_result`다.
- 요청 실패 행에는 `contract_status: NOT_EVALUATED`를 기록하고 `guardrail_status`를 기록하지 않는다.
- 403 nested error, 정상 응답, 결과 누락, 200/502 비 JSON, 계약 FAIL 종료코드를 단위 테스트했다.
- 네트워크가 없는 포트로 실제 CLI를 실행해 JSONL 보존, `network_error`, `NOT_EVALUATED`, 종료코드 2 요약을 확인했다. 이는 모델 평가가 아니다.

### 실제 연속 대화

- `eval:conversation-continuity`는 비로컬 URL을 거부한다.
- 자격증명은 `ANSWER_EVAL_EMAIL`, `ANSWER_EVAL_PASSWORD` 환경변수에서만 읽는다. CLI 인자·결과 JSONL·콘솔에 값이나 세션 쿠키를 쓰지 않는다.
- 로그인 응답의 HttpOnly 세션 쿠키를 메모리에만 유지하고, 첫 `/api/chat` 응답의 `conversation_id`를 뒤의 요청에 전달한다.
- 매 턴 뒤 `/api/conversations/{id}`를 조회해 `source: database`, turn 수, 사용자 질문, 화면에 표시된 최종 답변을 확인한다.
- 마지막에 다시 로그인한 새 세션으로 같은 대화를 복원한다.
- 현재는 자격증명/앱/격리 DB가 없어 차단 dry-run만 수행했고 `LOCAL_TEST_CREDENTIALS_REQUIRED`, `NOT_EVALUATED`, 종료코드 2를 확인했다. 실제 로그인·모델·DB 호출은 0회다.

재개 조건은 새 격리 PostgreSQL 16, local app, 별도 테스트 계정이다. 운영/복원 DB는 사용하지 않는다. 현재 셸에 두 환경변수를 비공개로 설정한 뒤 `product`에서 다음 명령을 실행한다.

```powershell
npm.cmd run eval:conversation-continuity
```

### 정책 미확정

1. 공개 회사 검색을 현행 게스트 공개로 유지할지, total/필터 count/최대 탐색 깊이/rate limit을 어디까지 허용할지.

3. 익명 상담의 호출량·provider 비용 보호를 proxy 마찰 외에 어떤 서버 측 quota/rate limit으로 보장할지.
4. 익명 피드백을 허용할지, 발급된 `comparison_id`와 서버 측으로 연결할지, 파일 크기/행 수/보존기간을 어떻게 제한할지.

임의로 공개 회사·익명 상담 API 전체를 로그인 전용으로 바꾸지 않았다.

### 미검증

- 운영 서버/운영 DB에 요청하지 않았으므로 현재 배포 API의 실제 노출과 rate limit은 미검증이다.
- 새 격리 PostgreSQL이 없어 `wg_conversation` 실제 권한, owner isolation, RLS 유무, 쿼리 결과 필드, persistence/relogin/restart는 미검증이다.
- 실제 provider/RAG/browser 호출을 하지 않아 새 계약의 현재 PASS/FAIL 결과는 미검증이다.
- 사용자 대화·계정 비밀 등 민감 데이터의 실제 외부 노출은 이번 로컬 정적·단위 범위에서 확인되지 않았다. 이는 운영 비노출 증명이 아니다.
