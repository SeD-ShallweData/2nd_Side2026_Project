## 구현 경계

`product/src/server/publicRateLimit.ts`는 Redis `EVAL`에서 모든 시간창을 확인한 뒤 한 번에 증가시킨다. 429이면 어느 시간창도 증가하지 않는다. quota key는 IP와 탭 표시값의 SHA-256만 담고 원문을 Redis나 로그에 남기지 않는다. 시간창은 첫 요청부터 고정 TTL이다. 단일 Redis 인스턴스를 대상으로 하며 클러스터 hash slot 배치는 범위 밖이다. [Redis의 스크립트 원자성 설명](https://redis.io/docs/latest/develop/programmability/eval-intro/)을 근거로 한다.

공유 모드에서 웹은 길이 32자 이상 비밀 토큰과 **단일 유효 IP**가 있는 정규화된 헤더만 받는다. 쉼표가 있는 `X-Forwarded-For`, 토큰 누락/위조, 직접 앱 접속은 503이다. 로컬 gateway는 Funnel의 PROXY v2 TCP 소스 IP를 파싱하고 외부 `Forwarded`, 모든 `X-Forwarded-*`, `X-Real-IP`, proxy token 및 hop-by-hop 헤더를 제거한 뒤 자체 헤더를 만든다. 다른 로컬 프로세스가 gateway로 가짜 PROXY 프리앰블을 보낼 수 있으므로 gateway는 네트워크 경계가 아닌 **신뢰된 로컬 호스트 경계**다. 앱 3111과 gateway 3110은 loopback만 listen해야 한다. [Tailscale의 PROXY v2 + TLS 종료 TCP 예시](https://tailscale.com/docs/reference/tailscale-cli/funnel)를 따른다.

Redis 템플릿은 고정 이미지 digest, loopback 6379, 별도 ACL, AOF 및 영속 `/srv/moneyworry/public-quota-redis` 볼륨을 사용한다. `PUBLIC_RATE_LIMIT_STORE=redis`로 전환해야 공유 보호가 실제 작동한다. 현재 배포 스크립트가 gateway/Redis를 자동 설치하지는 않는다. `infra/scripts/validate-service-envs.py`는 공유 모드의 loopback 인증 URL, proxy 토큰·신뢰 설정을 검증한다.

`product/scripts/public-quota-observe.mjs`는 UTC 일자별 허용·차단 요청과 현재 분의 허용 요청을 읽는다. 차단 발생, Redis 접근 실패, 분당 회사 조회 300/익명 상담 100/계약서 분석 30 이상이면 이벤트를 출력한다. 이 수치는 **관측 경고**일 뿐 차단 기준이나 비용 상한이 아니다. 웹 로그의 `public_rate_limit_store_unavailable` 및 `public_rate_limit_local_fallback`, gateway의 prelude/Host 거절·upstream 실패 이벤트, API 429/503, 공급자 호출량 증가를 함께 관찰해야 한다. 실제 알림 전달 경로는 운영에서 미설치·미검증이다. 기존 health-watch의 생존/준비 알림만으로 Redis 장애나 429 급증을 탐지했다고 판정하지 않는다. 금액 알림은 청구 데이터 연결 전에는 만들지 않는다.

## 승인 후 운영 적용 패키지

대상: 현재 운영 `moneyworry-web`과 실제 Funnel 443 경로. **명시적 운영 변경 승인 전에는 아래 명령을 실행하지 않는다.** 서버 접속/인증은 계정 소유자가 수행하며 비밀값을 채팅으로 보내지 않는다. 대상 코드 식별자는 이 문서 하단의 파일 SHA-256과 운영 빌드 `BUILD_ID`로 대조한다. 운영의 실제 serving SHA/경로/Funnel 설정이 기존 문서와 다르면 여기서 중단해 명령을 수정한다.

### 1. 읽기 전용 전제 확인

```bash
systemctl show moneyworry-web.service -p WorkingDirectory -p User -p ExecStart --no-pager
systemctl cat moneyworry-web.service
tailscale funnel status --json
ss -ltn '( sport = :3111 or sport = :3110 or sport = :6379 )'
docker compose version
node --version
cat /srv/moneyworry/repo/product/.next/BUILD_ID
sha256sum /srv/moneyworry/repo/product/src/server/publicRateLimit.ts /srv/moneyworry/repo/infra/scripts/public-quota-gateway.mjs
```

전제: 실제 앱이 loopback 3111, Funnel이 기대한 단일 443→3111이고, Node 22 계열·승인 대상 artifact가 일치하며, 3110/6379에 충돌 서비스가 없어야 한다. 불일치·둘 이상의 공개 경로·앱 직접 공개 bind·운영 Redis 기존 사용이 보이면 중단한다. 기존 `tailscale funnel status --json`, 서비스 파일, env 파일은 운영자만 접근 가능한 곳에 백업한다. 비밀값이 든 출력은 공유하지 않는다.

### 2. Redis와 웹 환경 준비

```bash
sudo install -d -m 0700 /etc/moneyworry
sudo install -d -m 0700 /srv/moneyworry/public-quota-redis
sudo install -m 0600 /srv/moneyworry/repo/infra/public-quota/redis.conf.example /etc/moneyworry/public-quota-redis.conf
sudo install -m 0600 /srv/moneyworry/repo/infra/public-quota/users.acl.example /etc/moneyworry/public-quota-users.acl
sudoedit /etc/moneyworry/public-quota-users.acl

sudo python3 /srv/moneyworry/repo/infra/scripts/validate-service-envs.py --db-env /etc/moneyworry/db.env --web-env /etc/moneyworry/web.env --rag-env /etc/moneyworry/rag.env --contract-env /etc/moneyworry/contract.env
MW_REDIS_UID="$(docker run --rm redis:7.4-alpine@sha256:858f009f9709ce576febc734aa78b8f6d624b82571f9ddb6bda4377c833b3499 id -u redis)"
MW_REDIS_GID="$(docker run --rm redis:7.4-alpine@sha256:858f009f9709ce576febc734aa78b8f6d624b82571f9ddb6bda4377c833b3499 id -g redis)"
sudo chown "${MW_REDIS_UID}:${MW_REDIS_GID}" /srv/moneyworry/public-quota-redis

```

운영자는 ACL placeholder를 로컬에서 고유 비밀값으로 바꾸고 `mwquota off`를 `mwquota on`으로 전환한 뒤, 같은 값을 URL 인코딩해 web.env Redis URL에 사용한다. URL이나 ACL 원문을 명령 인자·채팅·로그에 출력하지 않는다. 볼륨은 Redis 컨테이너 실행 UID가 쓸 수 있도록 **실제 이미지 UID 확인 후** 소유권을 설정한다. 임의 UID 가정으로 권한을 바꾸지 않는다. `web.env`에는 위 환경 파일 문서의 공유 모드·기존 한도 값을 넣고 `validate-service-envs.py` 전체 검증을 실행한다. Redis 미기동, ACL 오류, 6379 loopback 이외 bind, AOF 쓰기 실패, 검증 실패면 중단한다. 실제 web.env는 운영자가 백업하고 0600을 유지한다.

기존 다른 경로에 재귀 권한 변경을 하지 않는다. `docker compose ... ps`에서 컨테이너가 기동 중이고 6379가 loopback으로만 열렸는지 확인한다.

### 3. Gateway와 앱 배포

승인 대상 코드를 운영 빌드 방식으로 설치하고, 빌드 ID 및 제품 검사 결과를 확인한다. gateway env는 `/etc/moneyworry/public-gateway.env`에 `infra/public-quota/public-gateway.env.example` 기준으로 만들고, Host를 실제 Funnel 호스트로 설정한다. proxy token은 web.env와 동일한 **별도 로컬 비밀값**이다. `moneyworry-public-gateway.service.in`의 `@PROJECT_ROOT@`, `@NODE_BIN@`, `@WEB_SERVICE_USER@`, `@WEB_SERVICE_GROUP@`를 확인된 절대 경로·계정으로 렌더해 `/etc/systemd/system/moneyworry-public-gateway.service`에 설치한다. 다음 순서를 지킨다.

```bash
sudo install -m 0600 /srv/moneyworry/repo/infra/public-quota/public-gateway.env.example /etc/moneyworry/public-gateway.env
sudoedit /etc/moneyworry/public-gateway.env
MW_WEB_USER="$(systemctl show moneyworry-web.service -p User --value)"
MW_WEB_GROUP="$(id -gn "$MW_WEB_USER")"
MW_NODE_BIN="$(command -v node)"
sed -e 's|@PROJECT_ROOT@|/srv/moneyworry/repo|g' -e "s|@NODE_BIN@|${MW_NODE_BIN}|g" -e "s|@WEB_SERVICE_USER@|${MW_WEB_USER}|g" -e "s|@WEB_SERVICE_GROUP@|${MW_WEB_GROUP}|g" /srv/moneyworry/repo/infra/systemd/moneyworry-public-gateway.service.in > /tmp/moneyworry-public-gateway.service
sudo install -m 0644 /tmp/moneyworry-public-gateway.service /etc/systemd/system/moneyworry-public-gateway.service
sudo systemctl daemon-reload
sudo systemctl restart moneyworry-web.service
sudo systemctl start moneyworry-public-gateway.service
sudo systemctl is-active moneyworry-web.service moneyworry-public-gateway.service
sudo ss -ltn '( sport = :3111 or sport = :3110 or sport = :6379 )'
```

gateway 전환 전, 로컬 PROXY v2 합성 smoke로 3110→3111 경로의 200/421과 위조 헤더 제거를 확인한다. `systemctl is-active`만으로 업무 처리 성공을 주장하지 않는다. 앱이 공유 Redis에 연결되지 않거나 gateway 3110이 응답하지 않으면 Funnel을 바꾸지 않는다.

### 4. Funnel 절체 및 짧은 smoke

기존 443→3111 설정과 복구 명령을 저장한 뒤에만 실행한다. Tailscale CLI의 실제 버전 도움말에서 다음 플래그를 확인한다.

```bash
sudo tailscale funnel 3111 off
sudo tailscale funnel --bg --proxy-protocol=2 --tls-terminated-tcp=443 tcp://127.0.0.1:3110
tailscale funnel status --json
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' https://<ACTUAL_FUNNEL_HOST>/api/health/live
```

기대: 공개 health 200, 기존 기본 인증과 합성 회사 조회 1건 정상, Redis 허용 계수 증가, 외부 조작 `X-Forwarded-For` 값이 한도 identity에 반영되지 않음, 3110/3111/6379 외부 bind 없음. 계약서 분석 시연 면제와 10월 2일 자동 전환은 코드 날짜로 검증하고 운영 대량 호출로 한도 소진 시험을 하지 않는다. `429`, `503`, gateway 502/421 증가, Redis 오류, 정상 브라우저 차단이 보이면 절체 중단·복구한다.

### 복구

Funnel 절체 문제라면 기존 경로를 먼저 복원한다.

```bash
sudo tailscale funnel --proxy-protocol=2 --tls-terminated-tcp=443 tcp://127.0.0.1:3110 off
sudo tailscale funnel --bg 3111
tailscale funnel status --json
sudo systemctl stop moneyworry-public-gateway.service
```

**주의:** 새 코드와 `PUBLIC_RATE_LIMIT_STORE=redis`가 남은 채 구 Funnel→앱 3111로 돌아가면 공개 quota 경로는 인증된 proxy token이 없어 503이다. 서비스를 복구하려면 이전 승인된 웹 artifact와 백업한 web.env를 함께 복원해 웹을 재시작하거나, 정상 gateway로 다시 절체한다.
