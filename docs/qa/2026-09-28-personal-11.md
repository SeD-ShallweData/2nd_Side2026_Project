## 사용자 전체 수동 QA 실행표

**실행 게이트:** 최종 서비스 URL과 serving SHA/BUILD_ID가 팀장 증거로 특정되고 작업 11 후보와 일치하며, P0 잔여와 필수 provider/저장 경로가 재검증된 뒤 사용한다. 현재 검증된 대상은 위의 로컬 mock URL/빌드뿐이고, 이 서버는 일시적이다. 운영 URL을 추측해서 로그인하거나 파일을 올리지 않는다. 로그인/저장/탈퇴 시나리오는 **real 대화 저장 모드가 확인된 합성 환경**에서 시행한다. 합성 질문·가짜 회사/문서만 쓰고 실제 개인정보·실제 계약서는 넣지 않는다.

준비물: 최신으로 확인된 서비스 URL/빌드, 새 일반 테스트 계정 A와 **삭제 전용 계정 B**, 본인이 보관할 각 계정의 무작위 비밀번호, 개인 정보 없는 작은 PDF/PNG 계약서 fixture, 실패 메모. 예시 이메일 `mwqa-a-<고유번호>@example.invalid`, `mwqa-delete-<고유번호>@example.invalid`는 형식 예시이며 실제 환경에서 가입 가능 여부를 먼저 확인한다. 비밀번호/세션/파일 내용은 Codex에 보내지 않는다. 계정 A의 기록을 지우기 전에 결과를 확인한다.

| U06 | `이번 달 급여명세서를 받지 못했어요. 무엇을 요청하고 기록할까요?` → `회사가 답하지 않으면 노동포털에서 어떻게 이어가나요?` | 명세서·임금 항목·실제 입금/근무기록 등 질문에 맞는 행동, 공식 절차/한계. 일반 회사 카드나 단순 1350 문구만으로 대체되지 않음. 출처 링크는 실제 해당 주장과 일치. |
| U07 | 익명 상태를 유지한 같은 탭에서 `/signup`의 이름·합성 이메일·비밀번호로 계정 A 가입(또는 `/login`) → `/chat`의 `익명 상담 가져오기`에서 `동의하고 가져오기` | 가져오기 동의가 명시되고 현재 익명 대화 **한 개**만 계정 기록으로 들어옴. 로그인 상태/저장된 대화 목록 확인. 다른 탭/계정의 대화는 나타나지 않음. |
| U08 | 계정 A에서 새 상담으로 회사 A/B 정정·근로조건 질문을 20턴 이상 누적하고 10·20턴에 최신 급여일/회사/서류 사실 질문 → 새로고침 → 로그아웃·재로그인 → `저장된 대화`에서 이어하기 | 중간 회상·정정의 회사 귀속이 맞고, 원문/출처/당시 회사 표시가 저장됨. 새로고침·재로그인 뒤 같은 대화와 수정 사실을 이어받음. 원문과 요약을 분리해서 품질 확인. 긴 입력은 모두 가상 사실. |
| U09 | 질문 전 외부 AI 동의를 끈 상태의 전송 버튼, 이어서 동의 후 전송; 네트워크 장애가 실제 발생하면 `질문 다시 보내기` 한 번 | 미동의 전송 차단. 실패는 화면에 오류/대체 상태로 보이고 재시도 뒤 중복 답변·저장 행이 생기지 않음. 장애를 만들기 위해 운영 설정을 바꾸지 않음. |

U08의 20턴 입력은 특정 정답 암기용 문항을 재사용하지 않는다. 회사 A: `인천 OO건설의 급여일은 23일이고 이번 달 명세서는 아직 받지 못했습니다.`; 회사 B: `김포 OO건설은 급여일 8일이며 처음 들은 근무시간 9시간을 5시간으로 정정합니다.` 같은 **합성 사실**을 바탕으로, 면접 질문·기록·회사 전환·주제 복귀를 사용자 말투로 이어간다. 전체 20턴을 사용자가 설계할 필요는 없고 위 흐름의 사용감과 기억을 확인하면 된다. 실제 공개 사업장 카드의 이름/지역은 적용 환경에 따라 확인하고, mock 전용 이름이 운영에 없으면 실제 회사 개인정보를 대신 넣지 않는다.

실패 시 모든 로그를 보내지 않는다. **사례 ID, KST 시각, 확인한 URL의 빌드 ID, 입력 질문(합성만), 보인 결과의 짧은 문장/화면, 기대와 다른 점, 다시 시도했는지**만 기록한다. 오류 화면은 비밀/계정 식별자를 가린 부분 캡처가 있으면 도움이 된다. Codex가 이후 재현·코드/환경/정책/기대 불일치 분류와 필요한 영향 회귀를 수행한다. 종료 때 계정 A의 합성 대화·즐겨찾기를 화면에서 지우고, 삭제 전용 B의 삭제를 확인하며, 브라우저에 남은 합성 파일 선택/세션을 정리한다. 운영 데이터 삭제·백업 조작은 하지 않는다.

## 인수 판정과 다음 단계
