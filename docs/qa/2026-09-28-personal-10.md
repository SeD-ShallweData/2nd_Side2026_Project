# Money Worry 개인 후속 작업 10 — 코드 고정 후 개발 미사용 평가셋 검증

## 결론

**고정 후보 수용 실패(FAIL).** 사용자가 결과를 보기 전에 채택한 7개 허용 기준을 모두 충족하지 못했다. 이 평가는 외부 독립 인간 평가가 아니라 **코드 고정 후 개발에 사용하지 않은 평가셋 검증**이다. 자동 계측, Codex의 답변 검토, 사용자의 최종 품질 판단은 서로 다른 증거로 둔다. 평가 중 제품·프롬프트·가드·평가셋·허용 기준은 변경하지 않았다. 제품 결함 수정과 그 재시험은 작업 11의 결함 마감/회귀 검증이다.

동결 전 작업 4·5의 잔여 품질 문제도 좁게 수정하고 실제 provider로 재검증했다. 문서 종류 파서의 통장 사본/계약서 사본 혼동 등은 줄었으나 **원시 답변의 미진술 서류 부재 단정, 근거 누락, 가드 교체의 현재 질문 소실은 남았다.** 선행 품질 게이트를 통과했다고 주장하지 않는다. 그 상태를 알려진 후보 결함으로 고정해 새 평가를 실행했으며, 후보는 수용하지 않는다.

## 작업 4·5 선행 보완과 개발용 재검증

동결 전 제품에서 소유자 검사를 거친 사용자 문서 진술을 회사별 최대 8개로 추출·전달하고, 원본/사본/통장 사본/급여명세서의 `보유·분실·부재·미진술`을 보수적으로 분리했다. 통장 사본을 계약서 사본으로 읽던 파서 오류를 수정했다. 문서 활용 질문의 이전 assistant 서술을 생성 문맥에서 약화하고, 사용자 원문 상태를 현재 질문 가까이에 표시했다. 직전 답변의 완전 반복 감지와 사용자가 요청한 번호 형식 지침도 추가했다. 제품의 DB/schema/migration/worker/배포·정책·피드백 상태는 바꾸지 않았다.

개발용 26턴 Mock 대화 4회, 실제 Upstage 96회 HTTP 200을 `.runtime/personal10/prefreeze/`에 보존했다. 72회 후 파서 정정 확인을 위한 추가 상한 24회를 **호출 전에** 기록했다. 마지막 회차에서 한빛테크 통장 사본·계약서 원본 정정은 여러 턴에서 바로 회상됐지만, 다른 회사의 미진술 통장/계약서 상태를 없다고 쓰는 원시 답변이 다시 나왔다. 일부 가드 교체는 문서 상태를 답변에서 없앴다. 따라서 이는 회귀/수정 진단이지 작업 10의 새 점수가 아니다. 전체 제품 검사 105개 테스트 파일·1,081개 테스트 통과, 92개 opt-in skip, typecheck/빌드 통과, lint 오류 0(당시 경고 9); 마지막 작은 정리 뒤 대상 13개 테스트·typecheck·파일 lint·`git diff --check` 통과. 최종 실행기의 빌드는 동일 제품 해시로 다시 생성됐다.

유효 채점 행은 단문 24 + 장기 48 = **72**다. 정상 요청 70개 중 HTTP 200 **69개**, `S21`의 합성 회사 조회 오류가 HTTP 503이다. 사전 지정한 두 주입 장애 `S23` 출처만 출력, `S24` upstream 503은 각각 최종 가드 교체/폴백으로 HTTP 200이었고 정상 요청 성공률을 높이는 데 쓰지 않았다. 로그인 대화 **68개 행은 실제 DB `saved`/복원 200**, 고정 이력 익명 3개는 저장하지 않았다. 재로그인 복원 2회, 앱 재시작 2회, 요약 점검 6회에서 `ready`/`extractive-v4`와 10·20·24턴 저장을 확인했다. 다만 여섯 점검 모두 `recall_fact_count=0`이고 답변 회상이 자주 실패했다. 기계적 저장 성공을 기억 충실도 PASS로 바꾸지 않았다.

전체 시도 비용은 **proxy 호출 171회 = 실제 외부 Upstage 169회(모두 HTTP 200) + 합성 주입 2회**다. 분류 82, 질문 재작성 48, 생성 41회(proxy 기준); 반환 usage 합계 입력 437,913 / 출력 8,649 / 전체 **446,562토큰**이다. 171회 중 170회 usage가 있고 합성 503 1회는 usage 미제공이다. 자동 재시도 감지 0, 실제 provider 실패 0, `finish_reason` stop 168/length 1(후자는 D2T24의 rewrite). 유효 행의 최종 HTTP 지연 평균 1,477ms, p50 1,128ms, p95 3,776ms; 전체 proxy 호출 p95 2,066ms. 청구 금액·TTFT는 측정하지 않았으며 0으로 쓰지 않는다. 가드 분포는 통과 23, 교체 9, short circuit 38, 폴백 1, HTTP 결과 없음 1. 생성 없는 유효 행 39, provider 호출 자체가 0인 행 4다.

모든 합성 계정/DB는 전용 tmpfs 컨테이너 정지로 제거했고 최종 시도 계정 삭제 HTTP 200을 확인했다. 평가 라벨의 실행 중 컨테이너가 남지 않았음을 `docker ps`로 확인했다. B는 앱 종료 판정 오류 뒤 계정 삭제 HTTP를 확인할 수 없었으나 해당 tmpfs 컨테이너를 정지했다. 키·세션·실사용자 자료를 결과 파일에 보관하지 않았다.

## 작업 11에 넘길 결함과 사용자 판단

1. **긴급 안전 질문 오분기** (`S07`, `D2T08`, `D2T11`, `D2T13`, `D2T17`): 응급/진료 우선 답변이 일반 임금 안내·범위 밖으로 치환된다. 중대 오류 사례 원본을 보존하고, 후속 수정 후 회귀 검증한다.
2. **법률 적용·기한** (`S02`, `S03`, `D1T14`): 14일 지급 기한과 신고 기한 혼동, 5인 미만 가산 규정 누락, 야간근로를 연장근로로 단정한 원시 답변. 최종 가드가 일부만 회복한다.
3. **동명 회사 귀속/장기 회상** (`S09`, `D1T01`, `D1T05`, `D1T07`, `D1T10`, `D1T13`, `D1T16–T24`): 선택된 회사·지역이 있어도 선택 재요구, 10/20턴 요약 ready인데 `recall_fact_count=0`, 정정한 날짜/문서 회상 실패. 원본 저장·복원 성공과 분리해 고친다.
4. **주제 전환·정정·부분 지급 기억** (`S19`, `S20`, `D2T03–T04`, `D2T15–T24`): 고정 이력과 실제 누적 대화 모두에서 정정·사고 장소·30만 원 잔액의 순수 회상이 탈락한다. 답변으로 맞힌 턴도 있었으므로 저장소 전체 유실로 단정하지 않는다.
5. **가드 오교체와 요청 실패** (`S05`, `D1T11`, `D2T19`, `S21`): 관련 원시 답변을 일반 진정/회사 카드로 바꾸어 질문을 잃거나 회사 오류에서 503을 반환한다. raw/final/HTTP를 각각 재현한다.
6. **근거 및 회사 카드 왜곡** (`D1T02`, `D1T24`, `S03`, `D1T08–T09`, `D2T09`): 공개 카드가 제공한 근거 범위와 사용자 진술의 출처를 분리하고, 근거 없는 법률·회사 표현 및 무관한 source DTO를 교정한다. `D1T24`는 중대 오류다.
7. **동결 전 04·05 회귀 잔여**: 기존 개발용 26턴에서 다른 회사의 미진술 서류를 부재로 쓰는 원시 답변과 문서 상태를 없애는 가드 교체가 남았다. 이 사례는 작업 10 점수에 합산하지 않고 작업 11 회귀 목록으로 유지한다.

사용자 판단을 받은 좁은 사례 두 개는 전체 합격 판정을 바꾸지 않는다. `S17`은 지급일·입금·근로시간 기록과 1350을 안내했지만, 사용자는 누락 근무시간 질문에 **지나치게 일반적**이라고 판단했다. 최종 유용성 **FAIL**로 반영했다. `D1T19`는 안전교육 주기와 착용 보호구 종류를 묻는 면접 질문 하나를 제안했다. 사용자는 **질문 하나로 충분하다**고 판단했다. 원시·최종 유용성 **PASS**로 반영했다. 정확한 질문·답변·기술 판정과 사용자 판단은 `product/eval/personal10-answers.v1.jsonl`과 Codex review 파일에 구분해 남겼다. 전체 72문항 검토를 사용자에게 넘기지 않는다.

미정 최종 품질 허용 범위는 **없음**. 결과 전에 권장안을 사용자가 확정했다. 사용자의 두 사례 판단 및 작업 11 전체 수동 QA는 별개다. 작업 06의 공급자 계정·계약·지역·보존 설정은 계정 소유자 확인이 아직 필요하고, 작업 07–09의 운영 증거 미완료는 이 로컬 합성 평가의 실행 가능 여부와 별개다. 이 보고서는 운영 DB·VM·worker·배포·요금 청구나 실제 사용자 환경의 합격 증거가 아니다.

## 재현·산출물

원본 실행은 `product/.runtime/personal10/`의 위 세 시도와 `freeze.json`에 보존했다. 추적 가능한 합성 결과는 `product/eval/personal10-answers.v1.jsonl`(72개 질문·원시/최종·가드·출처, 키/세션 제외), `personal10-technical-results.v1.json`, `personal10-codex-review.v1.json`, `personal10-verdict.v1.json`이다. 결과 SHA-256은 각각 `81a68081a5abdd022d3fd63734ff6a3f787ca3a682a1af6f550a9a94b469479c`, `226ed45ea85ab49ef315c3aa82411a5829dc484b3ae2c442ef22bcB358617c7e`, `cc0fae75d90edf444682d979b7b6b5436f278ffbaa73062bd128b20a91fbfa9b`, `4e0d38f7746c70296b5443ca49ebb65098478d0aa2b686dfbc1fcd20f352e442`다. 원본 `.runtime`은 Git 제외이므로 다른 환경의 완전 원문 재현에는 이 로컬 산출물 복사가 필요하다.

로컬 집계 재현(제품 호출 없음):

```powershell
cd product
node scripts/personal10-freeze.mjs --verify .runtime/personal10/freeze.json
node scripts/personal10-aggregate.mjs
node scripts/personal10-export-answers.mjs
node scripts/personal10-score.mjs
node scripts/personal10-verdict.mjs
```

새 실호출은 동일 질문을 다시 쓰는 **회귀/반복 검증**이며 새 개발 미사용 평가가 아니다. 새 격리 DB, provider 자격의 현지 존재, PostgreSQL Docker Engine, Node/npm/Python RAG 자산이 필요하다. `node scripts/run-personal10.mjs --live`는 합성 DB와 실제 API/provider를 호출하고 최대 200 proxy 요청에서 중단한다. 첫 실행기 오류·부분 실행·재시작 정정의 원본 기록을 덮어쓰지 않는다. 자동 Git 작업은 하지 않았다.
