## raw 근거·최종 유용성의 별도 판정

- 채택 수정 후 raw 9개에 15일/9월 27일 및 기록·접수 행동이 모두 있다. 그러나 **법령·절차 문장별 괄호 근거 계약을 모두 충족한 답변은 0/9**다. 고정 6개에는 조문 이름이나 뒤쪽 근거 목록이 있고, 연속 3개 raw에는 출처명 자체가 없다. 서비스 source DTO가 남는 것과 raw의 문장별 근거 표기는 별개다. 모든 9건을 완전 PASS로 판정하지 않는다.
- 수정 후 고정 product-recall 반복1은 “15일에도 9월 27일에도 미입금이면”이라는 흐름이라 기존 급여일 경과만으로 대응할 수 있다는 취지를 약화한다. fixture 반복2의 “진정 시 필요한 자료”는 권고와 접수 선행요건의 구분이 불분명하다. 서문 무응답 개선과 이런 의미상 약점은 서로 다르다.
- owner metadata가 없는 고정 4개 final은 직접 생성 실험의 후처리 한계로 최종 제품 인수에서 제외한다. summary10의 final 2개는 사실·행동을 보존하나 회상 prefix와 raw의 사실 설명이 중복된다.
- 실제 service의 수정 후 turn7/9는 질문에 쓸 수 있는 사실·행동을 제공하지만 근거 표기와 증빙 권고 문구가 남아 **PARTIAL**이다. turn8은 짧은 회상 계약 **PASS**. turn10은 비교 질문에 직전 본문을 재사용하여 **FAIL(직접성/반복)**로 분류한다. 같은 답변 안에 1350 상담/진정 구분 한 문장은 있지만 전체 복제를 정상적인 새 답변으로 승격하지 않는다.
- 기존 guard의 빈틈도 보존한다. 수정 전 turn7의 1350 상담 또는 방문 접수 문장은 guard passed였고, 비채택 실험은 정상적인 “1350에서는 안내, 제출은 별도”에도 `HOTLINE_FILING_CONFUSION`을 냈다. 과잉/미교체 후보를 확인했지만 이번 작업에서 가드를 완화하거나 수정하지 않았다.

## 추가7호출과 비채택 판단

최초 38호출 이후, 본문 전체 복제와 근거 누락에 대해 **추가 7회/누적 45회** 계획을 먼저 기록했다. 긴 제공 문맥 뒤에 현재 질문에 직접 답하기·차이 설명·문장별 근거 계약을 다시 명시한 후보로 제품 회상 2회, 실제 turn10 입력 고정 replay 2회, 같은 turn10의 현재 service 경로 1회(3calls)를 실행했다.

서문 실패는 0/5였지만 근거 표기는 여전히 누락됐고, service replay는 직전 답변과 완전히 같았다. direct replay 2건은 1350 안내/접수를 분리한 문장에도 기존 guard 교체가 발생했다. **이 지침 추가를 개선으로 채택하지 않고 제거했다.** 최종 소스가 최초 채택 후 실측 버전과 같음을 해시로 확인했다. 이 5답변을 최종 버전 성공 표본이나 추가 연속 대화로 계산하지 않는다.

## 채택 구현·검사

- `generationHistory.ts`: 최근 10메시지를 원래 화자와 함께 JSON 참고 기록으로 전달한다. 사용자 진술은 보존하고 assistant를 한 문장으로 축약하지 않는다. assistant가 2,000자를 넘으면 앞 1,400/뒤 600자를 보존하고 중간 생략/truncated를 표시한다. 이번 실측 이력은 이 한도에 걸리지 않았다. 중간의 법적 조건 손실 가능성을 모두 해결한 요약기는 아니다.
- `DualLlmChatProvider.ts`: native assistant 답변 예시 대신 위 기록과 마지막 현재 user 질문을 사용한다. 현재 근거·정책 기준·요약·guard·fallback·추출·온도·700token 한도·호출수는 유지한다. policy trace 버전은 v11이다. SKT도 공유 생성 조립 코드를 쓰지만 실호출 검증은 Upstage만이다.
- `prompts/chat/system.md`: 과거 화자와 현재 질문을 구분하고 새 질문의 사실·행동에 답하도록 명시한다. 짧은 회상에 절차를 강제로 덧붙이지 않는다. Responses도 읽는 공통 prompt라 기존 Responses 단위 회귀를 포함했지만 그 native 이력 구성이나 실호출은 변경/검증하지 않았다.
- 원문 저장·extractive-v3 요약 정의·공개 parser·owner 경계·회상 shortcut·출력 guard는 변경하지 않았다. 외부 호출 재생성이나 서문 삭제 처리는 없다.
- 관련 회귀 **7files/75tests PASS**. 새 5건은 회상 본문/번호 보존, 사용자 정정·주입 문구의 데이터 역할, 긴 assistant 한도/후반 조건, 빈 이력/10개 창, raw 서문 한 번 호출+stop/usage+기존 guard를 검사한다. 기존 비교 테스트는 현재 질문이 마지막 user이고 이전 본문이 참고 기록에 남는지 검사하도록 갱신했다.
- 전체 Vitest **102files PASS/1file skip, 1,062tests PASS/85 opt-in skip**. 첫 `npm.cmd run check`는 그 뒤 새 평가 도구의 미지원 IntentTopic 타입에서 중단됐다. 도구를 기존 `other`로 고친 후 **typecheck/lint/build를 별도로 이어서 완료**했다. 고정 생성의 근거와 요구사항은 바뀌지 않는다. 하나의 중단 없는 check 실행이라고 기록하지 않는다.
- ESLint **0errors/기존 7warnings**. 첫 전체 lint의 8warnings 중 새 도구의 unused 타입 1건을 제거했다. Next production build PASS. 도구 최종 문법/typecheck 및 무호출 preflight도 확인했다.
- 최종 제품 해시는 채택 after 실측과 동일하다. schema/migration 파일 변경0. DB/browser/실제 HTTP/RAG 벡터/Linux·GitHub CI/배포/공급자 계약은 이번 NOT RUN이다.

## 재현과 다음 작업

현재 잔여 전체 복제는 `1790573412995-after/results.jsonl`의 continuous turn10에 질문·hydrate된 원문/summary가 있고, turn9/10 raw를 직접 비교하면 동일하다. 추가 replay는 `1790573628444-focused`에 보존했다. 서문만 있는 출력은 before의 fixed product-recall/current 및 continuous turn9에서 확인한다. 각 행의 call 번호로 calls.jsonl의 실제 payload/usage/stop에 연결한다. 미래에 다시 실행한 모델 출력은 같음을 보장하지 않는다.

재현 도구는 product 디렉터리/Node22에서 사용한다. 키는 준비된 자식 환경의 UPSTAGE_API_KEY만 사용하며 새 입력을 요청할 필요는 없다.

```text
node scripts/run-personal04.mjs preflight
node scripts/run-personal04.mjs before
node scripts/run-personal04.mjs after .runtime/personal04/<새 before 실행>
node scripts/run-personal04.mjs focused .runtime/personal04/<after 실행>
```

`before`는 실행 시점의 현재 제품을 새 기준선으로 측정한다. 예전 소스로 되돌리는 명령이 아니다. 기존 세션 누적 45회라 남은 cap3으로는 새 묶음을 완료할 수 없으며 임의 상향하지 않았다. 재측정은 별도 범위/상한을 먼저 정해야 한다. 비채택 후보의 당시 번들/프롬프트는 증거용으로 남고 현재 `focused`는 최종 채택 소스를 사용한다.

**잔여 조건**: summary와 실제 생성 답변이 누적된 뒤 새 세부 질문을 하면 직전 본문 전체가 재사용될 수 있다. 법령·절차의 문장별 근거 누락, 일부 급여일/약속일 대응 시점과 증빙 필수성의 모호함, 기존 guard의 과잉/미교체도 남는다. 원시 품질 전체 완료 판정은 하지 않는다. 일반 문서 사실 압축/64슬롯/별칭/회사 초점은 05의 별도 범위다. 다음 05에서 이 잔여와 영향 회귀를 함께 우선순위화하되 자동 시작하지 않는다.
