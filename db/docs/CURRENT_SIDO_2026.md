# 사업장 현재 지역명 이관 (2026-09-30)

2026-07-01 출범한 `전남광주통합특별시`를 현재 사업장 지역명으로 사용한다.
법적 명칭·시행일 근거: [전남광주통합특별시 설치를 위한 특별법 시행령](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=287059).
`광주광역시`, `전라남도`, 약칭 `광주특별시`를 같은 현재 지역으로 묶는다.
`강원도`, `전라북도`, `제주도`, `세종시`도 현행 공식 명칭으로 바꾼다.
지도에는 16개 통합 광역 지역을 표시하고 지역 필터는 공식 전체 명칭으로 제공한다.
지역 선택 순서는 [행정안전부 주민등록 통계의 현행 시·도 순서](https://jumin.mois.go.kr/etcStatBirth.do)를 따른다:
서울 → 전남광주 → 부산 → 대구 → 인천 → 대전 → 울산 → 세종 → 경기 → 강원 →
충북 → 충남 → 전북 → 경북 → 경남 → 제주. 화면에는 각 지역의 전체 공식 명칭을 쓴다.

`0022_current_sido_names.sql`은 기존 `public.firms.sido`를 `sido_source`에 보존한 뒤
현재 표시값을 변경한다. 사업장 ID와 행 수는 그대로 유지한다. 기존 모델 입력의 `sido_code`, 과거 시점의 예측·사고 자료,
상담·신고 원문은 과거 출처의 의미를 보존한다. 기존 위험 집계 뷰는 현재
`firms.sido`를 읽으므로 이관 후 현재 지역명으로 다시 집계된다. 원본 CSV 재적재는
`db/scripts/ingest.sh`가 현재 이름으로 변환하면서 `sido_source`를 유지한다.
산업안전 원본과의 자동 연결은 이 `sido_source`로 기존의 엄격한 지역 일치를 검증한다.

운영 적용 전에는 `MIGRATION_OPERATIONS.md`에 따라 실제 대상의 백업, migration
ledger·schema 상태를 읽기 전용으로 확인한다. 격리된 PostgreSQL 16 복제본에
`0022`를 먼저 적용하고 다음을 확인한다.

1. `firms` 전체 행 수와 `firm_id` 집합이 전후 동일한지 확인한다.
2. 이관 전 광주광역시·전라남도·광주특별시·전남광주통합특별시 건수 합이
   이관 후 전남광주통합특별시 건수와 같은지 확인한다. 다른 구 명칭도 동일하게 확인한다.
3. migrator 재실행이 ledger에 따라 no-op인지 확인한다. 현재 사업장 지역 필터·지도·검색 건수와
   업종 건수를 DB `COUNT(*)`와 비교한다.
4. 과거 원본·모델 지역 코드와 상담·신고 원문이 그대로인지 확인한다.

운영 DB에는 이 문서만으로 migration을 실행하지 않는다. 담당자가 실제 대상의
ledger·백업·복구 절차를 확인한 뒤 적용한다. 롤백은 적용 전 백업 복원으로 수행한다.
