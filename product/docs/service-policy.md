# 돈워리 서비스 정책과 표현 가이드

- 문서 상태: Draft v1
- 기준일: 2026-08-04

이 문서는 프론트엔드 문구, API 응답, 챗봇 프롬프트, Mock 데이터가 공통으로 따라야 할 안전 기준이다. UI가 보기 좋아지는 것보다 사용자가 모델 신호를 확정 사실로 오해하지 않게 하는 것을 우선한다.

## 1. 결과 분리 정책

### POL-01. 임금체불과 산업재해 결과를 분리한다

- 임금체불 결과는 사업장 단위의 관측·예측 신호로 표시한다.
- 산업재해 결과는 `지역×업종` 맥락 또는 엄격히 검증된 사업장 연결의 공표 우선순위 신호로 표시한다.
- 검증된 사업장 연결도 개별 사업장 사고 확률이나 안전 판정으로 바꾸지 않는다.
- 두 결과는 별도 카드, 별도 제목, 별도 설명, 별도 기준일을 사용한다.
- 한 결과가 없거나 오류여도 다른 결과를 숨기지 않는다.

### POL-02. 종합 위험점수를 만들지 않는다

- 임금체불과 산업재해를 더하거나 평균 내거나 가중합하지 않는다.
- “종합 안전도”, “회사 총위험”, “돈워리 점수” 같은 단일 지표를 만들지 않는다.
- LLM도 자체적으로 두 결과의 우선순위나 종합 등급을 계산하지 않는다.

### POL-03. 일반 사용자에게 원시 수치를 노출하지 않는다

다음 값은 관리자·연구용 내부 정보이며 클라이언트 응답, 정적 HTML, 브라우저 JavaScript 번들, 챗봇 답변에 기본 노출하지 않는다.

- `raw_probability`
- `percentile`
- `risk_ratio`
- `predicted_count`
- `shap_value`와 세부 기여값
- 내부 임계값과 모델 판정 규칙

사용자에게는 설명형 상태, 근거 항목, 데이터 충분도, 기준일과 출처를 제공한다.

## 2. 상태 표현 정책

| 내부 상태 | 사용자용 기본 표현 | 의미 | 금지 해석 |
|---|---|---|---|
| `normal` | 뚜렷한 이상 신호 없음 | 현재 확인 가능한 자료에서 특이 신호가 확인되지 않음 | 안전 인증, 향후 문제 없음 |
| `watch` | 추가 확인 권장 | 확인할 변화나 조건이 관측됨 | 위험 사업장 확정 |
| `review` | 우선 확인 필요 | 여러 확인 신호가 있어 사용자의 추가 확인이 중요함 | 위법·체불·사고 발생 확정 |
| `unknown` | 분석 가능한 자료 부족 | 데이터 부족, 매칭 실패 또는 분석 불가 | `normal`로 간주, 안전 간주 |

### POL-04. `normal`은 안전 판정이 아니다

- `normal`은 현재 데이터 범위에서 뚜렷한 이상 신호가 없다는 뜻뿐이다.
- “안전”, “안심 기업”, “문제없는 회사”, “추천 기업”으로 바꾸지 않는다.
- 계약 조건과 실제 근무 환경은 사용자가 별도로 확인해야 한다.

### POL-05. `unknown`은 데이터 부족이다

- `unknown`을 `normal`로 변환하지 않는다.
- UI에서 카드 영역을 유지하되 “분석 가능한 자료가 부족합니다”를 표시한다.
- 데이터 부족 카드에는 위험 근거, 긍정 근거, 안전을 암시하는 색·아이콘을 표시하지 않는다.
- 챗봇은 “자료가 없으므로 안전하다”는 식의 추론을 하지 않는다.

## 3. 공식 사실과 모델 신호 분리

### POL-06. 예측 결과와 공식 명단 등재 사실을 분리한다

- 공식 명단 `listed`는 해당 기준일의 공개 명단에서 일치 결과가 확인됐다는 뜻이다.
- `not_listed`는 해당 기준일 명단에서 확인되지 않았다는 뜻이지 체불 사실이 전혀 없다는 뜻이 아니다.
- `unavailable`은 명단 자료를 확인할 수 없거나 매칭 신뢰가 부족하다는 뜻이다.
- 공식 명단 상태는 임금체불 모델 등급과 별도 영역에 표시한다.
- LLM이 `watch`나 `review`를 근거로 “명단에 등재됐다”고 말하지 못하게 한다.

## 4. 조회와 LLM 정책

### POL-07. `company_id`로 정확히 조회한다

- 사용자는 동명이인 후보의 주소와 업종을 보고 사업장을 선택한다.
- 사업장명은 화면 표시와 검색에만 사용한다.
- 신호 조회, 회사 컨텍스트 상담, 이력 연결은 `company_id`를 사용한다.
- 사업장명이 비슷하다는 이유로 다른 회사의 수치나 공식 명단 상태를 인용하지 않는다.

### POL-08. LLM은 계산하거나 추정하지 않는다

LLM이 할 수 있는 일:

- 조회된 상태와 근거 항목을 쉬운 말로 설명
- 공식 문서에 근거한 행동 순서 안내
- 사용자가 추가로 확인할 질문 제안
- 데이터의 기준일과 한계 설명

LLM이 할 수 없는 일:

- 사업장 위험 상태 재계산 또는 변경
- 없는 사업장·수치·명단 등재 사실 생성
- 임금체불과 산업재해 결과를 종합
- 지역·업종 산재 신호를 개별 회사 사고 확률로 변환
- 회사의 안전·위법·입사 적합성 확정

### POL-09. 근거가 부족하면 답변을 제한한다

- RAG에서 직접적인 공식 근거를 찾지 못하면 일반 지식으로 법률 답변을 채우지 않는다.
- “현재 연결된 공식 문서 범위에서는 확인하기 어렵다”고 밝힌다.
- 고용노동부 1350 등 공식 확인 창구를 안내한다.
- 제한 응답에는 `guardrail_status: limited`와 한계를 함께 반환한다.

### POL-10. 입사 여부를 직접 결정하지 않는다

- “입사하세요”, “입사하지 마세요”, “당장 퇴사하세요”처럼 결정을 대신하지 않는다.
- 관측된 정보, 확인할 질문, 사용 가능한 공식 절차를 제시한다.
- 위급한 생명·신체 위험은 일반적인 입사 판단과 분리해 즉시 안전 확보를 안내한다.

## 5. 기준일과 출처 정책

### POL-11. 기준일·유효기간·출처를 표시한다

- 신호 카드에는 `data_as_of`, `generated_at`, `valid_until`, `freshness`를 표시한다.
- 출처에는 문서명 또는 데이터명과 기준일을 포함한다.
- `valid_until`이 지난 결과에는 “자료 갱신 필요” 또는 “유효기간이 지난 결과”를 표시한다.
- 오래된 결과를 최신 정보처럼 표현하지 않는다.

### POL-12. 공식 확인 창구를 안내한다

- 임금체불, 근로조건, 신고 절차의 추가 확인에는 고용노동부 1350 등 공식 창구를 안내한다.
- RAG 출처는 국가법령정보센터, 고용노동부, 근로복지공단 등 공식 자료를 우선한다.
- 출처 URL이나 문서 식별자를 확인할 수 없으면 존재하는 것처럼 만들지 않는다.

## 6. 산업재해 긴급 상황 정책

### POL-13. 위급 상황은 즉시 대응 안내가 우선이다

사용자가 현재 사고, 심각한 부상, 화재, 붕괴, 유해물질 노출 등 즉각적인 위험을 설명하면 다음 순서로 안내한다.

1. 본인과 주변 사람의 안전 확보 및 위험 구역 이탈
2. 필요한 경우 119 등 긴급 구조 요청과 사업장 비상 절차 실행
3. 현장 책임자와 관계 기관에 즉시 알림
4. 안전이 확보된 뒤 기록·신고·상담 절차 안내

이 경우 사업장 신호 카드 설명이나 일반 법률 상담을 먼저 길게 제공하지 않는다. 챗봇 응답은 `answer_type: emergency_guidance`, `guardrail_status: escalated`로 표시한다.

## 7. 근로계약서 검토 정책

### POL-14. 계약서 검토는 확인 보조다

- 결과는 문서에서 기본 항목을 찾도록 돕는 정보다.
- “위법 계약서”, “무효 계약”, “법적으로 완벽한 계약서”라고 확정하지 않는다.
- 문서 인식 실패와 실제 누락을 구분한다.
- 추출이 불명확하면 `missing` 대신 `review`로 분류한다.
- 사용자가 원문을 직접 재확인하고 필요하면 1350 또는 전문가에게 문의하도록 안내한다.
- Mock 결과는 실제 파일 분석 결과처럼 위장하지 않고 시연 모드임을 표시한다.

## 8. 프론트엔드 문구 예시

### 허용 문구와 금지 문구

| 상황 | 허용 | 금지 |
|---|---|---|
| 임금 `normal` | 현재 확인 가능한 데이터에서는 뚜렷한 이상 신호가 확인되지 않았습니다. | 이 회사는 임금을 잘 주는 안전한 회사입니다. |
| 임금 `watch` | 최근 고용 변동이 관측되어 임금 지급 조건을 추가로 확인하는 것이 좋습니다. | 이 회사는 임금을 체불할 것입니다. |
| 임금 `review` | 입사 전 임금 지급일과 4대보험 처리 방식을 우선 확인해 보세요. | 임금체불 고위험 기업입니다. |
| 임금 `unknown` | 분석 가능한 자료가 부족합니다. 자료 부족은 안전하다는 뜻이 아닙니다. | 위험 신호가 없으므로 괜찮습니다. |
| 공식 명단 `listed` | 기준일 현재 공개 명단에서 일치 결과가 확인됐습니다. 원문을 함께 확인하세요. | 이 회사는 불법 기업입니다. |
| 공식 명단 `not_listed` | 기준일 현재 확인한 공개 명단에서는 일치 결과가 확인되지 않았습니다. | 임금체불 이력이 전혀 없습니다. |
| 산재 `normal` | 해당 지역·업종 자료에서는 최근 뚜렷한 추가 확인 신호가 나타나지 않았습니다. | 이 사업장은 사고가 나지 않습니다. |
| 산재 `review` | 같은 지역·업종에서 추가 확인이 필요한 신호가 관측됐습니다. 현장 안전조치를 직접 확인하세요. | 이 회사는 산재가 발생할 위험이 높습니다. |
| 산재 범위 | 이 정보는 지역·업종 단위 맥락이며 개별 사업장 판정이 아닙니다. | 이 회사의 산재 위험등급은 높음입니다. |
| 산재 검증 연결 | 이 사업장과 엄격히 연결된 공표 우선순위이며 사고 확률은 아닙니다. | 이 회사의 사고 확률은 N%입니다. |
| 입사 판단 | 확인 항목을 검토한 뒤 다른 채용 조건과 함께 판단하세요. | 여기는 입사하지 마세요. |
| 계약서 검토 | 기본 명시 항목 중 임금 지급일을 문서에서 확인하기 어렵습니다. | 이 계약서는 위법이므로 무효입니다. |
| 근거 부족 | 현재 연결된 공식 문서 범위에서는 확인하기 어렵습니다. | 아마 법적으로 문제가 없을 것입니다. |
| 만료 데이터 | 이 결과는 유효기간이 지나 최신 자료를 추가로 확인해야 합니다. | 현재 상태입니다. |

### 권장 카드 제목

- 임금 지급 관련 확인 신호
- 산업재해 확인 우선순위 신호
- 공식 명단 확인 결과
- 데이터 기준일과 출처
- 입사 전 확인할 항목
- 근로 중 대응 절차

### 금지 카드 제목

- 회사 종합 위험도
- 안전도 점수
- 사고 확률
- 임금체불 확률
- 입사 추천 점수
- 확실히 안전한 회사

## 9. 시각 표현 정책

- `normal`에 인증 마크, 방패 체크, “100%” 등 안전 보증을 연상시키는 표현을 사용하지 않는다.
- `unknown`에는 초록색이나 긍정 아이콘을 사용하지 않는다.
- `watch`와 `review`에는 공포를 과장하는 번쩍임, 사이렌, 해골 등 낙인성 표현을 사용하지 않는다.
- 공식 명단 사실과 모델 신호는 색만 다르게 하지 말고 제목과 설명 구조도 분리한다.
- 색을 보지 못해도 상태를 이해할 수 있도록 텍스트 라벨을 항상 함께 표시한다.
- Mock 데이터에는 화면에서 확인 가능한 “데모 데이터” 표식을 둔다.

## 10. 출시 전 확인 체크리스트

- [ ] 임금체불과 산업재해 카드가 별도 영역인가
- [ ] 산업재해 카드에 지역·업종 또는 검증된 사업장 연결 범위가 표시되는가
- [ ] 사용자용 API와 정적 번들에 원시 모델 값이 없는가
- [ ] `normal`을 안전이나 추천으로 표현하지 않았는가
- [ ] `unknown`을 숨기거나 `normal`로 변환하지 않았는가
- [ ] 공식 명단 상태와 모델 신호가 분리됐는가
- [ ] 모든 회사 컨텍스트 요청이 `company_id`를 재검증하는가
- [ ] 챗봇이 자체 계산·등급 변경·종합 판단을 하지 않는가
- [ ] 근거가 없을 때 제한 응답과 공식 창구가 나오는가
- [ ] 기준일, 유효기간, 출처가 표시되는가
- [ ] 위급한 산업재해 질문이 긴급 안내로 우선 처리되는가
- [ ] 계약서 결과가 법률 확정 판정처럼 표현되지 않는가
