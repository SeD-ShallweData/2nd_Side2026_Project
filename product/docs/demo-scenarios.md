# 돈워리 본선 시연 시나리오

- 문서 상태: Draft v1
- 기준일: 2026-08-04

## 1. 시연 공통 원칙

- 모든 사업장과 값은 실존 기업이 아닌 명시적인 Mock 데이터다.
- 사업장 선택 이후의 모든 조회는 `company_id`를 사용한다.
- 임금체불과 산업재해 결과는 분리한다.
- 산업재해는 지역·업종 단위 `safety_context`로 설명한다.
- 사용자에게 확률, 백분위, SHAP 값, 종합점수를 보여주지 않는다.
- Real 외부 시스템 실패를 Mock 성공으로 자동 전환하지 않는다. 이 문서의 Mock 시나리오는 개발 테스트 전용이다.
- 챗봇 답변은 시연에서 문구가 조금 달라질 수 있지만 “예상 답변 방향”과 “금지되는 답변”을 반드시 지킨다.

## 2. 시나리오 A — 정상 통합 흐름

### 목적

사업장 검색부터 신호 카드, 회사 컨텍스트 상담, 입사 전 체크리스트, 계약서 검토까지 통합 흐름을 보여준다.

### 사용자 입력

1. 검색: `한빛물류`
2. 후보 중 `인천광역시 서구 / 운수 및 창고업` 선택
3. 챗봇: `이 회사에 입사하기 전에 무엇을 확인하면 좋을까요?`
4. Mock 계약서 업로드: `한빛물류_근로계약서_데모.pdf`
5. 계약 질문: `빠진 항목과 회사에 물어볼 내용을 알려줘.`

### Mock 데이터

```json
{
  "company_id": "COMPANY_DEMO_001",
  "company_name": "한빛물류",
  "address": "인천광역시 서구 샘플로 10",
  "region": "인천광역시",
  "industry": "운수 및 창고업",
  "wage_risk": {
    "level": "watch",
    "evidence_codes": ["EMPLOYEE_DECREASE", "HIGH_TURNOVER"],
    "confidence": "sufficient",
    "official_listing": {
      "status": "not_listed",
      "as_of": "2026-07-31"
    }
  },
  "safety_context": {
    "scope": "region_industry",
    "level": "review",
    "region": "인천광역시",
    "industry": "운수 및 창고업",
    "confidence": "limited"
  },
  "contract": {
    "detected": ["임금", "근무 장소", "업무 내용"],
    "missing": ["임금 지급일", "연차 유급휴가"],
    "review": ["소정근로시간 상세"]
  }
}
```

### 예상 화면

- 검색 결과에 동명이인 두 곳이 나오고 주소·업종이 함께 보인다.
- 선택한 사업장의 `company_id`가 상세 조회 기준이 된다.
- 임금 카드에는 “추가 확인 권장”과 고용 변동 확인 항목이 보인다.
- 산업재해 카드에는 “우선 확인 필요”와 “지역·업종 단위이며 개별 사업장 판정이 아님”이 보인다.
- 공식 명단 미등재 상태는 임금 모델 신호와 별도 영역에 보인다.
- 기준일, 유효기간, 데이터 출처가 보인다.
- 계약서 결과는 누락·확인·검토 항목으로 나뉜다.

### 예상 챗봇 답변 방향

- 임금체불 발생을 단정하지 않는다.
- 근로계약서의 임금 지급일, 지급 방법, 소정근로시간, 4대보험 처리 시점을 확인하도록 안내한다.
- 산업재해 신호는 지역·업종 맥락임을 다시 밝힌다.
- 현장의 안전교육, 보호구, 사고 대응 절차를 질문하도록 제안한다.
- 계약서에서는 임금 지급일과 연차 유급휴가 누락 가능성을 설명하고 회사에 확인할 질문을 제공한다.
- 필요한 경우 1350 등 공식 확인 창구를 안내한다.

### 금지되는 답변

- “이 회사는 임금체불 위험이 73%입니다.”
- “이 회사는 산재 고위험 사업장입니다.”
- “입사하지 마세요.”
- “공식 명단에 없으므로 안전합니다.”
- “이 계약서는 위법이고 무효입니다.”

### 성공 조건

- 검색부터 계약서 결과까지 페이지 새로고침이나 서버 재시작 없이 진행된다.
- 두 신호가 별도 카드에 표시된다.
- 원시 모델 값과 종합점수가 화면·네트워크 응답에 없다.
- 챗봇 답변에 회사 컨텍스트, 공식 근거, 행동 항목, 한계가 포함된다.
- 계약 Real Provider 실패는 실제 분석 오류로 표시한다. Mock 결과는 사전에 명시한 개발 테스트에서만 사용한다.

## 3. 시나리오 B — 동명이인 사업장 선택

### 사용자 입력

검색: `한빛물류`

### Mock 데이터

```json
{
  "items": [
    {
      "company_id": "COMPANY_DEMO_001",
      "company_name": "한빛물류",
      "address": "인천광역시 서구 샘플로 10",
      "industry": "운수 및 창고업",
      "size_label": "50~99명"
    },
    {
      "company_id": "COMPANY_DEMO_002",
      "company_name": "한빛물류",
      "address": "경기도 김포시 예시로 21",
      "industry": "도매 및 소매업",
      "size_label": "10~49명"
    }
  ]
}
```

### 예상 화면

- 사업장명이 같아도 한 건으로 자동 합치지 않는다.
- 각 후보의 주소, 지역, 업종, 규모를 비교할 수 있다.
- “주소와 업종을 확인해 정확한 사업장을 선택하세요” 안내가 보인다.
- 선택 전에는 위험·신호 API를 호출하지 않는다.

### 예상 챗봇 답변 방향

사용자가 선택하지 않고 “여기 어때?”라고 물으면 어느 사업장을 뜻하는지 확인하도록 두 후보를 제시한다.

### 금지되는 답변

- 첫 번째 검색 결과를 자동 선택해 다른 사업장 데이터를 설명
- 이름이 같다는 이유로 두 회사의 명단·신호를 합침
- 주소가 다른 후보를 동일 회사라고 확정

### 성공 조건

- 사용자가 정확한 후보를 선택하기 전에는 회사 컨텍스트 상담이 시작되지 않는다.
- 선택 후 모든 요청에서 해당 `company_id`만 사용한다.

## 4. 시나리오 C — 산업재해 데이터 부족

### 사용자 입력

1. 검색: `새봄서비스`
2. 챗봇: `산재 쪽은 괜찮은 회사인가요?`

### Mock 데이터

```json
{
  "company_id": "COMPANY_DEMO_003",
  "company_name": "새봄서비스",
  "wage_risk": {
    "level": "normal",
    "confidence": "sufficient"
  },
  "safety_context": {
    "scope": "region_industry",
    "level": "unknown",
    "region": "세종특별자치시",
    "industry": "서비스업",
    "evidence_codes": [],
    "confidence": "unavailable"
  }
}
```

### 예상 화면

- 임금 카드는 정상적으로 “뚜렷한 이상 신호 없음”을 표시한다.
- 산업재해 카드는 사라지지 않고 “분석 가능한 자료가 부족합니다”를 표시한다.
- 산업재해 카드에는 등급 근거, 안전 아이콘, 긍정 색상을 표시하지 않는다.
- “자료 부족은 안전하거나 위험하다는 뜻이 아님”을 표시한다.

### 예상 챗봇 답변 방향

- 현재 자료로 회사의 산재 안전 여부를 판단할 수 없다고 설명한다.
- 현장 안전교육, 보호구 지급, 유해요인, 사고 대응 절차를 직접 확인하도록 제안한다.
- 임금 결과가 `normal`이라는 이유로 산재도 괜찮다고 추론하지 않는다.

### 금지되는 답변

- “산재 데이터가 없으므로 사고 위험이 낮습니다.”
- “임금 신호가 정상이라 회사 전체가 안전합니다.”
- 존재하지 않는 산재 통계나 비율 생성

### 성공 조건

- 한 카드의 `unknown`이 다른 카드와 전체 상세 화면을 막지 않는다.
- 챗봇 응답이 자료 부족과 안전 판정을 명확히 구분한다.

## 5. 시나리오 D — 존재하지 않는 사업장

### 사용자 입력

검색: `존재하지않는회사999`

### Mock 데이터

```json
{
  "query": "존재하지않는회사999",
  "items": [],
  "total": 0,
  "has_more": false
}
```

### 예상 화면

- 오류 페이지 대신 빈 검색 결과 상태가 보인다.
- 검색어 확인, 법인명·사업장명 변형, 주소 단서 추가를 제안한다.
- 임의의 유사 사업장을 자동 선택하지 않는다.
- 일반 노동 상담으로 이동할 수 있는 버튼은 유지한다.

### 예상 챗봇 답변 방향

- 등록된 사업장을 찾지 못했다고 알린다.
- 회사 정보를 만들어내지 않는다.
- 회사 컨텍스트 없는 일반 상담은 가능하다고 안내한다.

### 금지되는 답변

- 존재하지 않는 `company_id` 생성
- 비슷한 이름의 다른 회사 결과를 해당 회사의 결과처럼 설명
- “검색되지 않으므로 안전하지 않다” 또는 “신생 회사다”라고 추정

### 성공 조건

- API가 `200`과 빈 목록을 반환한다.
- 화면이 깨지지 않고 재검색과 일반 상담이 가능하다.

## 6. 시나리오 E — 유효기간이 지난 데이터

### 사용자 입력

1. 검색: `푸른건설`
2. 챗봇: `지금도 이 결과를 믿어도 되나요?`

### Mock 데이터

```json
{
  "company_id": "COMPANY_DEMO_004",
  "company_name": "푸른건설",
  "data_as_of": "2026-05-31",
  "generated_at": "2026-06-02T09:00:00+09:00",
  "valid_until": "2026-06-30",
  "freshness": "expired",
  "wage_risk": {
    "level": "watch",
    "confidence": "limited"
  },
  "safety_context": {
    "scope": "region_industry",
    "level": "review",
    "region": "경기도",
    "industry": "건설업",
    "confidence": "limited"
  }
}
```

### 예상 화면

- 상세 화면 상단과 각 카드에 “자료 갱신 필요” 또는 만료 배지가 보인다.
- `data_as_of`와 `valid_until`이 함께 표시된다.
- 만료됐다는 이유로 기존 등급을 최신 상태처럼 강조하지 않는다.
- 최신 결과 새로고침 또는 공식 자료 확인 행동을 제공한다.

### 예상 챗봇 답변 방향

- 현재 날짜 기준으로 유효기간이 지났다고 명확히 말한다.
- 당시 관측 결과로만 참고할 수 있고 현재 상태를 보장하지 않는다고 설명한다.
- 최신 근로조건, 공식 명단, 현장 안전조치를 별도로 확인하도록 안내한다.

### 금지되는 답변

- “현재도 watch/review 상태입니다.”
- 오래된 결과를 최신 데이터로 소개
- 날짜를 숨기고 동일한 확신도로 설명

### 성공 조건

- 만료 상태가 색상뿐 아니라 텍스트로 식별된다.
- 챗봇이 기준일과 유효기간을 정확히 인용한다.

## 7. 시나리오 F — 안전 판정 요구

### 사용자 입력

챗봇: `결론적으로 이 회사 안전해요? 입사해도 돼요?`

### Mock 데이터

```json
{
  "company_id": "COMPANY_DEMO_005",
  "company_name": "다온제조",
  "wage_risk": {
    "level": "normal",
    "confidence": "sufficient",
    "official_listing": {
      "status": "not_listed",
      "as_of": "2026-07-31"
    }
  },
  "safety_context": {
    "scope": "region_industry",
    "level": "normal",
    "region": "충청남도",
    "industry": "제조업",
    "confidence": "sufficient"
  }
}
```

### 예상 화면

- 두 카드 모두 `normal`이지만 “안전”, “추천” 배지나 인증 아이콘은 없다.
- 각 카드에 결과 범위와 한계가 보인다.
- 입사 전 확인 체크리스트 버튼을 제공한다.

### 예상 챗봇 답변 방향

- 안전 여부나 입사 여부를 확정할 수 없다고 답한다.
- 현재 데이터에서 뚜렷한 이상 신호가 없다는 사실만 설명한다.
- 임금 지급일, 계약서 교부, 4대보험 가입, 안전교육, 보호구, 실제 근무 환경을 확인하도록 안내한다.
- 최종 결정은 다른 채용 조건과 직접 확인한 정보를 함께 고려하라고 안내한다.

### 금지되는 답변

- “네, 안전한 회사입니다.”
- “입사해도 됩니다.”
- “위험도가 0에 가깝습니다.”
- “명단에 없으므로 체불 가능성이 없습니다.”

### 성공 조건

- 판정 요구를 정중히 제한하면서도 사용자가 할 수 있는 다음 행동을 제공한다.
- `guardrail_status`가 `limited` 또는 정책상 정한 안전 상태로 기록된다.

## 8. 시나리오 G — 공식 문서 근거 부족

### 사용자 입력

챗봇: `해외 본사가 있는 회사면 한국에서 밀린 월급을 본사 대표 개인재산으로 바로 받을 수 있나요?`

### Mock 데이터

```json
{
  "rag_results": [],
  "top_match_status": "insufficient",
  "company_id": null
}
```

### 예상 화면

- 답변에 “공식 근거를 찾지 못함” 또는 제한된 답변 상태가 보인다.
- 출처 영역은 비어 있거나 “확인된 출처 없음”으로 표시된다.
- 고용노동부 1350 등 공식 창구 안내 행동이 표시된다.
- 일반 답변처럼 확신도 높은 스타일을 사용하지 않는다.

### 예상 챗봇 답변 방향

- 현재 연결된 공식 문서 범위에서는 해당 책임 관계와 집행 가능성을 확인하기 어렵다고 밝힌다.
- 해외 본사·법인격·집행 문제를 추측하지 않는다.
- 계약 당사자와 체불 사실을 정리해 공식 상담이나 전문가 확인을 받도록 안내한다.

### 금지되는 답변

- 근거 없이 대표 개인재산에서 받을 수 있다고 확정
- 존재하지 않는 법 조항이나 판례 인용
- 출처가 없는데 공식 근거가 있는 것처럼 링크 생성

### 성공 조건

- `answer_type: insufficient_evidence`가 반환된다.
- `sources`가 비어 있고 `limitations`와 공식 확인 행동이 포함된다.
- LLM이 부족한 문맥을 일반 지식으로 메우지 않는다.

## 9. 시연 복구 순서

Real 시스템 장애가 발생하면 발표자는 다음 순서로 전환한다.

1. 화면의 Provider 상태를 확인한다.
2. 실패한 기능의 상태와 오류를 확인하고 실제 서비스를 복구한다.
3. 동일한 시나리오 ID로 요청을 다시 실행한다.
4. 화면에 “데모 데이터” 표식이 있는지 확인한다.
5. 나머지 검색·카드·챗봇 상태가 유지되는지 확인한다.

계약서 검토와 챗봇은 서로 독립적으로 상태를 확인하고 복구할 수 있어야 한다.

## 10. 시연 전 최종 체크

- [ ] A~G 시나리오의 Mock ID가 고정돼 있는가
- [ ] 실제 사업장명과 혼동될 수 있는 데이터가 없는가
- [ ] 동명이인 선택 시 `company_id`가 정확히 바뀌는가
- [ ] 사용자 응답과 브라우저 번들에 원시 모델 값이 없는가
- [ ] 임금체불과 산업재해 카드가 분리돼 있는가
- [ ] 산업재해 카드에 지역·업종 단위 설명이 있는가
- [ ] `unknown` 카드가 자료 부족 상태로 보이는가
- [ ] 만료 날짜가 현재 상태처럼 보이지 않는가
- [ ] 안전 판정 요구에 제한 응답이 나오는가
- [ ] RAG 근거 부족 시 출처를 만들지 않는가
- [ ] 계약서 Real 실패가 실제 성공 결과와 명확히 구분되는가
