# 돈워리 통합 프로토타입 MVP 범위

- 문서 상태: Draft v1
- 기준일: 2026-08-04
- 대상: AI Rookie 본선 통합 프로토타입

## 1. 서비스 목적

돈워리는 구직자와 근로자가 공개 데이터와 공식 노동 정보를 바탕으로 사업장을 더 정확히 확인하고, 임금체불·산업재해·근로계약과 관련해 다음 행동을 결정하도록 돕는 AI 노동 정보 서비스다.

서비스는 특정 사업장의 안전이나 위법 여부를 판정하지 않는다. 관측된 신호, 데이터의 한계, 공식 명단 등재 사실을 분리해 보여주고 사용자가 확인해야 할 사항과 공식 상담·신고 절차를 안내한다.

## 2. 핵심 사용자

### 구직자

- 입사 전 사업장 정보를 확인하려는 사람
- 동명이인 사업장 중 지역과 업종을 기준으로 정확한 대상을 고르려는 사람
- 임금 지급 조건과 근로계약 항목 등 입사 전 확인사항이 필요한 사람

### 근로자

- 임금체불이나 산업안전 문제를 겪고 있거나 우려하는 사람
- 신고 절차, 증빙 준비, 공식 상담 창구를 알고 싶은 사람
- 근로계약서에서 빠진 기본 항목을 확인하려는 사람

사업주와 근로감독관은 장기적으로 고려할 수 있지만 본 MVP의 핵심 사용자가 아니다. 관리자용 모델 확인 화면은 공개 서비스가 아니라 개발·시연 보조 도구로만 분리한다.

## 3. 핵심 문제

1. 사업장명이 같거나 표기가 달라 사용자가 정확한 사업장을 고르기 어렵다.
2. 임금체불 예측과 산업재해 지역·업종 신호가 하나의 위험점수로 오해될 수 있다.
3. 낮은 위험 신호가 곧 안전 판정으로 잘못 해석될 수 있다.
4. 노동법과 신고 절차 정보가 흩어져 있어 사용자가 지금 할 일을 찾기 어렵다.
5. 실제 ML 운영 DB, RAG, LLM, 계약서 분석 시스템이 모두 준비되지 않아도 프론트엔드 시연은 계속 가능해야 한다.
6. 데이터가 없거나 오래됐거나 외부 API가 실패할 때 서비스가 그 사실을 숨기지 않아야 한다.

## 4. MVP 포함 기능

### P0 — 본선 핵심 흐름

1. **사업장 검색**
   - 회사명 또는 사업장명 검색
   - 동명이인 후보의 지역·업종 표시
   - 사용자가 선택한 정확한 `company_id`를 이후 흐름의 기준으로 사용

2. **사업장 상세와 신뢰 정보 카드**
   - 임금체불 신호와 산업재해 맥락을 별도 카드로 표시
   - 임금체불 카드는 사업장 단위 관측 결과를 설명
   - 산업재해 카드는 개별 사업장 판정이 아닌 `지역×업종` 단위 신호임을 표시
   - 기준일, 유효기간, 출처, 데이터 충분도 표시
   - 공식 명단 등재 사실과 모델 신호를 분리

3. **회사 컨텍스트 기반 상담**
   - 선택된 `company_id`와 사용자용 조회 결과를 상담 컨텍스트로 전달
   - LLM이 사업장이나 수치를 추정하지 않고 조회된 사실만 설명
   - 입사 전 체크리스트 또는 근로 중 대응 절차 안내

4. **공식 문서 기반 노동법·신고 절차 안내**
   - 법령, 임금체불 신고 절차, 대지급금, 고용노동부 1350 등 공식 자료 검색
   - 근거가 부족하면 답을 만들지 않고 한계와 공식 확인 창구 안내

5. **데이터 부족·만료·오류 처리**
   - `unknown`을 `normal`로 바꾸지 않음
   - 카드는 유지하되 위험 등급이나 근거 대신 “분석 가능한 자료가 부족합니다” 표시
   - `valid_until`이 지난 결과는 최신 결과처럼 보이지 않게 만료 상태 표시
   - 외부 시스템 실패 시 명시적 오류 또는 근거가 제한된 안내로 상태를 정확히 표시

### P1 — MVP에 포함하되 실패 격리

6. **근로계약서 기본 검토**
   - 임금, 소정근로시간, 휴일, 연차 유급휴가, 근무 장소, 업무 내용 등 기본 항목 확인
   - 누락·확인·추가 검토 항목과 사용자 질문 예시 제공
   - 법률 확정 판정이 아니라 확인 보조임을 명시
   - 실제 문서 분석이 불가능해도 Mock 파일 메타데이터나 테스트 텍스트로 시연

### 개발·시연 보조 범위

- Mock/Real 공급자 전환 상태 확인
- 관리자에게만 허용되는 내부 수치 확인용 로컬 화면
- 외부 시스템 연결 상태와 오류 로그 확인

이 보조 기능은 본선 사용자 시연의 주 흐름과 분리한다.

## 5. MVP 제외 기능

- 임금체불과 산업재해를 합친 종합 위험점수
- 일반 사용자에게 확률, 백분위, SHAP 값 등 원시 모델 값 공개
- “안전한 사업장” 확정 또는 안전 사업장만 추천
- 사용자의 입사·퇴사 여부를 대신 결정
- 개별 사안의 위법·합법 여부 확정
- 사업주·근로감독관용 인증과 전체 운영 대시보드
- 커뮤니티, 사업장 리뷰, 별점, 실명·익명 게시 기능
- 관심 사업장 저장, 여러 사업장 비교
- 외국어 지원, 사진 상담, 모바일 앱
- 실제 결제, 운영자 신고·차단, 프로덕션 인증
- 모델 학습·재학습과 원천 데이터 전처리 UI

## 6. 기능 우선순위

| 순위 | 기능 | 우선하는 이유 | 외부 의존성 |
|---|---|---|---|
| P0 | 사업장 검색과 정확한 선택 | 모든 회사 컨텍스트 기능의 시작점 | 운영 DB 또는 Mock |
| P0 | 임금체불·산재 분리 카드 | 핵심 제품 가치와 안전 정책 | ML 운영 DB 또는 Mock |
| P0 | 회사 컨텍스트 챗봇 | 조회 결과를 행동 가이드로 연결 | LLM, 선택적으로 RAG |
| P0 | 공식 문서 상담 | 노동 정보 서비스의 신뢰 근거 | RAG 또는 제한 응답 |
| P0 | 데이터 부족·만료·오류 상태 | 오판과 전체 시연 실패 방지 | 없음 |
| P1 | 근로계약서 검토 | 구현 자산이 있으나 외부 API 의존 | 계약서 분석 API 또는 Mock |
| 보조 | 관리자 확인 화면 | 모델 결과 검증과 발표 보조 | 내부 데이터 |

## 7. 완료 기준

다음 조건을 모두 만족하면 통합 프로토타입 MVP를 완료한 것으로 본다.

- 사업장명 검색 후 동명이인 후보를 구분해 하나의 `company_id`를 선택할 수 있다.
- 선택한 사업장의 임금체불 신호와 지역·업종 산업재해 신호를 별도 카드로 확인할 수 있다.
- 사용자 화면과 네트워크 응답에 `raw_probability`, `percentile`, `shap_value`가 포함되지 않는다.
- `normal`을 안전으로 표현하지 않고 `unknown`을 자료 부족으로 표시한다.
- 공식 명단 등재 사실과 예측·관측 신호가 시각적·문장상 분리돼 있다.
- 챗봇이 선택된 사업장 컨텍스트를 사용하되 없는 수치나 사실을 만들지 않는다.
- 공식 문서 근거와 사용자가 취할 수 있는 행동을 함께 안내한다.
- 근거가 없으면 제한 응답을 사용하고, 외부 시스템 실패는 Mock 성공처럼 숨기지 않는다.
- 계약서 검토가 실제 분석과 Mock 양쪽에서 동일한 사용자용 응답 형태를 제공한다.
- 존재하지 않는 사업장, 데이터 일부 부족, 만료 데이터, 외부 API 오류 시나리오가 동작한다.
- Mock/Real 전환이 프론트엔드 수정 없이 어댑터 설정만으로 가능하다.

## 8. 본선 시연에서 반드시 보여줄 기능

1. 동명이인 후보가 있는 사업장 검색과 정확한 선택
2. 임금체불 `watch`와 지역·업종 산업재해 `review`가 서로 다른 카드에 표시되는 모습
3. 확률 숫자 없이 근거 항목과 기준일을 설명하는 모습
4. 선택된 회사 컨텍스트를 바탕으로 챗봇이 입사 전 확인사항을 안내하는 모습
5. 공식 문서를 근거로 신고·상담 절차를 안내하는 모습
6. 산업재해 신호를 개별 회사의 안전 판정으로 단정하지 않는 모습
7. 데이터 부족 또는 만료 상태를 정직하게 표시하는 모습
8. 근로계약서 누락 항목 검토 시연

계약서 검토는 실제 분석 API로 시연하며, 실패하면 오류 상태를 명확히 표시한다. 별도 Mock 시나리오는 개발 테스트에서만 사용한다.

## 9. 실패 격리 대상

| 기능 | 대표 실패 | 격리 방법 | 핵심 시연 영향 |
|---|---|---|---|
| ML 운영 DB | 연결 실패, 결과 미생성 | 연결 오류 또는 정보 없음으로 명시 | 없음 |
| RAG | 인덱스 미연결, 검색 결과 없음 | 일반 지식으로 채우지 않고 제한 응답과 1350 안내 | 회사 조회는 유지 |
| LLM | 타임아웃, 공급자 오류 | 재시도 후 정적 행동 가이드 또는 다른 공급자 사용 | 검색·카드 유지 |
| 계약서 분석 | 문서 인식 실패, API 오류 | 분석 실패를 명시하고 재시도 안내 | 계약서 검토 중단 |
| 사업장 검색 DB | 실 DB 미준비 | 고정 Mock 후보 목록 사용 | 전체 시연 유지 |
| 오래된 결과 | `valid_until` 경과 | 만료 배지와 최신 자료 확인 안내 | 결과 참고 가능 |

## 10. 결정 근거

- 3주차 회의의 “위험 확률 직접 공개 제외”, “안전 사업장만 추천 불가”, “임금체불 행동 가이드” 결정을 따른다.
- 6주차 회의의 “임금체불과 산업재해 결과 분리”, “종합점수 금지”, “일반 사용자 수치 비노출”, `company_id` 조회 원칙을 따른다.
- 통합 설계 프롬프트의 사업장 검색·회사 컨텍스트 상담·공식 문서 RAG·계약서 검토 요구를 반영한다.
- 2026-08-04 사용자 확인에 따라 `unknown` 카드를 유지하고, 산업재해는 `safety_context`로 표현하며, 계약서 검토는 실패 격리된 MVP 기능으로 둔다.
