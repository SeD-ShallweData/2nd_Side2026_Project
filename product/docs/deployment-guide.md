# 돈워리 배포 가이드

## 1. 정적 시연본

`exports/돈워리-통합프로토타입.html`은 서버 없이 실행하는 전달용 파일이다. Mock 데이터와 사전 생성된 Upstage·SKT 비교 답변을 파일 안에 포함한다.

장점은 비용과 외부 노출 위험이 없고 실행이 간단하다는 점이다. 반면 실제 LLM, DB, ML, RAG API를 호출할 수 없으며 사용자 질문에 따라 새로운 답변을 만들지 않는다.

## 2. 실제 LLM 사이트에 필요한 구조

```text
[사용자 브라우저]
        │ 질문과 선택한 company_id
        ▼
[돈워리 Next.js 백엔드 API]
        ├── 정책 가드레일
        ├── DB·ML·RAG 컨텍스트 조립
        ├── Upstage API 호출
        └── SKT A.X API 호출
                  │
                  ▼
       [정제된 비교 응답만 브라우저로 반환]
```

API 키는 브라우저의 HTML이나 JavaScript에 넣지 않는다. 배포 서비스의 서버 환경변수 또는 서버 전용 비밀 저장소에 보관하고, `/api/chat` 같은 백엔드 경로에서만 읽는다.

또한 공개 배포에는 다음 보호가 필요하다.

- 팀 로그인 또는 일회성 시연 인증
- 사용자별 요청 횟수 제한과 전체 일일 한도
- 입력 길이·파일 형식·파일 크기 제한
- 타임아웃과 공급자 오류 처리
- 질문·계약서·개인정보 로그 최소화
- API 키와 시스템 프롬프트 응답 제외
- 비용 및 공급자별 오류율 모니터링

## 3. 단계별 권장 방식

### 지금: 팀 검토

단일 HTML 파일을 전달한다. UI, 정보 표현, 시연 순서를 검토하는 목적에 가장 적합하다.

### 다음: 실제 LLM 비공개 시연

현재 GPU 서버의 Next.js 백엔드를 유지하는 편이 유리하다. SKT의 접속 허용 정책과 서버의 API 키 파일을 그대로 사용할 수 있기 때문이다. 서버 관리자에게 다음 중 허용 가능한 방식을 확인한다.

1. Cloudflare Tunnel용 외부 TCP/UDP 7844 허용
2. 서버의 HTTPS 443 공개 및 리버스 프록시 사용
3. 대회 측이 제공하는 공식 외부 접속·배포 경로 사용

외부 공개가 가능해지면 현재 구현된 Basic 인증에 요청 제한을 추가한 후 팀 시연 URL을 만든다.

### 이후: 지속적인 공개 웹서비스

Next.js 전체를 Vercel 같은 서버리스 플랫폼에 배포할 수 있다. 이 경우 `/data/shared-SeD/api_key.env` 파일은 존재하지 않으므로 각 키를 배포 환경변수로 다시 등록해야 한다. SKT API가 배포 플랫폼의 요청 출발지를 허용하는지도 먼저 확인해야 한다.

DB·ML·RAG가 GPU 서버에 남는다면 프론트엔드만 별도 배포해서는 기능이 완성되지 않는다. 공개 프론트엔드가 접근할 수 있는 인증된 백엔드 API 주소가 함께 필요하다.

## 4. 권장 결론

- 화면 공유와 팀 피드백: 단일 HTML
- 실제 두 LLM 비교 시연: 현재 서버 백엔드 + 승인된 HTTPS 공개 경로
- 본선 이후 안정적인 서비스: 공개 프론트엔드 + 인증된 백엔드 API + 환경변수 기반 비밀 관리

정적 HTML에 API 키를 넣어 직접 Upstage나 SKT를 호출하는 방식은 사용하지 않는다. 브라우저 개발자 도구와 다운로드된 소스에서 키가 그대로 노출되기 때문이다.
