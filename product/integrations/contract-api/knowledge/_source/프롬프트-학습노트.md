■ 계약 4요소 (시스템 프롬프트 골격 체크리스트)
  ① 권위: 검색 컨텍스트 > 모델 학습 지식 명시
  ② 범위: 컨텍스트 불충분 시 행동 정의
  ③ 제약: 형식·톤·인용 요건
  ④ 폴백: 아래 엣지 케이스 3종의 행동 규정

■ 폴백 = 엣지 케이스 3종 (통합)
  - 빈 검색 결과 → "관련 출처를 찾지 못했다"고 명시적 거절
    (지어내며 찾은 척하는 것 방지)
  - 모순 출처 → 모순을 드러내고 양쪽 다 인용
    (임의 선택·거짓 종합·무시 방지)
  - 오래된 정보 → 출처에 날짜 메타데이터, 최신 우선 지시
  ※ 폴백 강도는 정책 결정: 근거 강할 때만 답하면 충실하지만
    거절이 늘고, 느슨하면 커버리지↑ 충실성↓. 팀과 합의할 것

■ 인용 지시 구체화 4요소
  - 인용 문법 통일 (예: [doc_001])
  - 범위: 모든 사실적 주장에 인용
  - 다중 출처면 모두 인용
  - 토큰 절약: 긴 지시 대신 올바른 인용 예시 1개로 패턴 전달

■ 문서 배치 (Lost in the Middle)
  - 컨텍스트 처음·끝은 잘 활용, 중간은 부분 무시 (U자 곡선)
  - 샌드위치 패턴(실무 기본값): 1위 문서 맨 앞, 2위 맨 끝
  - 기타: 시간순, 클러스터 그룹화, 권위 기반 정렬
  - 전제: 검색 점수 랭킹이 신뢰할 만해야 함 → 팀원과 확인

[3] 멀티턴 대화 처리

■ 문제: 후속 질문("그거 더 설명해줘")을 그대로 검색하면 실패
■ 해법: 2회 호출 구조 (프롬프트 체이닝)
  호출 1: 이력+질문 → 독립 질문으로 재작성 [내 프롬프트 ①]
  → 검색 (팀원)
  호출 2: 검색 결과+질문 → 답변 생성 [내 프롬프트 ②]

■ 재작성 프롬프트 필수 규칙 3
  - 이력 없이 이해되는 독립 질문으로 재구성
  - 답하지 말 것 (재작성만)
  - 이미 독립적인 질문은 그대로 반환 (의미 표류 방지)

■ 구현 결정 3
  - 이력 범위: 최근 N턴(3~5)만
  - 호출 2에도 최근 이력 포함 ("아까 그 방식" 처리)
  - 호출 1은 작고 빠른 모델

■ 토큰 비용
  - 이력 전체 투입 시 최악 2차 증가 (지수 아님)
  - N턴 윈도우면 턴당 거의 상수
  - 지배 항은 이력보다 검색 청크(top-K×청크 크기)
  - 절감: 오래된 이력은 요약으로 압축 + 프롬프트 캐싱
    (고정 시스템 프롬프트를 앞에 배치)

[4] RAG 평가

■ 원리
  - 검색기×생성기 품질은 곱셈: 약한 쪽 개선이 이득 큼
  - 프롬프트 수정 전에 병목이 검색인지 생성인지 진단 필수
  - 평가는 일회성 아님: 평가-진단-반복의 지속 과정

■ RAG Triad (진단 도구) ★
  - Context Relevance: 필요한 정보가 검색되고 쓰였나
    → 낮으면 검색 실패 (팀원 영역)
  - Faithfulness: 모든 주장이 문서에 근거하나
    → 낮으면 생성 실패 (내 영역, 프롬프트로 수정)
  - Answer Relevance: 물은 것에 실제로 답했나
    → 낮으면 정렬 실패 (내 영역)
    예: "CEO 누구?"에 회사 연혁만 답하면 충실해도 0점
  ※ 검색 점수 낮은데 답이 맞으면 = 모델이 학습 지식으로
    답하는 중. 우리 분석결과 질문에서 무너지는 거짓 안정감

■ 검색 지표 (팀원과 공용어, 개념만)
  - Precision@K: 상위 K개 중 유용 비율. RAG에선 특히 중요
    (무관 청크가 컨텍스트 차지 + 모델 혼란)
  - Recall@K: 전체 관련 문서 중 찾은 비율. K↑→recall↑ precision↓
  - MRR: 첫 관련 문서 순위 (1위=1.0, 2위=0.5)
  - MAP: 관련 문서 여러 개가 상위에 몰린 정도
  - NDCG: 등급형(0~3) 관련성의 순위 품질, 하위 순위 로그 감점
    → 순위 = 어텐션 배분이라 Lost in the Middle과 직결

■ RAGAS 자동 평가 (LLM as judge)
  - Context Precision: 청크 중 관련 비율 (정답문 불필요)
  - Context Recall: 정답문 문장의 컨텍스트 뒷받침 비율 (정답문 필요)
  - Faithfulness: 지지된 주장/전체 주장 (정답문 불필요)
  - Answer Relevancy: 답에서 질문 역생성 → 원질의와 유사도 (불필요)
  - 사실 검증 원리: 주장 추출 → 함의/모순/무관 판정 (NLI/LLM)
  → 정답 데이터셋 없어도 Faithfulness + Answer Relevancy로
    프롬프트 개선 효과 측정 가능 (둘 다 내가 움직이는 축)

■ 평가 세트 구축
  - 질의 확보: 사람 작성 / 기존 QA셋 / LLM 합성 (각각 장단점)
  - 실제 서비스 대상자가 물을 법한 분포로 구성
  - 후속 질문 시나리오 필수 포함 ("그건?", "방금 그거 자세히")
  - 실무 조합: 정답 있는 소규모 벤치마크 + 정답 없는 지표 상시 측정
