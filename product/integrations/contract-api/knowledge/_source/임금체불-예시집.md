## 0. 30초 요약

| 항목 | 내용 |
|---|---|
| 원천 데이터 | 국민연금 가입 사업장 내역(월), 고용노동부 체불사업주 명단(반기), KOSIS 산업별 기업수(연) |
| 예측 단위 | **사업장 × 월** |
| 예측 대상 | 체불사업주 명단공개 여부 (이진 분류) |

### 1-3. 파생 지표 계산 예시

| 지표 | 계산 | `wp_demo_001` 결과 |
|---|---|---|
| 순고용변화율(12M) | `(38 - 51) / 51` | `-0.255` → ※ 표에는 월평균 환산 `-0.068` 사용 |
| 1인당 고지금액 | `159,000,000 / 38` | `4,184,210` |
| 1인당 고지금액 하락 streak | 연속 하락 개월 수 | `4개월` |
| 데이터 충실도 | 최근 12개월 중 결측 개월 | `1/12` → `medium` |
| 사업장 연령 | `2026 - 2022` | `4년` |

```python
# 하락 streak — 자금난의 "지속성"을 보는 지표
def falling_streak(values):
    streak = 0
    for prev, cur in zip(values, values[1:]):
        streak = streak + 1 if cur < prev else 0
    return streak
```

## 2. 모델 예시

### 2-1. 단계별 업그레이드 경로

프로토타입은 **1단계부터 시작**하세요. 화면과 API가 먼저 붙어야 합니다.

| 단계 | 모델 | 예시 |
|---|---|---|
| 1 | 규칙 기반 | `결측 ≥ 1 → +30점`, `순고용변화율 < -0.2 → +25점`, `업력 < 3년 → +15점` |
| 2 | LogisticRegression | 해석 가능한 baseline. 계수 부호가 상식과 맞는지 확인용 |
| 3 | LightGBM / CatBoost | 비선형·상호작용 |
| 4 | Voting Ensemble | 세 모델 확률의 가중 평균 |
| 5 | SHAP | 체크리스트 변환의 입력 |

### 2-2. 규칙 기반 v0 (프로토타입 첫날에 쓸 것)

```python
def rule_score(wp):
    score, reasons = 0, []
    if wp["missing_months_recent_3"] >= 1:
        score += 30; reasons.append("missing_recent_3m")
    if (wp.get("net_change_rate_12m") or 0) < -0.2:
        score += 25; reasons.append("employment_drop")
    if 2026 - wp["founded_year"] < 3:
        score += 15; reasons.append("workplace_age")
    if wp["falling_streak"] >= 3:
        score += 20; reasons.append("notice_amount_falling")
    if wp["defaulter_matched"]:
        score += 40; reasons.append("defaulter_listed")   # 이건 예측이 아니라 사실
    return score, reasons
```

> 이 점수는 **내부용**입니다. `reasons` 만 다음 단계(체크리스트 변환)로 넘어갑니다.

### 2-3. 성능 수치를 다루는 방법 (중요)

선행 프로젝트에서 나온 값과, 그것을 어떻게 말해야 하는지:

| 수치 | 값 | 측정 세팅 | 말할 때 반드시 붙일 것 |
|---|---|---|---|
| Precision@10 | 0.86 ± 0.05 | **1:1 균형 검증셋** | "균형 검증셋 기준" |
| Precision@50 | 0.69 | 동일 | 동일 |
| ROC-AUC (Voting) | 0.653 | 동일 | — |
| 양성 표본 | 71개 사업장 → 338 (시점 shift 증강) | GroupKFold 5×5 | "독립 정보량은 71개 사업장분" |

❌ **하면 안 되는 서술**
> "Precision@10 0.86으로 무작위 검사 대비 60배 효율"

→ 0.86은 균형셋(무작위 기대값 0.5), 60배는 실제 유병률 가정. **기준이 다른 두 수를 나란히 두면 성능 주장 전체가 흔들립니다.**

✅ **해야 하는 서술**
> "균형 검증셋 기준 Precision@10은 0.86이며, 실제 유병률 환경에서 재측정한 곡선은 별도로 제시합니다. AUC 0.653이 말해주듯 이 모델은 **상위 극소수 구간에서만 신호가 강합니다.** 그래서 개별 사업장에 확률을 붙이지 않고 Top-K 우선순위 큐로만 씁니다."

### 2-4. "점수가 낮다 = 안전"이 성립하지 않는 이유

라벨 구조가 **Positive-Unlabeled** 입니다.

```
양성 = 명단공개된 체불사업주 (고액·상습·확정)   ← 극히 일부
음성 = "아직 명단에 오르지 않은" 미확인 상태     ← 진짜 음성 아님
```

따라서 낮은 점수는 `"명단공개 패턴과 닮지 않았다"` 일 뿐입니다.
**"안전"은 예측의 역방향이 아니라 관측 사실의 집계로 정의합니다.** → 3절.

```sql
  SELECT * FROM workplace_stability

    AND stability_score >= :threshold
)
SELECT * FROM pool
WHERE (SELECT COUNT(*) FROM pool) >= 30   -- 셀이 작으면 아예 반환 안 함
ORDER BY RANDOM() LIMIT 5;
```
