# knowledge/ — 사전 투입 지식

RAG를 붙이기 전까지, 여기 있는 문서는 **`<doc>` 태그로 감싸져 시스템 프롬프트에 통째로 들어갑니다.**

## 구조

| 폴더 | 성격 | 프롬프트에 들어가나 |
|---|---|---|
| `_source/` | 원본 자료 보관 (발표자료, 예시집, 학습노트) | **아니오** — `_` 시작 폴더는 로드되지 않음 |
| `common/` | 모든 페르소나가 공유 — 서비스 정의, 상담 창구, 표현 규칙 | 예 |
| `wage/` | 임금체불 — 관측 지표, 체크리스트 변환, 대응 절차, 제도 기준 | 예 |
| `safety/` | 산재 — 경보 체계, 신호 해석, 재해 후 절차 | 예 |
| `contract/` | 근로계약서 — 법정 기준, 독소조항 표현 사전, 대응 절차 | 예 |

어느 페르소나가 어느 폴더를 쓰는지는 [prompts/registry.json](../prompts/registry.json)의 `knowledge` 항목에서 정합니다.

## 원본과 정제본을 나눈 이유

업로드한 원본 3종은 합계 약 8만 자입니다. 주입 상한(16,000자)의 5배라 그대로는 못 넣습니다.
그래서 **원본은 `_source/`에 작업 근거로 보존하고, 프롬프트에는 정제본만** 넣습니다.

정제본을 고칠 때는 원본을 근거로 삼되, 원본을 직접 편집하지는 않습니다.

## 새 문서 넣는 방법

1. 주제 폴더에 `.md` 또는 `.txt`로 만듭니다
2. 파일명에 **숫자 접두어**를 붙입니다 — `10-업종별재해율.md`. 파일명 순으로 이어붙으므로 순서가 곧 우선순위입니다
3. 서버를 재시작할 필요 없습니다. 파일이 바뀌면 다음 질문부터 반영됩니다
4. 반영 확인:

```bash
curl -s localhost:8000/api/health \
  -H "Authorization: Bearer $CONTRACT_INTERNAL_TOKEN" | jq .knowledge
```

## 규칙

- **파일당 2,000자 안팎**을 권장합니다. 전체 상한은 16,000자([app/config.py](../app/config.py)의 `KNOWLEDGE_BUDGET`)이고, 넘으면 뒤쪽부터 잘립니다
- `_`로 시작하는 파일·폴더는 로드되지 않습니다. 초안은 `_draft-xxx.md`로 두세요
- 수치에는 **출처와 기준 연도**를 반드시 적습니다. 모델은 여기 적힌 대로 인용합니다
- 원본 PDF·엑셀·대용량 CSV는 여기가 아니라 [data/raw/](../data/)에 둡니다. 이 폴더에는 **요약·정제된 텍스트만** 넣습니다

## 작성 형식

```markdown
# 업종별 재해율 (2024년 기준)

출처: 고용노동부 산업재해 현황분석, 2025-06 발표

- 전체 산업 평균 재해율: 0.65%
- 건설업: 1.02%

주의: 재해율 = (재해자 수 / 산재보험 적용 근로자 수) × 100
```

제목 + 출처 + 본문 구조는 그대로 RAG 청크 단위로 쓸 수 있게 잡아둔 것입니다.

## RAG로 넘어갈 때

합계가 16,000자에 닿으면 프롬프트 주입의 한계입니다.
`data/rag/`로 옮겨 청킹·임베딩을 붙이고,
[app/prompts.py](../app/prompts.py)의 `_load_knowledge()`만 검색 결과로 교체하면 나머지는 그대로 씁니다.

자세한 절차는 [docs/프롬프트_가이드.md](../docs/프롬프트_가이드.md) 10절.
